# AGENTS.md — acp-agent example

## Rationale

- Overlay patches: a config patch replaces the whole app config, so every overlay that patches `acp-agent` restates its base fields verbatim (`persona`, `workspaceContext`, `persistenceRoot`, `persistenceCompression`, model). Include patches cannot target entries behind a nested include, so each `<name>.cordis.snapshot.yml` includes `cordis.yml` directly and applies the scenario overlay together with the replay swap in one patch.
- Replay selection: `resolveConfigPath` (`packages/boot/app-boot`) swaps a `*cordis.yml` basename for `*cordis.snapshot.yml` in the same directory, only when `FREDDIE_SNAPSHOT=replay`. A patch's `name` asserts its target: a mismatch skips the patch and warns only when a logger exists.
- Known gap: the replay overlays name `@freddie/freddie-llm-replay` and `cordis.snapshot.yml` names `./tests/fixtures/subagent-settlement-marker.ts` (a marker that lets scenarios fence a later parent action on the real child settlement edge without a test-only model tool); this tree ships neither.
- Model pin: `cordis.yml` ships `deepseek-v4-pro`, but the recorded corpora (request headers, provenance, system prompt) were captured on `deepseek-v4-flash`, so overlays that restate the app config re-pin flash. `image*` overlays select the vision route; `image-text-route` keeps flash text-only so the strict `read_image` gate refuses and no image reaches the durable log.
- Persistence: snapshot modes use raw JSONL (`persistenceCompression: none`), and a whole-config patch must restate it or the default zstd frames hide the logs from the harness. `persistenceRoot` follows `$FREDDIE_SNAPSHOT_SESSIONS_ROOT` when the harness sets it, else `./.sessions`.
- stdout is reserved for ACP JSON-RPC: this tree has no stdout logger or HMR, and the bin loads the gitignored root `.env` before the config.
- Sandbox: the default composition confines bash and the filesystem tools to the workspace and asks before a wider retry; snapshot runs select `danger-full-access` so scenarios stay runner-independent, and `FREDDIE_PERMISSION_MODE` is the explicit override elsewhere. The mode and fallback root live on `ctx.sandboxPolicy`, and agent calls resolve both against the session cwd. In `session-sandbox-root` the session cwd lives under the user's home while the fallback deliberately points at `/tmp`, so a workspace-write mutation succeeds only when the session cwd replaces the process-level fallback root.
- Filesystem: `fs-sandbox` replaces `fs-local` behind `ctx.fs` and fences write/edit by effective mode (read-only denies, workspace-write contains to the workspace and temp roots, danger-full-access passes through); `fs-observation-policy` (read-before-edit) composes on top.
- Delegation: `session-projection` folds subagent catalog identity (mode/label), and `list_agents` and the listing fail loud without it. The separately loaded control package registers global `send_message` and its list plugin registers `list_agents`; `report` installs only in continuable child scopes. `tool-subagent-fork` stays one-shot because a continuable child's `report` tool and prompt section precede the inherited history a fork reuses, and `run_in_background` is off as an explicit foreground-only choice ([note](../../.agents/notes/implemented/architecture/2026-08-10-fork-children-stay-one-shot.md)).
- `child-question`: the provider is a tripwire; the runtime-owned child must be rejected by the seam before any UI wait begins.
- `image`: the durable attachment store resolves its root from `$FREDDIE_HOME`, which the harness scopes per run, so the overlay carries no paths. `retry`: the 1 ms zero-jitter delay keeps the durable `llm/retry` `delayMs` and replay wall time reproducible.
