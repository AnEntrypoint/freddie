# AGENTS.md — headless-agent example

## Rationale

- Overlay patches: a config patch cannot target an entry behind a nested include and replaces the whole app config, so each `*.cordis.snapshot.yml` includes `cordis.yml` directly and restates the scenario overlay in one patch. Replay fixtures are raw JSONL, so a whole-config patch must restate the compression choice or the default zstd frames hide the logs.
- Model: `cordis.yml` stays on `deepseek-v4-flash`; the goal/ralph replay corpora were recorded on it and their nested-include overlays cannot re-pin the app config. `advanced.cordis.snapshot.yml` re-pins flash because the recorded corpus (request headers, provenance) was captured on it.
- Known gap: the replay overlays name `@freddie/freddie-llm-replay`, which this tree does not ship.
- Configuration planes: the `$FREDDIE_HOME/settings.yaml` document is hot-reloaded and a `llm-deepseek:` section there overrides the adapter entry without a restart; the credential store layers the live process environment over `$FREDDIE_HOME/.credentials.yaml` (owner-only, hot-reloaded), and the adapter resolves `DEEPSEEK_API_KEY` through it on each request, so no key is inlined. The app bin loads the gitignored root `.env`, and stdout stays format-pure.
- `credentials` snapshot: the isolated run home holds no API key anywhere, yet the `deepseek-official` route still registers, so the prompt fails with the actionable `MISSING_CREDENTIAL` guidance this snapshot pins as first-run UX; the endpoint is never dialed because credential resolution fails first.
- `e2b`: one-world invariant. `e2b.cwd`, `sandbox-policy.workspaceRoot` and `bash-local`'s default workdir (the implicit host `process.cwd()`) must name the same remote directory; only `e2b.cwd` is created at sandbox open, so dropping its `!!js` line falls back to `/home/user/workspace` while Bash and PTY keep targeting the host path and every tool call fails with a remote spawn error.
- Filesystem policy loads before the model-facing filesystem tools so writes and edits require an observed file; relative paths resolve from the process cwd. `todo_write` replaces the logged whole list.
- Delegation: `session-projection` folds durable subagent identity (mode/label) and catalog reads fail loud without it. The control package registers global `send_message`; `report` installs only in continuable child scopes. `tool-subagent-fork` stays one-shot because a continuable child's `report` tool and prompt section precede the inherited history a fork reuses; `run_in_background` is off as an explicit foreground-only choice ([note](../../.agents/notes/implemented/architecture/2026-08-10-fork-children-stay-one-shot.md)).
- `subagent-diagnostic` snapshot: the seeded parent owns one session-backed child whose log carries `origin: 'subagent'` but no descriptor event, so the projection fold produces no identity and `list_agents` must surface the child as a `[diagnostic: corrupt]` row instead of dropping it. Its bundle omits the shell/filesystem stacks, so it opts out of the tools that would wait forever for executors this tree never mounts (`toolBash: false` in the inheritance snapshot for the same reason).
- `subagent-inheritance` snapshot: the deployment default stays wide (workspace-write) while the seeded parent carries a session-scoped read-only override that must beat it inside the child; only the inheritance capture can confine the child (without it the child writes successfully), which makes this the assembled-app red/green anchor for the delegation bypass.
- `subagent-settlement` snapshot: the replay child deliberately never calls `report`; the parent reaches its final answer only if the continuation manager places the child's closing message in the parent turn. A fence releases only after the real manager notice enters the parent inbox, so platform scheduling cannot choose a streamed-chunk interleave.
- Resume snapshots (`semantic-checkpoint`, `subagent-*`, `workspace-context-resume`): the persisted resume is awaited before the headless driver inspects root agents.
