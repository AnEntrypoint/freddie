
## 2026-08-21 -- gm DECIDE->COMPLETE gate has no per-session scope filter for inherited pending rows
Goal (G): Fix freddie's core-agent-loop issues from an audit, one focused gm session, full witness, commit+push.
What drifted / what went wrong: All 35 in-scope rows were fixed/witnessed/committed/pushed cleanly, but the DECIDE->COMPLETE gate (prd-all-closed) blocks on ANY pending .gm/prd.yml row regardless of whether that row is in the CURRENT session's actual requested scope. One inherited row (a one-way-door git-history force-push requiring explicit user consent) remained pending from a prior audit session and is not a core-agent-loop defect at all -- it structurally blocked COMPLETE anyway. As a spawned subagent with no AskUserQuestion channel, consent could not be obtained. Blind-retrying the bare transition 3x correctly tripped gm's own stuck-loop detector.
Fix / resolution: Applied BBCR -- stopped retrying after the gate's own stuck-loop flag, did not force-resolve or silently delete the unconsented row, and instead reported the true state to the calling orchestrator: G is fully achieved (all in-scope work durably shipped) with one separate, correctly out-of-scope, consent-gated finding surfaced for a human decision. gm-continue dispatched next per protocol.
Generalizes to: A gm session whose PRD inherits a pending one-way-door row it did not create and cannot consent to should not attempt to force COMPLETE -- report the true completion state of ITS OWN scope plus the standing blocker, rather than looping on a gate that has no session-scope awareness. Future sessions should check for exactly this shape (inherited consent-gated row + no interactive channel) early via phase-status/instruction, not discover it only at DECIDE.

## 2026-08-22 -- /goal and /skills wired into freddie's TUI + REPL
Goal (G): Ensure freddie exposes /goal and functional /skills+/skill slash commands via the TUI.
What drifted / what went wrong: initial implementation (added goal.js, skills_command.js, wired into both TUI and REPL HANDLERS) had 4 real defects surfaced by an adversarial reviewer -- a null-vs-string return contract violation, a REPL mid-turn reentrancy bug that could corrupt state.turnActive and break Ctrl-C, a resulting TOCTOU race between human /goal commands and the model's own goal tool calls, and silent text truncation in /goal's argument parsing when an objective happened to start with a status/budget keyword.
Fix / resolution: fixed all 4 (return '' not null; added a mid-turn slash-command guard to interactive.js mirroring the TUI's existing blanket block, allowing only /cancel and /steer through; length/numeric-parse guards in goal.js's STATUS_WORDS/budget branches so only an exact single-token match or a genuinely well-formed budget triggers the subcommand path). A second, independent reviewer confirmed all 4 fixes hold with no regressions before committing.
Generalizes to: any new slash command added to BOTH src/tui/commands.js and src/cli/interactive.js needs the REPL's mid-turn guard checked explicitly -- the TUI blocks all slash dispatch during an active turn via input-handlers.js, but the REPL has no equivalent unless explicitly added, and REPL commands that call runPrompt reentrantly will corrupt state.turnActive if that guard is missing. Also: any command doing keyword-based subcommand detection on args[0] should require the keyword to be the WHOLE input (or otherwise unambiguous) before branching, or it will silently truncate a legitimate multi-word value that happens to start with that keyword.
