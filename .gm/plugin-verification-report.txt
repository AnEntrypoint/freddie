5. HOT-RELOAD (src/host/index.js + src/host/plugin-runtime.js)
---------------------------------------------------------------
watchPlugins() mechanism:
  ✓ Monitors ~/.freddie/plugins/ for plugin.js changes
  ✓ Debounces 200ms to handle editor write bursts
  ✓ Guards against overlapping reloads with inFlight Set
  ✓ Never throws into caller (failures logged, watcher stays alive)
  ✓ Returns fs.FSWatcher instance on success, null if root doesn't exist

reloadPlugin() mechanism:
  ✓ Finds plugin by filename from sourcePaths Map
  ✓ Unregisters ALL old entries via capability Map:
      - All tools, commands, crons
      - All routes with method+path matching
      - All hooks with fn reference matching
      - All pages, ws routes, nav items, debugs, apis, assets
  ✓ Removes plugin from loaded[] array
  ✓ Clears capability and sourcePaths entries for old version
  ✓ Implements cache-bust via temp file:
      - Copies source to .reload-{timestamp}.mjs
      - Imports temp file (bypasses ESM module cache)
      - Cleans up temp file asynchronously
  ✓ Re-registers fresh plugin without requiring restart
  ✓ Graceful degradation: reload failure leaves old plugin in place

Live test result: watchPlugins() creates FSWatcher correctly, can be stopped and
recreated, stopWatchingPlugins() properly closes watcher.

6. CAPABILITY MAP TRACKING
----------------------------
Structure captured at load time for each plugin:
  - tools: [name, name, ...]
  - commands: [name, ...]
  - crons: [name, ...]
  - routes: [name, ...] (route count only)
  - _routeDefs: [{method, path}, ...] (needed for unroute matching)
  - hooks: [name, ...]
  - _hookFns: [{name, fn}, ...] (needed for off() with fn reference)
  - wsRoutes, pages, navItems, debugs, apis, assets: [...]

Purpose: Enables deterministic cleanup on reload without requiring module
reference to old plugin code.

Live test result: Failure isolation test confirmed 2 plugins loaded successfully
despite middle plugin throwing. Tools registered by both are present in registry.

OBSERVED BEHAVIOR (NOT DEFECTS)
================================
4 GUI plugins fail to load when createHost({surfaces: ['pi']}) is called:
  - gui-debug, gui-logs, gui-events, gui-agent
  - Error: "Cannot read properties of undefined (reading 'push')"
  - Root cause: These plugins declare surfaces='gui' but gui surface not enabled
  - Surface guard returns Proxy, plugin tries to call gui.route()
  - Proxy throws, register() never completes, cap object never populated
  - This is CORRECT behavior - GUI plugins should not be available when gui surface not enabled

6. Graceful degradation in watcher keeps system responsive even on reload errors
7. Shared registries (pi/gui/hooks) allow plugins to discover and coordinate
