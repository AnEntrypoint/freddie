# ui-workspace

## Rationale

- `src/client/index.js` `flowSource`: one source object per surface, created once in `apply`. The renderer's hook cache keys by source identity, so the source must not be rebuilt per render or per inject.
- `src/client/index.js` `apply`: each `ctx.slots.register` declares its `directoryFlow` child in the same call, so slot injection follows both the owner's and the declaration's HMR lifetimes.
- `src/client/index.js` `webjsxSlot(...)` argument: the stub is a bare `() => null`, so it cannot structurally prove it consumes `renderSlot` the way the `RendersCheck` type wants. Dispatch happens inside the registered custom element; only the compile-time shape check depends on this.
- `src/client/rows/Rows.js` `FreddieProjectRowItem` and `FreddieSessionNodeItem`: `#hoverCard` and `#menu` are created once and passed back through `renderHoverCard` / `renderMenu`. Rows re-render on the live relative-time clock; a fresh `freddie-hover-card` per render swaps out an open card mid-hover and leaks a detached portal card in `document.body` that survives pointerleave and reload.
- `src/client/rows/Rows.js` `FreddieProjectRowItem` menu `onSelect`: unknown ids return before the dispatch so a future menu row cannot fall into the destructive `actions.delete()` else branch.
- `src/client/rows/Rows.js` `sessionMenuItems`: archive is not `danger` and has no confirmation, because `archiveSession` only appends to the registry-global `archivedSessionIds` and never touches the session log.
- `src/client/tree.js` `deriveSearchResults`: blank placeholders never match a query; their canonical title is displayed localized, so matching it would tie search to one language.
- `src/client/WorkspaceBrowser.js` `FreddieViewOptionsMenu`: `portal: true` because the section header (`WorkspaceBrowser.css` `.freddie-workspaceBrowser__sectionHeader`) has `overflow: hidden` and would clip an in-place list.
- `src/client/WorkspaceBrowser.js` `FreddieWorkspaceBrowser#sessionListEl`: the tree / flat-list element is reused across renders. The browser re-renders on every store tick; a fresh element resets its row-item caches, and a hover-card portal then survives pointerleave because the pointerleave belongs to an already-replaced element.
- `src/client/WorkspaceBrowser.js` `FreddieWorkspaceBrowser#renderedOnce`: the one-shot creation helper calls `setProps()` before insertion and `connectedCallback` fires right after. Rendering in both double-renders the first mount and desyncs webjsx's per-element diff cache from the live DOM (same guard as `FreddieConversationRoot`).
- `src/client/WorkspaceBrowser.js` `#retainedAccountKeys`: `actions.retainAccountKeys` always rebuilds object references, so an unconditional call per render yields a new store snapshot each time and an infinite synchronous re-render loop. It is edge-triggered on the account-key signature.
- `src/client/WorkspaceBrowser.js` `#deleteCommittedId`: the delete confirmation stays pending until the committed list renders without the deleted id; closing earlier exposes one stale frame to the next Create Workspace gesture.
- `src/client/WorkspaceBrowser.js` `#tooltip`: `renderTooltip` results are cached per call-site `key`; `h(Tooltip, ...)` would recreate the element every render and drop its in-flight `#showTimer` hover delay.
- `src/client/WorkspaceBrowser.js` `#onTreeKeyDown` queries the live DOM for `[role="treeitem"]` instead of tracking a focus index, because the grouped tree, flat list and search results each render treeitems with a different DOM shape.
- `src/client/WorkspaceBrowser.js` `#wsPickFlow` and `WorkspacePicker.js` `#pickFlow`: the pick-flow element is cached across renders so the `#autoOpenArmedFor` latch survives `onClose`'s synchronous re-render.
- `src/client/WorkspacePicker.js` `FreddieWorkspacePickFlow#render`: an open flow over an empty directory-flow hole (occupant unloaded, e.g. Choose again with the error dialog up) snaps back through `queueMicrotask`, after the current synchronous render finishes; occupancy loss alone is not the only trigger.
- `src/client/WorkspacePicker.js` `autoOpenKey`: the add-only auto-open is edge-triggered on `[open, addIsTheOnlyEntry, flowBusy]`. Re-checking the held-true condition every render re-armed it on each render the popover's own `onClose` caused: an infinite microtask loop that hangs the tab.
- `src/client/WorkspacePicker.js` `addIsTheOnlyEntry`: the anchor gesture runs the add action directly only once the list is settled (`workspaceSnapshot.phase === 'ready'`; the add-only surface never waits). Earlier, the menu stays up with its loading status instead of jumping into a flow the arriving list would make unnecessary.

## CSS rationale

- `WorkspaceBrowser.css`: the session list is the only scrolling region; its 2px edge offset, stable 8px themed scrollbar and remaining padding equal the shell's right inset with or without overflow, so moving the bar does not move the rows. The first insertion boundary lives outside the scrolling clip at the same -8px coordinate as every workspace boundary. The bottom fade is a compact overlay (transparent to the sidebar fill, so it tracks the theme) and the last row is cleared above it. The rail variant uses its own `.rail` class from the wide owner prop because the region never reads the shell's class names. `rows/Rows.css`: session rows fade in on mount when a group unfolds; stable row keys keep already-visible rows from replaying it.

## Contract notes

- `src/client/contract/slots.js`: two registrations share the package. `WorkspaceBrowser` fills the sidebar shell's `sidebar.workspaces` hole (header, search, grouped/flat list, dialogs), registers the viewing store and consumes the shell's two-fact owner share (wide / expandSidebar). `WorkspacePicker` fills the conversation empty-state hole. Each declares one `single` directory-flow hole (two, because a hole has exactly one declaring entry) that a composed picker package fills. ui-workspace owns the trigger (the "Add workspace..." entry, shown only while the hole is occupied) and adoption (`createWorkspace({ path })`, retryable error dialog, Choose again); the occupant owns everything up to the picked path, including creating a directory. So adding a workspace has one route, and an unoccupied hole leaves no add affordance.
- `src/client/index.js` `apply`: `freddie.client.inject` edges are informational (prefetch metadata, never sequencing) and neither owner provides a waitable service, so the sidebar and conversation slot declarations may activate after this plugin; `apply` depends on them through `slots.inject()`.
- `src/client/locales.js`: runtime failure messages (wire error strings) pass through untranslated by policy.
- `rows/Rows.js`: hover swaps (folder to chevron, time to ellipsis, action buttons) are CSS-only. Row menus are visual-only except workspace Rename/Delete and session Rename/Fork/Archive; hover cards are suppressed while a menu is open. The hover-card time keeps the bare "now" bucket (no "now ago"). Absolute creation time goes through the dictionary's date template because `toLocaleString` follows the browser language, not the app locale, and mixes languages after a switch. Session status: pending interaction is primary and live activity outranks completion reminders.
- `stores.js`: the module exports only the store factory; a module-level handle would pin store identity across plugin reloads.
- `tree.js`: unassigned sessions trail under Ungrouped (browser-local order, recency before it is initialized). Ordinary sessions are visible; among blank sessions only the selected one; subagent children use their parent header catalog; archived sessions are visible nowhere but keep their accounting slot so unarchiving restores position. `deriveSearchResults`: local title/Workspace matches lead newest-first, content-only rows keep backend order, duplicates take the backend snippet; search opens the session only.
- `WorkspaceBrowser.js`: the rail state renders two 36px icons (search, add workspace), each requesting expansion through the owner share; adding raises the directory flow with no intermediate menu. Rail-search focus waits out the column slide duration (`--ds-transition-duration-slow`) because `focus()` forces synchronous layout. Outside-click dismissal stays off while `searchOnExpand` is in flight: the rail click flips the shell wide and mounts the listener during its own dispatch, then bubbles to document with the now-unmounted rail button as target and would dismiss the search it just opened. Native drag is accepted at document level during a row drag so releasing outside the list is not shown as a rejected drop before `dragend` commits the last marker. Row elements are reused per row identity via a cache pruned each render so closed sessions do not pin a HoverCard portal.
- `src/index.js` (node half): pure UI plugin; the empty apply exists so the plugin appears in the host cordis.yml / Loader, and the browser half ships via `exports["./client"]` and the package.json `freddie.client` declaration.
- `src/invariant.js`: no runtime invariant; a pure-consumer plugin registering presentational components into two host-declared slots plus dictionaries, emitting no cordis events and owning no cross-plugin mutable state.
