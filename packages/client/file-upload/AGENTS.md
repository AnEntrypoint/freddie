# client-file-upload

## Rationale

- `stageUpload` (`src/intake.js`): the body is iterated manually, not with `for await`. Leaving a `for await` early calls the iterator's `return()`, which destroys the request stream, and the server reads a destroyed request as a client abort, so the size ceiling would cut the socket instead of answering 413. `drainRequest` (`src/http-route.js`) drains the rest once, bounded by `DRAIN_GRACE_BYTES`, before every refusal so the client gets a readable response.
- `displayOnlyName` (`src/http-route.js`): the `name` query value is display-only; the destination comes from the content digest (`UploadStaging.digestPath`), never from the name.
- `sendableBody` (`src/client/runtime.js`) taps a stream body for progress on the page and shares `progressStream` with the page-owned carrier, so `src/client/worker.js` does not count stream bytes again.
- `absoluteUrlForBlobWorker`, `postTransferringStreamBody`, `cancellationOverTransportError` (`src/client/runtime.js`): a Worker built from a Blob has a `blob:` base, so its request URL must be absolute; transferring a stream body locks the caller's stream, so a retry needs a new one; a cancelled upload tears the socket down mid-body and the carrier reports a transport error, so the caller's cancellation is reported instead.
- A receipt is minted only after bytes are committed, resolves only under the uploading session id, and is retired when the prompt that consumed it is observed. `uploadStream` authorizes the session before intake and again after, so a session that vanishes mid-upload loses its staged bytes. Session authorization fails safe: no session store, unknown id, or a subagent session all refuse.
- The route rides `webServer` directly, not the `/api` bridge (which buffers whole bodies), so it re-applies the browser-trust fence with an empty trust list: loopback only. Staged paths derive only from the validated session id and the SHA-256 of the received bytes and are contained under the staging root; the client name is display-only. Media type comes from magic bytes (`sniffMediaType`), never the request; prompt content is image-only, so non-image staged files are refused at `encodedAttachments`.
- `src/client/worker.js` stringifies into a Blob Worker: worker globals only, no imports. `XMLHttpRequest` carries a `Blob` (only API with upload progress); `fetch` with `duplex: 'half'` carries a stream. One carrier is chosen before Cordis boots: a page owning the Host transport installs `__FREDDIE_FILE_UPLOAD__`, otherwise a short-lived dedicated Worker per upload. No base64 Remote fallback.
- `src/shared.js` must stay free of Node builtins (the browser half loads it). Default per-upload ceiling is 64 MiB. `src/invariant.js` registers no runtime check: receipt tables are keyed by session id by construction.
