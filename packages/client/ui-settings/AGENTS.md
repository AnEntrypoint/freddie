# client-ui-settings

## Rationale

- `src/client/settings-mirror.js` `load()`: the in-flight slot is owned before the loading publication (that publish can synchronously reenter `load()`), and cleared in the same synchronous segment that observes `rerun` false, never in a `.finally()` (one microtask later a `load()` lands, marks a rerun nobody reads, and the read is lost). `rerun` is cleared immediately before the wire read: a mark made earlier is covered by that read, one made after needs the rerun.
- `src/client/index.js`: the first connection also emits `connection/reset`, so startup normally costs two describe reads. The in-flight fold does not merge them; it guarantees at most one pending read and no lost mid-read invalidation.
- `src/client/settings-scope.js` operation queue: the returned task carries its own settlement to the caller, while the queue tail is kept fulfilled so one failed subscriber cannot strand later operations.
- `src/client/settings-scope.js` section validation: sections must be plain objects (checked before schemastery), because schemastery alone resolves `null` or an array through object defaults instead of refusing them. A schema envelope the client cannot rehydrate vouches for no section and is treated as schema-invalid.
- Package role: settings domain base (`ctx.settingsScope`, the single `settings.describe` mirror, schema service). It depends on no `ui-*` package; the shell (`sidebar.settings` occupant, nav, chrome) lives in ui-settings-general because a ui-sidebar dependency would cycle through ui-layout and ui-theme. Cross-plugin collaboration goes through cordis services, never value imports (client bundle purity gate, `packages/client/tsdown.client.js`). The mirror invalidates on `settings/document-updated` and `connection/reset`; remote browsers persist process-local because settings RPCs are loopback-only.
- `src/client/settings-scope.js`: a superseded write's revision is kept as a fence because the mirror folds only the LATEST settlement, so a queued successor takes its revision from there first. `bind` runs on the CALLER's fiber (the service proxy binds `this.ctx` at call time), so the scope disposer belongs to the caller and binding adds no wire read.
- `src/client/contract/slots.js` is intentionally empty: the slot type contract is documented here (no typecheck consumes it). All shell text comes from registrants; the shell owns no copy.
  - `settings.trigger` (single, root): sidebar-foot trigger content, owner `{wide}`; accessible name comes from the content (rail state renders the label visually hidden). Absent: icon-only button without a name.
  - `settings.header` (single, root): panel title seat, referenced by the dialog's aria-labelledby. `settings.close` (single, root): visually-hidden close label. Owner shares carry nothing.
  - `settings.action` (list, root): optional actions in the content header before Close; registrants own visibility, behavior, copy, failure display.
  - `settings.section` (list, root): one page per entry; options `id` (drives `only` filtering), `order`, `label`. Registrants re-register on locale change (the ledger bump is the shell's re-render trigger). Owner share: `{close}`.
  - `settings.plugins.tab` (list, root): page inside the Plugins section; options `id`, `order`, `label`; declared at runtime by the Plugins section owner.
  - `settings.onboarding` (list, root): one ordered step mounted at a time; owner `{stepId, complete, openSection}`. The step owns its modal surface (including `#root` inert) and renders null while facts load; the shell paints no chrome.
  - `settings.general.item` (list, root): one preference row in General; options `id`, `order`; no label projected and no owner props. Declared at runtime by ui-settings-general; typed here because every registrant already depends on this package.
