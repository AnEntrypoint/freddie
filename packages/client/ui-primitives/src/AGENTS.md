# AGENTS.md — ui-primitives/src

## CSS rationale

- `DiffBlock.css`, `ReadBlock.css`, `SearchBlock.css`, `TerminalBlock.css`: share `CodeBlock`'s geometry (12px radius, code-block surface plus banner row, markdown code-block font) so the cards read as one family. The deliberate divergence: bodies keep `white-space: pre` and scroll horizontally because folding a source line, path or command output destroys the indentation and alignment a reader scans by. `WebBlock.css` is prose instead, so each row wraps and the list scrolls vertically within a capped height (a design constant of the card, not a plugin option).
- `WebBlock.css` `.sources`: `overflow-y` makes it a scroll container that also clips inline-start overflow, so a list marker wider than `padding-left` would lose its leading digits. `searchMaxResults` is an unbounded positive integer, so the padding is `2.5em` (against the element's own font) to hold a three-digit marker (`999. ` measures 2.35em in the app font stack) plus the one-digit gap.
- `DiffBlock.css` / `ReadBlock.css`: the copy control floats over the top-right corner so the card has no empty banner row, and the file header reserves space at the line end for it (otherwise a long path scrolls under the button and its hit area eats clicks on the path's tail); the read gutter is a fixed-width column so the content edge stays put however wide the numbers grow, and is `user-select: none` so a copy carries the source, not line numbers; the diff draws its `- `/`+ ` prefix so a copied line and the shown line agree and the sign reads without color.
- `TerminalBlock.css`: the run-state gutter is the card's OWN `padding-left`, not a margin, because every consumer rewrites `margin` wholesale, which silently cancelled the reservation and let the dot fall outside the card into a clipping container. The banner is clipped to the card radius (a consumer's border would otherwise leave a corner notch) and pulled back across the gutter then re-inset so it spans the full surface. The prompt row uses `pre`, not `nowrap`, because `nowrap` collapses repeated spaces, tabs and indented continuations. Vertical scrolling lives on the OUTPUT, not the card root, which would run its scrollbar over the banner and copy control; scrollbars float 2px off the card edge via a transparent border and track end-margins keep the thumb out of the rounded corners. The status pill and copy control are capped to the prompt line height, sticky against the banner's scroll and drawn on the card surface, not transparent, so scrolled command text cannot bleed through. `--dsl-terminal-font` and `--dsl-terminal-line-height` are rebindable by a consumer wanting the smaller code size.
- `Toast.css`: the fade delay and duration MUST agree with `HOLD_MS` / `FADE_MS` in `Toast.js`, which unmounts at their sum; a mismatch cuts the fade or leaves an invisible banner. The banner is `pointer-events: none` (an announcement must never intercept clicks, notably after the fade while a throttled background-tab timer has not yet unmounted it); the copyable variant re-enables pointer events only while visible, because the `forwards` fill leaves opacity 0 and a transparent element still hit-tests, and takes them away again at the end of the fade. Hover or focus holds full opacity with the fade cancelled (the JS clears its unmount timer in the same gesture) and needs its own reduced-motion rule, since reduced motion drops the slide-in but keeps the delayed fade. It sits above the lightbox backdrop's z-index 1000 so a failure reported during a preview stays readable.
- `Menu.css`: portal mode is `position: fixed` with coordinates set inline from the anchor rect (side and align resolved in JS) and layers above modal overlays so an anchor inside a dialog still gets its menu on top. `.scrollable` stops 12px short of the viewport edges (24px = 2 x `MARGIN` in `Menu.js`) and scrolls inside `.viewport` so a pinned footer stays visible; menus with submenu rows skip it because the overflow clip would crop the side card. `.submenu` sits `left: calc(100% + 10px)` and `bottom: -4px` (the list's 4px pad plus the 6px gap; plain `100% + 6px` collapses to about 2px between outer card edges) and its `::before` bridges the gap so the pointer can cross without `mouseleave`.
- `Tooltip.css`: `max-content` sizing capped at half the viewport, because a fixed-position shrink-to-fit box measures only the space from `left` to the viewport edge and anchors near the right edge would wrap early. `HoverCard.css`: block, not `inline-flex`, because consumers wrap full-width rows; the card is hit-testable on purpose so resting the pointer on it holds it open (the grace close), which `pointer-events: none` would defeat.
