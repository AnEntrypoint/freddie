# Client runtime

## Rationale

- agents/scope.js `kScope`: `Symbol.for` so an HMR re-evaluation keeps the same tag (host freddie-scope does the same).
- contract/store.js `update`: a draft that mutated nothing is dropped (deepEqual gate); entries write their own store during render, and an identical clone would loop any outlet subscribed to what it reads.
- index.js `onConnected`: a changed `instanceId` means the server restarted under this socket and this tab holds the pre-restart bundle; reload rather than resync onto stale code.
- index.js `onStateChange('reconnecting')`: generation death precedes any next-generation frame (replays precede `onConnected`), the only safe moment to drop generation-scoped interaction state. `host/remote-event` is fanned out here because the session layer ignores registry frames.
- sessions/failure-display.js: AUTH failures project as a fixed message; provider text may echo a masked or partial credential. Raw diagnostic stays in the session log, never UI state.
- sessions/context-provenance.js: no table of known plugin ids; role and label come from the durable `source` alone so renamed, resumed or foreign logs project like live ones.
- sessions/conversation.js: every change swaps the top-level snapshot while unchanged substructures keep references (React.memo).
- sessions/conversation-assembler.js `replaceLocationData`: each scope phase (step, then turn) installs its cumulative data before the next builds; Turn publishers may read Step data in the same flush.
- sessions/notifier.js: `notifyNow` is only the direct echo of a user gesture; structural updates use `markDirty` (microtask-batched), visible streaming chunks `markFrameDirty` (one per animation frame, microtask without `requestAnimationFrame`). Flush rebuilds the snapshot BEFORE notifying (a `getSnapshot` reader needs a stable snapshot). `dirty` and `notifyPending` are separate so `ensureFresh` never swallows the notification (push subscribers would starve).
- sessions/provide.js: a failed `provide` splices the provider out and re-applies the prior roster. `publishCurrent` contains subscriber throws: it runs inside the list notification and one would starve later listeners.
- slots.js `inject`: any setup failure retires the injection permanently (`stop()`). `hostFace.locale` is a live getter (alias `service`): the face installs and HMR-swaps on the locale plugin's fiber while the host object is built once. `_register` runs `_core.register` first so load-time validation throws before store refs are acquired.
- workspaces/manager.js `upsert`: rejects a view older by `updatedAt` (unary responses and changed frames race unordered). `remove(direct)` still `notifyNow`s when a host frame removed the row first.
- workspaces/service.js `connectWorkspace`: concurrent connects coalesce (create's summary lacks cwd until the host frame, so a second call would mint another hidden blank). Reuse needs id in `sessionIds` AND cwd match (host membership rule); archived blanks are never reused. `project` clears an archived current selection (local echo, another tab's frame, reconnect baseline).
- sessions/{manager,session,service}.js: wire values import from `@freddie/freddie-host-apiproxy/api`, never the connection plugin (bundle-purity gate forbids cross-plugin value imports).
- manager.js `get`: replay `pendingBuffers` BEFORE the running/blank sync so a not-running summary sweeps replayed queue rows. Catalog children sync `blank=false` (child rows carry no `blank`).
- manager.js `refreshList`: `syncCompletedNotifications` runs after EVERY replayed mutation (one sync on the folded result misses idle-running-idle). Projection blocks use per-key `store.apply`, not `seed`: the list block is partial, an absent key must not clear.
- manager.js `session/subscribed`: new-generation re-baseline. The host omits an empty `session/queue`/`session/jobs`, so buffered queue frames, jobs and terminals reset here; projection rows past `lastSeq` are truncated.
- manager.js `session/projection`: `markDirty` stays synchronous (the store's any-key channel is microtask-batched) so the list is same-tick fresh. `pendingBuffers`: approval/question requests never reach history, so uninstantiated sessions buffer them keyed and deduped; every other frame drops (open backfills).
- manager.js `host/session-removed`: a durable subagent only goes idle, keeping lineage. `jobsBySession` clears here because owner disposal rides the mux stream, unordered against this frame. An in-flight catalog pull gets `parentAvailableOverride=false` plus a trailing refresh (a pre-removal true would revive the writable editor). `catalogStale` queues one trailing pull after an in-flight one settles.
- manager.js `create`/`fork`: a `workspace-attach-failed` error carries a real published session id; upsert it although the call failed. `applyMutation`: blank only lowers; `agentPreset` newest wins; `activity` is max-wins (replayed older user messages).
- session.js `prompt`: `promptAttempted`/`firstPromptPendingTurn` are set before the first await (blank-to-engaging edge on the first frame). `blankBit` lowers on ACCEPTANCE only: flipping on a rejected first prompt surfaces the session forever and drops `connectWorkspace` reuse.
- session.js `resync`: queue mirror and pending waits are NOT cleared (onConnected races mux frames, the host never resends the baseline); they re-baseline on `session/subscribed`. An idle reopen re-pulls the tail (a mux drop can land `turn/end` after the first page).
- service.js `followCurrent`: runs synchronously inside the list-store notify; safe because `open()`'s sync prefix touches only session-side state. A masked gap (current blanked, session transiently absent) holds the stage. `projectList` wipes the persisted selection when current is undefined.
- agents/scope.js: mirrors host `freddie-scope` (no-op fiber + context tag + `Context.filter`) but the filter lives on the actx itself (scoped dispatch is plain `actx.bail(actx, ...)`); key is the branded `SessionId` compared by value (agent id === session id); it scopes the Agent identity, not a live Agent, because a cold session's host Agent is disposed while its client actx stays for history viewing.
- contract/store.js: engine is hand-rolled (no zustand/immer); persist is hand-rolled because zustand's persist spreads state and explodes primitive state into `{0:'h',...}`; storage failures only disable persistence. `flush:'raf'` skews a mid-frame mounting component vs existing subscribers by one flush. `singleFlight` shares one pending promise (not a no-op) since a controller's `load()` has several simultaneous triggers (~40 concurrent identical wire calls were witnessed). `defineStore`'s `A & ActionsDecl<T>` position is load-bearing: it lets TS infer the draft param from `init`; fallback design is currying.
- slots.js `register`: must stay a prototype method (assigned after the class), never an instance arrow; the cordis service proxy binds `this.ctx` to the caller's context, which routes the effect and unload cascade into the caller's fiber. `dropSessionInstances` materializes an unpersisted-looking instance transiently to clear storage keys left by an earlier page load. `winners` returns a fresh array per call, so it is not a uSES `getSnapshot` source.
- workspaces/manager.js `removed` tombstones: correct only because Host workspace ids are never reused (fresh `randomUUID` per record); a path-derived id scheme must clear them. A frame/echo that installed the archive set during an in-flight list request outranks the older baseline set. Archive comparison is positional because host snapshots are append-ordered.
- session.js `installWindow`: stitches `liveBuffer` directly, never via `acceptLiveEvent` (`openState` is still 'loading' until `doOpen` flips it, so recursion would re-buffer every event into a queue nothing drains). `openGeneration` invalidates in-flight open/resync passes: every await re-checks it and a stale pass drops all writes. Window stays one contiguous raw range; a seq gap buffers and repulls the tail instead of appending a hole.
- session.js `events`/`views` are parallel arrays (the wire view stays out of `events` so the raw log slice is exactly what the model saw).
- projection-store.js: a lower-or-equal seq loses in both frames and baselines; a baseline that omits a key clears it unless a newer frame superseded the cut; rows past a new mux baseline `lastSeq` are dropped (they rode state a restart lost and would outrank recomputed values forever).
- service.js stage: staging is the open signal (window opens when the session is on stage); a session removed while staged defers its scope teardown (frozen read-only view) until the stage moves. Scope/binding resolution is pure and render-safe (StrictMode double invoke); side effects live in `followCurrent`.
- service.js `fork` title: only the trailing fork number is incremented, keeping half-width or full-width parentheses; a fractional seq anchor floors to an integer (frozen interrupted-turn nodes carry flow-ordering seqs between events; the wire takes integers).
- service.js `scopeOf`/`sessionOf` are service methods: fetch bundles must not value-import the standalone helper (a second module instance would have a private tag Symbol that never matches).
- context-provenance.js: `MessageSource` is merge-extensible, so unreadable shapes degrade to `inject` and unknown context forms to the opaque presentation.
- assistant-timing.js: step key uses a NUL separator; steps whose start or first token fell outside the window yield null boundaries.
