# ui-tool

## Rationale

- `components/ToolRow.js` `#everOpened`: a never-opened row builds no card body. ReadBlock/CodeBlock tokenize through shiki on every render, and a keystroke re-renders every mounted row (40 collapsed rows measured ~0.5s synchronous plus ~3s over the next two frames). The latch is never cleared so `keepContentWhenOpen` keeps block state (copy feedback, expanded sub-state, highlight memo) after collapse.
- `ToolRow.js` `#terminalEl`/`#diffEl`/`#readEl`/`#searchEl`/`#webAnswerEl`/`#codeEl`, `toolviews/bash-sample.js` `#terminalEl`, `ToolDetails.js` `cachedBlock`: the `render*Block` one-shot factories (and WebBlock's inner MarkdownText) recreate their DOM on every call, dropping copy/expanded/highlight state, while rows re-render on every streaming state change. Cache per row instance (a call carries one card kind, so one is non-null) and per selected `block` identity in a WeakMap.
- `ToolRow.js` `openFile`/`fileLinkKeyDown`: the path link stops click and Enter/Space propagation, because the row's keydown (`DisclosureRow.js`) calls `preventDefault()` and toggles expand instead of activating the link.
- `toolviews/bash-sample.js` and `GenericToolCard.js`: a failing exit status (`terminalFailed`) is the terminal card's own error signal; the call itself settles `isError: false`, so the red state dot is derived from the card.
- `toolviews/bash-sample.js`: registrants use `ctx.slots.register` and ToolRow props only and never import the chat domain; the row replicates ToolRow's expand and hover-Inspect interaction locally for that reason.
- `models/terminal-card-model.js` `terminalCardModel`: only a present call view can mean "omitted cwd, use the workspace". A settled result whose window dropped the call head has no cwd anywhere (the original call may have used an explicit workdir), so `cwd` stays undefined and the prompt draws a bare `$`.
- `models/search-card-model.js` `searchCardModel`, `models/web-card-model.js` `webCardModel`: view frames are untrusted wire data. The host schema checks `card`/`shape` strings but not `files`/`paths` contents or the web `kind`, so grouped `files`, `paths` and `kind === 'fetch'` are validated explicitly and anything unknown returns null (generic view) instead of crashing SearchBlock or drawing `HTTP undefined`. The `oxlint-disable-next-line` guards are load-bearing despite the compiled unions.
- `search-card-model.js`: `recovery` (the raw result text holding the `Full ... stored at ...` locator) is carried only when `truncated`; it is the only route to the dropped rows.
- `models/read-card-model.js` `readCardModel`: lines are copied into the primitive's own shape so the card holds no reference into the runtime's frozen snapshot cache.
- `models/diff-card-model.js` `diffCardModel`: a settled result's applied hunks replace the call-time diff; a window that dropped the call head still renders from the result view alone.
- `models/tool-call-model.js` `toolRowModel`: `resultText(block) || null` makes blank content mean "no text", since a blank first line would erase the collapsed error row's summary and blank content has nothing to expand.
- `toolviews/ask-question-row.js` `AskQuestionRow`: apiproxy settles composer verdicts as `UserQuestionError` codes. `ASK_CANCELLED` is the user dismissing the set; `ASK_ABORTED` is a turn interrupt while pending and keeps the shared stopped (amber) state. Both name their verdict instead of the generic failed shape.

## CSS rationale

- `ToolRow.css`: the trailing summary fragment (the todo row's parallel-active `+n`) is `flex: none` and `nowrap` outside `.summary`'s ellipsis, because `flex: none` stops the box shrinking but not the text wrapping, which would break the one-line row in the narrow case the slot exists for. The Inspect pill sits in real flow under the expanded body's bottom-left (it reserves its line, so revealing never shifts layout), is revealed by hovering anywhere on the tool call or by keyboard focus, uses the base background (`bg-overlay` reads too heavy) and a solid hover fill (a translucent token would let content bleed through). Expanded IN/OUT and terminal cards scroll INSIDE their own surface so the scrollbar sits within the rounded card; the terminal output cap is 224px (260px card cap minus the ~36px banner), and the running-state label is visually hidden text because the `StateDot` and sweep are aria-hidden and color-only. The block-shaped bodies (run_code `CodeBlock`, terminal, diff, read, search and web cards) are drawn by the shared primitives, so this file owns only their indentation and replaces each primitive's standalone vertical margin with the row rhythm.
- `toolviews/bash-sample.css` deliberately repeats ToolRow's expand-pointer, chevron-hover preview, running sweep, terminal-card and Inspect-pill rules because each registrant owns its own module; it also keeps ToolRow's bounded IN/OUT fallback for a bash error that settles without terminal-card material (for example command cancellation), so the command and full error stay available from the keyed row.
