# AGENTS.md - ui-directory-picker-browse

Rules for this package. The package contract is in [README.md](README.md); the client rules are in [../AGENTS.md](../AGENTS.md).

## Rationale

Facts that a name cannot carry; each bullet names the file and symbol it belongs to.

- `index.js` (`apply`): the two `directoryFlow` slot registrations are one transactional effect, so both declaration lifetimes must be live before the pair installs; the nesting order of the two `inject` calls is arbitrary.
- `#supersede`, `#requestSeq`, `#openGeneration` (`DirectoryBrowser.js`): a newer intent aborts the in-flight listing on the wire (the Host stops scanning, not just the result being dropped) and bumps `#requestSeq`; every settlement compares its seq. `#openGeneration` (bumped on each open/close edge and on disconnect) fences settlements from a previous open, a pending folder creation included, so they never mutate a reopened dialog or relist a stale target.
- `#land` (`DirectoryBrowser.js`): a landing swaps panes and never blanks them. Away from the display root it is two-pane (target's actual entry re-selected in the parent level, matched case-insensitively when the separator is `\`, because Windows keeps the typed case); a submitted navigation (`closeEditor`) waits at most `PARENT_LEG_WAIT_MS` for the parent leg and a late leg upgrades in place, while the editor's draft-following scan waits for both legs so one keystroke moves the view once. A failed parent leg is silent. `#scanned` remembers what a draft scan asked for and what came back, so the draft still matches when the host respelled it (`..`, forward slashes).
- `#select` (`DirectoryBrowser.js`): deliberately not one-frame like `#land`; the pane split is the click's own feedback. An unreadable selection clears itself so the view falls back to the single pane.
- `#cancelPathEdit` (`DirectoryBrowser.js`): supersedes the pending navigation so a late success cannot jump to the cancelled path; with no preview it falls back to the single pane, and with no level listed it restarts the home listing (else the picker stays blank). Opening the editor supersedes any pending listing for the same reason, and its draft is seeded with a trailing separator so typing continues into child names.
- `#confirmCreate` and the Enter handler of the path input (`DirectoryBrowser.js`): `trim()` only rejects a blank draft, the Host gets the original text, because a real name may end in whitespace and trimming would create or list a different sibling.
- `#previewSuspended` (`DirectoryBrowser.js`): set on Enter so a pending draft-debounce timer cannot supersede the submitted navigation and land the draft's parent; the next edit releases it.
- `#onOpenEdge` (`DirectoryBrowser.js`): closing clears `#loading`, else the slow-scan timer keeps arming while hidden and the reopened dialog shows the indicator on its first frame; it also retires armed refocus flags.
- Editor scope `onkeydown` and `onblur` (`DirectoryBrowser.js`, `css.editorScope`): path-edit cancellation lives at the card scope because once Tab parks focus on a filtered row the input is off the event path; Escape stops propagation so the `Modal` document listener does not close the dialog. Blur cancels only when focus leaves this card (`closest('[role="dialog"]')`, so a sibling overlay counts); it ignores window focus loss, moves inside the card, and an Enter still in flight (the input keeps focus).
- `#refocusPick`, `#refocusEditZone`, `#refocusPathInput` (`DirectoryBrowser.js`): when an editor exit unmounts the focused node, focus falls to body; after the commit it is re-parked (a pick on the selection's `aria-current` row in the left pane, Enter and an input-focused Escape on the crumb edit zone), and only if focus really fell to body. Pointer-out cancels never set them. Rows and the hidden toggle `preventDefault` on `mousedown` while editing so a focus steal cannot blur the editor and drop the click.
- `parentInert`, `draftPending` (`DirectoryBrowser.js`): while the nested create dialog is open every parent control is disabled; while a path draft is uncommitted `targetPath` is stale relative to the header, so Open and New folder are disabled.
- `#outerModal`, `#createModal` (`DirectoryBrowser.js`): body-portaled `freddie-modal` elements held and updated in place; hiding this element does not hide those siblings, so a closed render closes both explicitly or their masks keep intercepting clicks. The crumb trail and Miller row are scrolled to their end after each render so the current directory and a child preview stay reachable on a narrow window.
- Truncation note (`DirectoryBrowser.js`): shown from the panes on screen and untouched by an in-flight scan, so it does not shift the columns on every navigation away from a cut level.

## CSS rationale

- `DirectoryBrowser.css`: the doubled class beats Modal's own `.dialog` regardless of stylesheet order; header and footer are flex-none while the columns scroll, so a short viewport keeps Open/Cancel reachable; the path bar IS the editor's box in both modes (outline and padding on the bar, hover on the edit zone lights the whole row, a negative left margin pays back border and padding so text keeps the title's column) and is lit by the affordance it belongs to, never by a crumb, whose hover offers navigation, not path entry.
- `DirectoryBrowser.css` columns: on a narrow viewport the Miller row scrolls horizontally (the effect pins the child pane into view) below a 256px per-column floor; the themed classic scrollbar occupies the column edge, so extra clearance keeps row pills off the thumb. `.loadingFloat` floats over the content's bottom-right corner so a scan never shifts column height and the stale view keeps rendering beneath it (it appears only once a scan outlives `SLOW_SCAN_DELAY_MS`); right, not left, because the truncated/error status rows flow at the bottom left; it must follow `.status` in the cascade since the element carries both classes and its padding must win the same-specificity race.
