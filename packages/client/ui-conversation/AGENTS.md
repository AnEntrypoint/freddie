# AGENTS.md - ui-conversation

Rules for this package. The package contract is in [README.md](README.md); the client rules are in [../AGENTS.md](../AGENTS.md).

## Rationale

Facts that a name cannot carry; each bullet names the file and symbol it belongs to.

- Composer ownership (`ConversationRoot.js`, `ConversationComposer.js`, `apply.js`): the Root keeps the direct scrollport, seat and observer; the session-maybe body owns composer/hero declarations and complete input currency. The audited layout/session/header/chat markers opt into tracked reads; composer and InputBar retain default delivery ([decision](../../../.agents/notes/implemented/architecture/2026-10-06-composer-read-tracked-subscriptions.md)).

- Portal ownership (`skeleton/PermissionSelect.js`): detached factories render controls but cannot own a body-mounted confirmation. Connection creates or updates the portal; disconnection removes and clears it ([lifetime](../../../.agents/notes/implemented/bug-fix/2026-10-06-connected-session-export-modal-owner.md)).
- Controller publication (`apply.js`) awaits the owned `ConversationController` fiber before publishing session input and slot consumers: an already-selected session renders synchronously during HMR. `input/hub.js` binds each shell to both plugin and session effects; either disposer removes the other owner, and `input/facade.js` releases its queue subscription before machine release ([lifetimes](../../../.agents/notes/implemented/bug-fix/2026-10-06-conversation-controller-publication-order.md)).
- One-shot helpers (`h(Tooltip, ...)`, `MessageIconActions()`, `JsonBlock`, `CodeBlock`, `MarkdownText`, `Menu`, `PermissionSelect`, `RiskConfirmation`): `applyDiff` replaces a raw DOM Node child instead of updating it, so calling one from a render that re-runs recreates the element, drops its state (copy timer, hover delay, open toggle, incremental markdown) and orphans body-portaled children. Hold the element and update it through the `render*` form (`renderTooltip`, `renderMenu`, `renderRiskConfirmation`, `renderPermissionSelect`), or cache it per stable chat `node` (`cachedMessageIconActions`, `cachedJsonBlock` in `MessageItem.js`; `TurnTailNodeView.js`, `ChatNodeSeat.js`; `ref` in `ContextInjectionRow.js`; `callId` in `DetailsPanel.js`). `AssistantMarkdown.js` owns its block-index cache in a native element keyed by `node.key`, not the assembler's rebuilt node object. Keep that cache through transient DOM disconnects; a module-global element cache prevents disposed rows from being collected. Its VNode omits children so parent diffing cannot erase the private subtree, and uses `defineElement`'s returned tag so namespaced creation respects HMR registration ([lifetime](../../../.agents/notes/implemented/bug-fix/2026-10-06-assistant-markdown-cache-lifetime.md)).
- `#renderedOnce` (`ConversationRoot.js`, `ConversationComposer.js`, `InputBar.js`): props delivery renders while detached to collect observable dependencies. Connection renders initialized elements again to establish live DOM bindings; a connection before props does nothing. Do not replace either render with an identity guard on mutable session handles.
- Identity-compared props: `MarkdownText` compares `fileMentions` and code labels by identity, so `#openFile` (`ChatView.js`), the fence labels (`AssistantMarkdown.js`, per `t`) and `cachedMentions` (`AssistantNodeView.js`, keyed by `node`: `owner` is a fresh literal and `turn` rides `node.location`, which snapshots rebuild) must stay stable, or the closing block re-parses on every keystroke.
- Row windowing (`ChatView.js`): mount the initial 40-row slice before opening, restore only while connected, and center on the saved owning `windowKey`; nested tool anchors are absent from `chat.order`. Moving either edge retains the visible span and anchor, with `mountedRowBudget` plus one reveal step when the viewport needs more rows. Prepending shifts both finite bounds before rendering. Only a mounted logical tail can follow or show running-turn and steering rows. Reader scroll does not redraw unchanged flow ([decision](../../../.agents/notes/implemented/architecture/2026-10-06-conversation-moving-row-window.md)).
- `#pendingEdit`, `editRangeOf` (`InputBar.js`): `beforeinput` is the only moment a textarea still holds the pre-edit selection (`getTargetRanges()` is empty for form controls); diffing drafts is ambiguous when typed text repeats what it lands against (a trigger char typed before a reference reads as inside it). Only `insert*`/`delete*` record a range; a history replay reports wherever the caret sits.
- `#revealCaret`, `#restoreCaret` (`InputBar.js`): the hidden mirror shares the draft's metrics and wrap width, so a collapsed Range at the caret index measures it. After a newline engines disagree (chromium returns no rects, firefox the line above), so the newline is measured and one line added. Paste and cut write through the machine and a programmatic selection change reveals nothing, so they ask for the reveal.
- Unlock effect (`InputBar.js`, `#afterRender`): `focus({ preventScroll: true })`, because the browser's reveal would move the transcript under a user who only switched session; the caret is revealed in the box instead. A persisted draft arrives after that effect (parent mount effects run after children's), so a second reveal fires when the draft becomes non-empty, without focusing. `repairSafariTextareaLayout` runs only after a native shrink.
- `#composing`, `LEGACY_IME_COMPOSITION_KEYCODE` (`InputBar.js`): composition Enter picks a candidate and must not send; Safari delivers the closing keydown after `compositionend`, so clearing is deferred one tick; Shift+Enter is decided before the IME guard. `canSteerQueue` is a thunk on purpose: eager evaluation walks the queue and resolves draft images on every keydown. `#toastSeq` keys the Toast so a repeated message restarts its cycle.
- `settling`, `hero` (`ConversationRoot.js`, `ConversationComposer.js`): while a session replays the composer renders hidden instead of flashing hero then docked; a session the list summary proves blank is exempt in every open state, since it can only land on the hero. A raised block keeps the model seat live (choosing a model clears it) and the bar is one session-maybe slot with `inert` as a prop so the textarea survives transitions. Composer blocks flow one way: plugins this package cannot import raise them, the bar reads them.
- `apply.js`: the approval takeover has `priority: 1` so a question takeover (default 0) wins when both are pending; the approval re-elects when the question resolves. The no-session hook sources are module constants so `observableHook`'s per-source cache keeps one identity. Reader positions are deliberately not persisted.
- `subscribeStore` (`ConversationSession.js`): the header and body subscribe directly for their own element renders on view and inspection changes, alongside observable `useStore` reads tracked by the slot framework. `data-approval-scroll` (`ApprovalPanel.js`) has `tabindex="0"`: it scrolls but holds nothing focusable, so a keyboard user could not reach the command's tail.
- `ContextBody.js`: every form falls back to `OpaqueBody` (absent, unknown, malformed) so a resumed or foreign log renders; an unrecognized action is not shown as loaded or updated; an empty catalog list is real (it retires every earlier name); rows are index-keyed because a foreign log may repeat a name.
- `input/machine.js`: typing joins the open undo run only while contiguous and inside the merge window; undo/redo pushes the log manually because `pushTxn` would cut the redo chain. After submit, text appended during the Host round trip survives only as a pure suffix, sent content leaves the undo log, a command claim persists only while the live draft equals the enter-time draft, and a warmup failure keeps the draft instead of downgrading to a prompt.
- `input/facade.js`, `input/hub.js`: a claim that does not declare image acceptance never submits with images (one notice, all retained); machine-driven draft replacements bypass `onChange`, so the caret is re-tracked; a dead attempt must not reach the Host executor; release settles after the submit RPC, when teardown may have unloaded the conversation service.
- `MessageIconActions.js`, `QueueDock.js`: an unavailable branch action uses `aria-disabled`, not `disabled`, because native disabled buttons deliver no hover or focus events to the tooltip; the queue's unsupported-edit hint stays a native `title`. `ModelRetryItem` (`MessageItem.js`) anchors the host-scheduled delay to this browser's first render because host event time and `Date.now()` may be different clocks.
- `service.js`: the cordis Service tracker rebinds `this.ctx` on property access through `ctx.conversation`, so methods read the session tag with `scopeOf`; mutable state must stay reachable through one property read because assignment through the tracker proxy and `#` private fields bypass the rebinding.
- `input/facade.js`: the InputState store batches notifications through `raf` for observable input readers; InputBar re-renders synchronously from `#onChange`, so its controlled value never depends on that subscription. Submit serializes references through the session controller's codec routing; owner missing, serialize failure or disposal blocks the send with a notice and keeps draft and chips.
- `input/hub.js` steer-all: strict steer in FIFO order; `steer-unavailable` and `queue-item-not-found` converge silently (a row the host already steered makes the repeated steer a no-op), any other failure is one composer notice.
- `input/submission-policy.js`: direct `steer` is best-effort; AgentLoop turns a closed-window submission into the next waking Queue item. Host and Agent own the delivery window.
- `input/machine.js`: draft edit, occurrence reconciliation and undo push are one transaction bumping `draftRev`, so span CAS is revision equality and mutation success is read as a `draftRev` advance. The machine owns each attempt's AbortController and drops stale `adjudicated`/`adjudication-failed`/`submit-settled` events by `seq`. Paste-upgrade of a matched token is its own transaction (undo one restores the token text, undo two the pre-paste draft).
- `input/decorations.js`: a reference token needs the trigger at draft start or after whitespace and an exact lexicon member name.
- `skeleton/ContextMeter.js`: the occupancy sentence is split on a marker so each locale keeps its own word order while the headline keeps its tone.
- `skeleton/EmptyHero.js`: hero chrome has no glow, composer or workspace row; the workspace row rides the InputBar accessory hole.
- `skeleton/TodoPanel.js`: the `TodoItem` status union is re-declared locally because client packages do not depend on `freddie-llm`.
- `invariant.js`: no runtime invariant; the `conversation.view` tab ring and `conversation.chat.node` renderer seat ride the slot system whose ledger invariants live in the runtime slots package.
- `submission-settings.js`: the default keeps Enter-as-Queue for running conversations.
- Custom elements converted from React hold former refs/state as private fields, re-render with `applyDiff(this, vdom)`, and pair bind/unbind methods with `connectedCallback`/`disconnectedCallback`; the one-shot `create*` helpers keep the old function-component call shape.

## Rendering contracts

- `chat/ContextBody.js`: model-facing text is bounded at the disclosure, not the producer. Content runs keep
model order: adjacent text joins with no separator, an unknown block breaks the run and keeps its own fallback
(the block union is merge-extensible). Instruction, catalog, snapshot, recall and relay readers are all-or-nothing
(an unreadable source falls back to the opaque body; the row is labelled with the form actually rendered).
`instructions` keeps its `<system-reminder>` framing verbatim; `snapshot` shows sections as assembled plus the
supersedes framing line as a caption; `relay` shows the sender session id as a field (no title resolution);
`recall` shows retained/omitted counts; only `notice` supplies a collapsed one-line summary. `kind` is always
omitted from source fields, `form` only when a dedicated body rendered.
- `chat/StatsLine.js`: the node fold is only the fallback for assemblies without the `sessionStats` projection;
context occupancy uses `projectedTokens` (bare sample only for logs predating it); numerator and capacity are
independent last-wins fields, so the figure is a reference, not an exact measurement.
- `chat/turn-metrics.js`: TTFT is the turn's lowest-step reading, valid only when the turn start is inside the loaded
window (callers gate on `turnTimings`); throughput divides summed output tokens by summed decode time of steps
carrying both.
- `chat/MessageItem.js`: user-bubble `/name` and `@name` tokens decorate by shape alone (validated at compose
time); the logged model text stays the single truth.
- `conversation-nodes/common.js` and `turn-max-tokens.js`: the max-tokens notice sits between the closing Assistant
and the turn-tail so the tail stays the turn's last node and keeps branch enabled; with no closing text Assistant it
anchors at the `turn/end` seq.
- `conversation-nodes/turn-error.js`: retries run inside the failing turn, so `llm/retry` history never suppresses
the terminal error row; the retry node renders that history separately.
- `contract/slots.js`: the approval face forwards render identity and question material from the carrier; `answer`
owns the wire encoding, throws on a rejected carrier receipt, and panel removal stays frame-driven via the broadcast
`approval/resolved`.
- Input visibility tiers: business packages see `InputState` through the InputZone currency; scoped input events carry the mutation verbs; only the conversation wiring layer sees the full `SessionInput`; `InputMachine` (`input/machine.js`) is package-private.
