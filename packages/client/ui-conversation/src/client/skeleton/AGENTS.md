# AGENTS.md — ui-conversation/src/client/skeleton

## CSS rationale

- `ConversationRoot.css` `[data-ce='freddie-conversation-root']` / `[data-ce='freddie-entry-host']`: custom-element tags default to `display: inline`, which ignores `height: 100%` and breaks the height chain down to `.scrollBody`, so the transcript never overflows or scrolls. `display: contents` removes the wrappers from layout. They are selected by `data-ce` because a hot-reloaded class registers under a versioned tag (`--v2`) while every instance carries `data-ce=<logical tag>` (`defineElement`).
- `ConversationRoot.css` `.root`: `--freddie-chat-content-width` (W) is the one content width for the transcript, the dock cards (card minus four 8px insets) and the takeover cards; the input card alone is W + 32px. On narrow viewports the chat scroller and takeover frames pad clearance + 16px per side while the input card clears the bare clearance, so the relation holds at every width. Declared on the root because the transcript and the composer seat are sibling subtrees.
- `ConversationRoot.css` seat: `--freddie-composer-text-max-height` is declared on the seat (the only shared ancestor of the fallback and the elected overlay) so the InputBar draft and every takeover body top out at one height and electing a takeover never grows the footer past the card it replaces.
- `ConversationRoot.css` scroll body: `overflow-x: hidden` is stated explicitly because a box scrolling on one axis computes the other axis to `auto`, making any bleed user-scrollable; the scrollbar gutter is reserved unconditionally because the composer seat rides the content box in Chat and the padding box under a view's composer overlay, so an `auto` gutter would move the input card sideways when the two differ ([decision](../../../../../../.agents/notes/implemented/bug-fix/2026-08-04-composer-tab-gutter-reservation.md)). The overlay seat gives back `--freddie-scrollbar-width` (mirrors the WebKit bar width); an engine resolving a different width drifts the card by half the difference, an accepted residual risk ([decision](../../../../../../.agents/notes/implemented/bug-fix/2026-08-12-composer-overlay-seat-width-compensation.md)).
- `ConversationRoot.css`: the composer seat sits above markdown `CodeBlock` sticky banners (z-index 6); the input mask fades the transcript under a FIXED 36px band with px stops (not %) so a growing draft only widens the solid region, and its 0px stop is bg-base at zero alpha, not white, so both themes fade from their own base; the overlay clip box is a scroll container on both axes rather than `overflow: hidden`, since a single-axis scroller computes the other axis to `auto` and the seat's absolute positioning needs a containing block in every engine; the hero is flex-centered, NOT absolute + transform, because a transform would make the box the containing block for `position: fixed` descendants (pickers, modals) and shrink them; the settling phase keeps the seat mounted but invisible so no wrong layout flashes before the phase lands.
- `InputBar.css` draft: `.scroll` is the ONLY scrolling box in the composer. The caret belongs to the textarea and every visible glyph to the backdrop, so they stay together only by riding one browser-applied offset; assigning an offset from one box to the other trails by frames because wheel scrolling composites off the main thread. The mirror, backdrop and textarea must share font, line-height, padding and wrapping (the mirror sets the height), and all three sit inside `.scroll` so a scrollbar narrows their shared containing block equally: a self-scrolling textarea makes WebKit reserve gutter only for it (768px against 776px, two to five extra wrapped lines). The line-height must resolve to a length, since the caret reveal parses it; `normal` would make the reveal a silent no-op. The backdrop owns glyph colors, range marks and the disabled color (the textarea stays caret-only so its marker glyphs cannot cover reference icons); reference highlights are pure range marks with `box-decoration-break: clone` and the leading marker reserves the icon's advance.
- `InputBar.css`: textareas default to `content-box`, so the shared `.input` / `.mirror` / `.backdrop` rule sets `border-box`, or the `width: 100%` textarea gains its padding outside the card and wraps 28px later than the mirror and backdrop; the no-workspace trigger's dashed stroke is an `::after` overlay (theme-token background masked by an SVG dash ring, 1px visible inside) because native `dashed` has a fixed pattern and cannot keep the 22px radius; disabled toolbar controls pass pointer events through so the whole capsule is one pick target; the toolbar wraps so the trailing model/send group takes its own line (auto margin re-anchors it right) instead of the left chips shrinking until one overlaps the model trigger; the send circle opts out of the row's 2px shift with `transform`, not margin, to leave flex centering untouched; the toolbar `.row` is an anonymous `container-type: inline-size` because CSS modules hash `container-name` per module, so a named container could never match `PermissionSelect.css`'s `@container (max-width: 460px)` (460px is where the row starts squeezing labels).
- `ApprovalPanel.css` scroll region: an agent's justification and command are unbounded model text in a fixed-height column, so uncapped a long command pushed the action row past the viewport and the approval could not be answered; the strip and action row stay outside the region. It is `border-box` so the cap is the region's outer height, matching the composer draft area's box so the two seats are interchangeable.
- `PermissionSelect.css` `.trigger`: `inline-flex`, not inline, because an inline seat reserves baseline descent under the svg and floats the glyph off-center in the 28px trigger. `ContextMeter.css`: the design platform ships no purple static token, so the tint is a violet-400 literal.
