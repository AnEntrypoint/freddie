# AGENTS.md — ui-user-questions

## Rationale

- `PlanReviewPanel.js`: a `plan-review` question takes the waiting-approval card shape (tinted strip, content, right-aligned action row) instead of the generic flow's pager, numbered options, skip and custom answer, which read as a quiz the user is graded on. Approve and decline answer with the option labels the asker offered (asker descriptions become tooltips); "discuss" is the generic flow's cancel verb promoted to a labelled button, because in a two-outcome decision dismissal is the third real answer.
- `QuestionComposer.js` `FreddieQuestionComposer.#render` creates `freddie-question-flow` and `freddie-plan-review-panel` with `document.createElement`, not JSX (webjsx's `IntrinsicElements` covers built-in tags only), and reuses the child across renders so `setProps` drives the child's own `applyDiff`.
- `FreddieQuestionFlow.#onOptionKeyDown` implements the WAI-ARIA radio/checkbox arrow-key pattern (focus wraps at the ends; single-select also moves selection with focus). It sets the draft directly and must not go through `#choose`: `#choose` auto-advances to the next question, and arrow keys navigate within one question's options.
- `FreddieQuestionFlow.#renderDetail` keeps one element per question index in `#detailEls` and hands it back to `renderMarkdownText`; the flow re-renders on every option toggle and draft edit, and without the previous element `freddie-markdown-text` is recreated and loses its settled-render memoization.

## CSS rationale

- `QuestionComposer.css` / `PlanReviewPanel.css`: the takeover seat sits in a fixed-height, overflow-hidden conversation column, so the card is capped against the viewport and only its body scrolls, keeping header and footer actions reachable on long batches or plans. Option rows are scroll content, never the slack absorber: a shrinkable row collapses to its min-height while wrapped copy keeps its taller intrinsic height and paints outside the row box, over the title and the next row. The indicator uses `flex-start` alignment (centering drifts down a wrapped description) and re-centers against the first line box. `PlanReviewPanel` is its own module rather than sharing `ApprovalPanel`'s: the two takeovers agree on tokens and geometry, not content.
- `QuestionComposer.css` `.fieldMirror`: the never-painted height ruler stops growth at six lines (the card body is capped at 520px and still owes budget to the title, option rows and footer), so a long answer scrolls in the textarea; it is `content-box` so the cap counts TEXT lines in both variants (under `border-box` the block variant's 16px vertical padding eats two thirds of a line and the sixth arrives as an 8px sliver). Mirror and textarea share type, padding and wrapping or the box is the wrong height for the typed text.
