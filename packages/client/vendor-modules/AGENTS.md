# AGENTS.md — vendor-modules

## Rationale

- `scripts/generate-vendor.mjs` lists `zod` first in `ENTRY_SPECIFIERS` and resolves it from `packages/goal/goal`: the `@freddie/*/remote` client modules import `zod` in the browser, and a regeneration without the entry silently drops the package and breaks the page.
- `EMITTED_REWRITES` rewrites `zod/v4/locales/index.js` to export only `en`, and the walker scans the rewritten text, so no other locale file is reachable, copied, or fetched: the client only ever runs English messages (`v4/classic/external.js` calls `config(en())`), and the closure shrinks from 79 files to 28.
- `EMITTED_REWRITES` escapes every non-ASCII character in the `@shikijs/langs` `html`, `less` and `swift` grammars and in two documentation comments (`markdown-table`, `micromark-extension-gfm-autolink-literal`): the grammar characters are Unicode range endpoints inside TextMate regexes, and `\uXXXX` escaping yields a `JSON.stringify`-identical parsed grammar with no non-ASCII source. Each rewrite throws when it changes nothing, so a version bump that moves the text fails loudly instead of leaving the original behind.
- The final assertion scans the whole `vendor/` tree on disk plus `src/manifest.js`, not only the files this run wrote: the generator never deletes, so a stale file from an earlier version or a new locale file would otherwise slip through. It rejects characters matched by the generator's non-English script pattern, and rejects any file inside a `locales`, `locale` or `i18n` directory except `en` and `index`.
- Files of `LIVE_WORKSPACE_PACKAGES` are scanned for imports but never written: `src/index.js` serves those four packages live from the workspace, so a vendored copy is dead weight that drifts from source.
- `IMPORT_MAP_PROVIDED_ELSEWHERE` skips `@freddie/freddie-client-modules` and its `/client` subpath: that plugin contributes its own import-map entries, and a vendored duplicate would register a second, conflicting URL for the same specifier.
- `SPECIFIER_ALIASES` maps the unscoped `webjsx` identity, imported by `packages/client/web/src/seed.js`, onto `@freddie/webjsx` and registers both keys against the same URL right after the scoped entry, which keeps the import-map key order stable.
- Rewriting a file under an existing `<name>@<version>` directory needs the old file deleted first, because the drift check refuses to overwrite it; `serveVendor` sends pinned versions as `immutable`, so a browser that already cached the old bytes keeps them until its cache is cleared.
- `scripts/generate-vendor.mjs` runs from any cwd (paths derive from `import.meta.url`). `ENTRY_SPECIFIERS` lists only what workspace source imports directly; everything they transitively need is found by the fixed-point bare-specifier scan and gets its own import-map entry from the same traversal, so a transitive package such as `@freddie/cosmokit` (reached only through `cordis/loader`) resolves in the browser without a separate root-guessing pass.
- `resolverFor` resolves `shiki` and `@shikijs/langs` from `ui-primitives`' resolution graph and `zod` from `packages/goal/goal`, so the scan never depends on whichever copy a generic lookup would find first.
- `packageDirOf` finds a package root by the last `node_modules/<pkg>` segment, and for pnpm-workspace-linked packages (no such segment) by the nearest ancestor `package.json` whose `name` matches.
- `BARE_SIDE_IMPORT_RE` is anchored to statement start (file start, `;`, `{`, `}` or newline) so a string argument such as `updateError("import", ...)` is not read as a side-effect import.
- `CJS_EXPORT_SHIMS` rewrites the single trailing `module.exports = Anser;` of `anser` to `export default Anser;` (its `lib/index.js` has no other CJS surface); a browser import map cannot run CommonJS. It touches module-boundary syntax only; every other vendored file is copied byte-for-byte.
- `node:` specifiers never enter the copy queue; only `node:module` is mapped, to `vendor/node-module-stub.js`, which the generator writes itself (not hand-kept under `vendor/`, so regenerating cannot lose it). Its only importer is `@freddie/cordis-plugin-loader`, on a branch the browser boot never takes.
- `copyKatexAssets` copies katex's stylesheet and fonts into the same versioned vendor directory so the stylesheet's relative `url(fonts/...)` references resolve unchanged; the stylesheet is exposed as a `cssLinks` `<link>` row because CSS is never reachable through the import map.
- `src/index.js` `serveVendor` sends `no-cache` for `@freddie/` workspace packages (a local edit does not bump the version) and for unversioned files such as `node-module-stub.js`; every other path carries a pinned version and is `immutable`, so a cold boot does not revalidate about 200 modules.
- `renderProcessShim` is a minimal `process` stand-in, not a Node polyfill: `@freddie/cordis-plugin-loader` reads `process.env.CORDIS_SHARED`, `process.execArgv` and `process.versions.node` at module or field-initializer level even on the browser path. With no bundler `define` step, `FREDDIE_CLIENT_*` values (read as `process.env.FREDDIE_CLIENT_*` by `ui-brand-official`, `ui-renderer` `DocumentTitle`, `ui-sidebar` `SidebarRoot`) reach the page through this shim's `env`.
- The remaining Latin-script residue in the vendored copies is third-party data with no safe rewrite: the `scriptData` table and its fallback class names in `katex.mjs`, the CSS keyword names in the `css` and `less` grammars, and the emoji shortcodes in the `mdx` grammar. Changing them would change math rendering and syntax highlighting.
