# client-connection

## Rationale

- `PRIVILEGED_METHODS` (`src/index.js`): pinned to loopback even when `trustedHosts` is set. `trustedHosts` is a DNS-rebinding fence, not authentication, so anything that reads or changes deployment configuration, secrets, the host filesystem or host processes stays loopback-only until authentication exists. Classify every new Typert host endpoint here; nothing catches a miss.
- `pinnedFetchHandler` sits before `channelDispatch` because the Typert gateway's interceptor claims `/api` endpoints before any fallback. `canonicalMethodName` folds `settings/describe` and `settings.describe` into one spelling. The pin is Host-header based: a reverse proxy forwarding a client-chosen Host unchanged bypasses it.
- `src/index.js` imports `@freddie/freddie-host-apiproxy` for `toFetchHandler`, which also activates the `webServer` Context merge.
- `agentPreset.read|copy|openDocument|remove`: recon, roster rearrangement, host-desktop access. `agentPreset.list|select` stay open: `session.create` already takes an `agentPreset` and the default deployment carries `bash` and filesystem tools, so pinning the switch would fence beside an open gate.
- `llm.discoverModels` carries a draft credential and makes the host GET a caller-chosen URL (SSRF probe); `llm.providers|models` hold ids and names only and the LAN model picker needs them. `credentials.describe` (whether an arbitrary env-var name is set, and where) and `settings.describe` (every namespace's configuration) are recon.
- `pluginManager.setDisabled` rewrites the profile's `cordis.patch.yml` and remounts host code; `pluginManager.describe` is pinned with it so one 403 tells a trusted-host browser switching is unavailable instead of offering toggles that can only fail.
- `terminal.*` is pinned whole: `create` allocates a host shell, `write` drives it, `environment` and `shells` are recon.
- `workspaceFiles.*`, `workspace.*`, `directoryPicker.*`, `host.pickDirectory|openPath|listDirectory|createDirectory` touch the host filesystem outside any session grant or drive native dialogs. `host.listDirectory|createDirectory` were once unpinned beside pinned `directoryPicker` twins, letting a trusted host browse any directory on a headless deployment.
- `dynamicCordisRunner.*` is one capability (load a package's host half into this process, then call it): `runHostHalf` and `invoke` are host code execution with no model in the loop and the bookkeeping verbs share the pipeline, so a partial pin leaves it reachable one verb over.
- `gm.*` writes `.gm/prd.yml` and `.gm/mutable*.yml` under the process cwd and `gm.transition` advances the phase machine whose gates gate everything else. `commands.execute` runs a handler from caller-supplied text; `job.kill` terminates a host process. `commands.list` stays open (descriptor catalog).
- `sessionArtifacts.share` is the only artifact verb crossing a session boundary. `sessionReferenceResolver.candidates` rows carry every visible session's id, cwd and title.
- `UNPINNED_BY_DECISION`: the session read and command verbs, `stream.next|close` and `respond` stay reachable because the browser client is that caller on a LAN deployment. Pinning `session.prompt` would (canonical spelling) also pin the legacy route a LAN client prompts through, and any caller who may prompt already runs the session's tools as this process. `subagent.*` is unpinned too. Largest residual exposure: transcripts, every session's id and cwd, and `respond` (settles a human's approval). Closing it takes authentication, not another set entry.
- `goals.*`, `messageFeedback.*`, `sessionArtifacts.list|put|deleteArtifact|checkpoints`, `pluginInventory.list`, `commands.list`, `fileReferences.list` are confined to the calling session by a caller-supplied `sessionId`, not authenticated identity: they share the residual above.
- Routes outside `/api` (`/plugins`, `/workspace`, `/styles`, `/vendor`, `/`, HMR) carry no Host, Origin or Fetch-Metadata fence: they serve buildless client source and the plugin graph and neither write nor launch. Fencing them needs an exported trusted-host predicate, not loopback-only, because LAN browsers load them.
- `isTrustedApiRequest` (`src/api-request-trust.js`) applies the Host fence to every request with no marker shortcut: a plain-HTTP browser read (images, navigations) carries neither Origin nor Fetch-Metadata, so it looks like curl while a rebound page can read the response. Host is the one header rebinding cannot forge. `sec-fetch-site: cross-site` is refused regardless of Origin, and an attached Origin must equal the request authority (opaque `null` fails).
- `isBareAuthority` / `parseAuthority` / `canonicalAuthority`: a Host header is an authority alone; userinfo, path, query or fragment parse as a different host than the one named, so they are refused. `http:` is a WHATWG special scheme, so parsing yields a non-empty hostname or throws (an authority that parsed under `http` cannot fail under `https`). `refuseMalformedTrustedHosts` (`src/index.js`) applies the rule at load, so a `trustedHosts` typo cannot authorize a hostname prefix.
- `abortWhenConnectionTearsDown` (`src/http-bridge.js`): disconnect hangs off the response; `IncomingMessage` `close` fires once the body is consumed (at once for a bodyless GET) and would abort every SSE stream after open, while `ServerResponse` `close` fires on teardown and `writableEnded` separates a normal `end()`. `drainedOrClosed`: a false `res.write` waits for `drain` (or `close`) instead of buffering a slow SSE consumer.
- `src/client/api.js`: never import the `@freddie/freddie-host-apiproxy` root from client code (it drags `bootHost`/cordis into the browser); use `./api` and `./client`.
- `freddie.client.external` lists `@freddie/freddie-values` because `packages/core/session/src/json.js` re-exports from it and the loaded session surface reaches that file; an import map has no entry for an undeclared specifier.
- `mintRpcId` (`src/client/web-api-client.js`) uses `randomUuid` (`random-uuid.js`): the base class calls `crypto.randomUUID`, absent on a plain-HTTP page from a non-loopback trusted host, so the readiness `host.describe` would throw and the connection reconnect forever.
- `ConnectionController` (`src/client/connection.js`): `describe` proves unary reachability and `onOpen` each physical stream before any frame; only then may `onConnected` fire, so its resync cannot outrun the subscribed baseline. A state sink may stop the controller synchronously, so no description is published for a dead generation and `apply` (`src/client/index.js`) drops the stale connected notification.
- `start` (`src/client/index.js`): stopping the stream loop releases ownership, else re-applying the runtime after an HMR rebuild failed with `the stream loop is already owned by another consumer`; `owned` keeps a stale stop from releasing a newer claim.
- `src/client/fixture.js` (offline world for GUI drives): `buildAlphaLog` keeps turns before `todo` because a standing plan retires at the next `turn/start` (`backscanTodos`). `TERMINAL_EXIT_STATUS` is authored beside the sample because the real presenter strips `[exit code: N]` with `parseExitStatus` (`@freddie/freddie-shell`), which the fixture does not import. `presentResult` picks the structured card by tool name (`call.card` cannot tell `read` from `edit`).
