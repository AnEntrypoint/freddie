## Rationale

- `src/client/index.js` `apply`: the chip lives in the later conversation scope, so it registers a reader in `rosterReaders`; `AgentPresetSectionController`'s `rosterChanged` callback fans reloads out to it. Copy/delete write a directory, not a setting, so no `settings/document-updated` announces them and the chip would keep a stale roster.
- `index.js` `creatorDraft`: assigned inside the conversation-scope inject and cleared on its disposer; `sectionInjected` reads it per render, so the creator button disappears while no session flow exists. It stages `'cordis'` (the self-referential creator preset) WITHOUT applying (`seat.stage(id, true)`): the still-current running session would refuse the swap and drop the stage. `sessions.list.subscribe -> seat.apply` lands it on the blank session `workspaces.startSession` produces; `introduce=true` makes the chip announce a pick made on another screen.
- `index.js`: the chip reloads on `settings/document-updated` for `AGENT_PRESET_SETTINGS_NS`, and `agent-preset/selected` is folded into the shared session row in every tab (idempotent with the initiating tab's RPC echo). A staged pick survives a reload because `load()` prefers it over the refreshed fallback.
- `seat-store.js` `load`: `current = staged ?? currentSession().agentPreset ?? fallback`. The middle term stops a late load reply from regressing the display after `apply()` consumed the stage (the chip mounts and loads only once the flow's session is current).
- `seat-store.js` `apply`: a nonblank session neither consumes nor invalidates the staged pick (it may be the session that was current when the creator flow opened), hence the early return without clearing `staged`.
- `AgentPresetLabel.js` `#maybeLoad` (and `#render` of `AgentPresetRow.js`/`AgentPresetSection.js`): the roster read starts when the shared snapshot `status === 'idle'`, never on a per-element flag; the slot renderer recreates an element whenever the store its render read changes, so a per-instance latch turned each `loading` and `ready` transition into another `agentPreset.list` call. Deployments with no presets never fetch (no session reports one).
- `AgentPresetSeat.js` `#render`: one `introText` wrapper span around the per-character spans, because the chip is a flex row with a gap and loose character spans would each pick up the gap. CSS owns the motion; `#maybeArmIntro` only arms it (deduped by `armKey`) and acknowledges via `introduced()`.
- `AgentPresetSection.js` description tooltip: `maxWidth: 360` keeps the bubble inside the settings dialog (the default half-viewport bubble spills across the app); `title: ''` on the description span stops the card body's native tooltip climbing to it, so a cut-off description shows one bubble. Tooltips/modals are self-rendering custom elements, mounted after `applyDiff` via `[data-desc-slot]`, never diffed as vdom children.
- `AgentPresetSection.js` card: the `cardMain` button IS the control (picking a preset is the common act); the action row is a sibling because nested buttons are invalid. A broken preset disables its body. The explicit `aria-label` stops screen readers reading the whole card. System presets get the read-only viewer unless broken (no readable composition); user presets get the location action even when broken (the files are where it is fixed). The custom group stays visible while empty (heading plus creator entry); status `unavailable` hides the section entirely.
- `section-store.js`: `draftBlocker` refuses an id already in the roster (a copy never overwrites); `load` drops `revealedPaths` for presets no longer listed; `confirmCopy` ends in `openLocation` because a preset is its files from then on.
- `settings-store.js`: `AgentPresetSettingsController.load` sets `writable` from the shared mirror's view, `false` when it never answers (remote browsers are process-local because settings RPCs are loopback-only), so the row stays read-only rather than offering a write the Host refuses. `INITIAL.writable` is `true` only until `load()` (an idle row renders nothing interactive). With no preset marked default (settings can name a since-deleted preset) `currentValue` falls back to the first entry. `select` re-reads the roster after a write because the Host resolves the default through the same roster the row shows. `writeDefaultPreset` returns a transport rejection as a message so the row does not silently snap back.

## CSS rationale

- `AgentPresetSeat.css` `.introIcon`: the icon's 0.15s ease-in must equal `INTRO_TEXT_DELAY_MS` (`AgentPresetSeat.js`) so the name's characters (delays set inline) start the moment it lands; every character occupies its width from the start, so nothing reflows mid-run.
- `AgentPresetSection.css` `.cardDesc`: clamped to four lines because a preset publishes its own description and one long one would stretch every card in its `1fr` grid row; the clamp is CSS-only (full text stays in the DOM for assistive tech). `.cardId` takes the free space with an auto margin because `-webkit-line-clamp` on a flex-stretched box leaves clamp height and box height disagreeing.
