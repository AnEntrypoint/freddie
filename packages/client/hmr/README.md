# @freddie/freddie-client-hmr

Hot reload for every buildless web source. Dynamic client-plugin packages swap their Loader fibers — rows that define custom elements included, since every definition goes through ui-primitives' `defineElement` registry and a re-definition takes effect on the next render ([registry note](../../../.agents/notes/implemented/architecture/2026-09-14-custom-element-hot-swap-registry.md)). A stylesheet edit publishes `css-rebuilt` with the css-manifest's new bundle rev and the browser swaps the one `/styles/app.css?rev=` link in place (load the new link, then drop the old — no navigation, no fiber swap). A change under the shell's own roots (`apps/web`, `packages/client/web`) publishes `shell-rebuilt` naming the root and the browser remounts `AppWebEntry` in the same document: it imports the shell under a fresh `/__hmr/<rev>/` prefix (its relative imports fetch fresh bytes while bare specifiers still resolve through the import map, so plugin, cordis and seed module identities are shared), disposes the live entry into the same `#root`, and runs the new one — `window`, the boot payload and `window.__FREDDIE_HMR__` survive. The seeded platform packages (`ui-slots`, `ui-primitives`) resolve through the frozen import map, so a change there still reloads the document. The web bundle mounts the row unconditionally and needs no separate HMR watcher.

The browser half subscribes to the system SSE channel (`GET /plugins/events`), exposes connection and frame-sequence health at `window.__FREDDIE_HMR__` (a journal that outlives the driver fiber across self-reloads and remounts, and whose every row is also dispatched as a `freddie:hmr` event on `window` for the GUI notice), and reloads one plugin per `rebuilt` frame through a serialized queue. `HEAD /plugins/events` returns only the stream metadata; `GET` alone joins the live broadcaster. The host sends an authoritative graph when each channel opens plus sequenced heartbeat frames while it stays open. The browser reloads the document after three missed default heartbeat intervals, and terminal recovery joins the same queue as every swap; failed, closed, or buffer-capped responses leave the broadcast set. Each rebuilt frame carries the host's updated graph row (`/plugins/<id>/~<rev>/<entry>`), which the browser applies before `invalidate` and `prefetch`, so native `import()` uses the new cache-keyed bundle URL and every sibling import under it. The remaining sequence is `registry.delete` (before the fiber: a bare fiber dispose trips the framework Loader's self-dispose branch, which would mark the entry disabled), drain the old fiber, delete `entry.fiber`, remove owned `<style data-plugin>` tags, `entry.refresh()` re-imports and re-applies, `fiber.await()` rethrows startup failures loud. A reconnect graph revision mismatch or a failed plugin reload remounts `AppWebEntry` in the document from the host's latest graph; a missing SSE frame reloads the document, since the graph published in the gap is unknown. Dependents reload through Cordis itself: a fiber's activation epoch tracks its service providers' uids, so replacing a provider fiber cascades into dependents without client-side graph analysis. The node half debounces native filesystem save bursts before scanning a dirty dynamic, shell, or static root, retains polling only for roots whose platform cannot create a native watcher, relays every `hmr/journal` row of the host HMR service (`reload`, `deferred`, `failed`) as a `host-reloaded` frame with workspace-relative plugin paths, and drops an SSE client whose pending socket buffer exceeds `maxBufferedSseBytes`; EventSource reconnects from the authoritative graph.

## Model Experience

None, as the reload driver is browser-side machinery; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Reload is coarse by design** — a fresh fiber and fresh components; React state inside the reloaded plugin is lost while the data layer (connection/runtime fibers, Session objects) is untouched. react-refresh-grade state preservation conflicts with "re-executing the bundle re-runs the factory" and is deliberately out.
- **No failure rollback** — a reload that fails remounts the shell in the document so `AppWebEntry.run` can render the boot failure page; the previous plugin fiber is not restored automatically.
- **Seeded platform packages reload the document** — `ui-slots` and `ui-primitives` are import-map entries shared by every bundle, and an import map cannot be re-pointed once a specifier has resolved; only the shell's own roots remount in place.
- **A stylesheet outside the css-manifest is invisible to the swap** — the bundle rev hashes manifest files only; a new `.css` file needs `generate-manifest` before an edit to it swaps.
