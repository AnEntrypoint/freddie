# @freddie/freddie-client-hmr

Hot reload for every buildless web source. Dynamic client-plugin packages swap their Loader fibers — rows that define custom elements included, since every definition goes through ui-primitives' `defineElement` registry and a re-definition takes effect on the next render ([registry note](../../../.agents/notes/implemented/architecture/2026-09-14-custom-element-hot-swap-registry.md)). A stylesheet edit publishes `css-rebuilt` with the css-manifest's new bundle rev and the browser swaps the one `/styles/app.css?rev=` link in place (load the new link, then drop the old — no navigation, no fiber swap). A change under the shell's own roots (`apps/web`, `packages/client/web`) publishes `shell-rebuilt` naming the root and the browser remounts `AppWebEntry` in the same document: it imports the shell under a fresh `/__hmr/<rev>/` prefix (its relative imports fetch fresh bytes while bare specifiers still resolve through the import map, so plugin, cordis and seed module identities are shared), disposes the live entry into the same `#root`, and runs the new one — `window`, the boot payload and `window.__FREDDIE_HMR__` survive. The seeded platform packages (`ui-slots`, `ui-primitives`) resolve through the frozen import map, so a change there still reloads the document. The web bundle mounts the row unconditionally and needs no separate HMR watcher.

The browser half opens the server-only WebSocket channel at `/plugins/events` (`ws:` for HTTP, `wss:` for HTTPS), exposes connection and frame-sequence health at `window.__FREDDIE_HMR__`, and reloads one plugin per `rebuilt` frame through a serialized queue. Its bounded journal survives driver replacement and shell remount; each row also dispatches a `freddie:hmr` event on `window`. Ordinary HTTP requests to the endpoint return 426 with `Upgrade: websocket`; they never hold a stream open. Browser upgrades must match the request's Host authority and must not be marked cross-site. Originless native clients remain supported. The host sends the authoritative graph on connection and sequenced heartbeat frames every `heartbeatIntervalMs` (default 15,000). The browser reloads the document after 45 seconds without a frame on an open channel or an unfinished handshake; closed channels retry after the browser driver's `reconnectIntervalMs` (default 1,000). Disposal cancels the heartbeat deadline and reconnect timer and closes the owned channel. Each rebuilt frame carries the updated graph row (`/plugins/<id>/~<rev>/<entry>`), applied before `invalidate` and `prefetch`. The reload then deletes the runtime registry entry, drains the old fiber, clears `entry.fiber`, removes owned plugin styles, refreshes the entry, and awaits startup. Dependents re-activate through Cordis provider epochs. A reconnect graph mismatch or failed plugin replacement remounts the shell; a sequence gap reloads the document because its missing graph update is unknown. Terminal recovery shares the reload queue. The host serializes each broadcast once, disables WebSocket compression, and drops closed, failed, client-writing, or buffer-capped channels. `maxBufferedEventBytes` (default 1,048,576) bounds pending bytes plus the complete next frame; reconnect starts from the authoritative graph rather than retaining a stale queue. The node half debounces native filesystem saves, polls only roots without complete native watchers, and relays host `hmr/journal` rows as `host-reloaded` frames with workspace-relative paths. WebSockets keep HMR out of the browser's per-origin HTTP/1.1 request pool ([decision](../../../.agents/notes/implemented/architecture/2026-10-06-hmr-websocket-connection-budget.md)).

## Model Experience

None, as the reload driver is browser-side machinery; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Reload is coarse by design** — a fresh fiber and fresh components; component-local state inside the reloaded plugin is lost while the data layer (connection/runtime fibers, Session objects) is untouched. Preserving component state conflicts with re-executing the plugin factory and is deliberately out.
- **No failure rollback** — a reload that fails remounts the shell in the document so `AppWebEntry.run` can render the boot failure page; the previous plugin fiber is not restored automatically.
- **Seeded platform packages reload the document** — `ui-slots` and `ui-primitives` are import-map entries shared by every bundle, and an import map cannot be re-pointed once a specifier has resolved; only the shell's own roots remount in place.
- **A stylesheet outside the css-manifest is invisible to the swap** — the bundle rev hashes manifest files only; a new `.css` file needs `generate-manifest` before an edit to it swaps.
