# AGENTS.md — sandbox

## Rationale

- `src/escalation.js` (fail-closed): the tool schema advertises every target mode because the effective mode is per-call truth; a request that cannot widen this call needs no approval (the standing policy already grants at least that access). Widening with no approval service throws; `allowed-once` is the only outcome that returns the mode, and `rejected`, `cancelled` and `unavailable` all throw. The approval `reason` is self-contained (`escalate sandbox to <mode>: <justification>`) because `approval/asked` stores it and the target mode is part of the grant identity.
- `src/roots.js`: roots are canonicalized with `realpathSync.native`, not the JavaScript realpath, which lexically collapses `..` before resolving a preceding symlink on some platforms; the native call follows the filesystem's component-by-component lookup, matching chdir/spawn and the enforcement layers this identity feeds. A failure (missing/unreadable prefix) returns the path unchanged.
- `confine` must return enforcing argv or fail closed (`SANDBOX_UNAVAILABLE`); silent unconfined passthrough is forbidden. `src/escalation.js` is shared by bash and fs tools: the ladder is checked at execution, never baked into schemas (the schema enum is `ESCALATION_TARGETS`, advertised whenever the capability confines so a session below the default keeps a lever); the ordered fail-closed approval sequence resolves before anything executes; a non-widening request never prompts.
- `src/roots.js` is the one derivation of writable roots (`workspace-write` = workspace root + `/tmp` + `os.tmpdir()`), canonicalized because Seatbelt and the fs fence compare resolved paths (`/tmp` is `/private/tmp` on darwin); bwrap and Landlock keep their own grant spellings.
- `src/index.js` `Config`: `mode` defaults to `read-only` (fail-closed). `workspaceRoot` deliberately has no schema default: `SandboxPolicyService` falls back to `process.cwd()` and resolves it absolute either way, so the stored root is always absolute however it was supplied.
- Precedence: an approved explicit mode outranks the session's last `sandbox/mode` event, which outranks the deployment default (`read-only` fail-safe). The override lives in the session log (`effective = fold(events) ?? default`), so it survives restart and sessions never share state. A session cwd is its workspace-write boundary; the configured root serves agentless calls. Filesystem identity is resolved before lexical normalization so symlink-sensitive components survive.
- `src/index.js` `Config` (local provider keys): the schema defaults every field; an empty `runnerCommand` means "not configured, use the platform chain", and `runnerFailureSignatures` without `runnerCommand` throws.
- `src/provider.js` runner selection (fail-closed): a sole candidate (darwin `seatbelt`) is selected without a probe. With several candidates the first probe not `unusable` wins.
- `src/provider.js` claimed enforcement (`STATIC_ENFORCEMENT` and probe results): bwrap's mount profile and Seatbelt's deny-file-write* profile govern every promised file effect by construction, so passing probes are `full`; the Landlock launcher's probe distinguishes full from per-ABI-partial.
- Runner selection is by platform first, probes second: chains are probed in preference order only with more than one candidate (Linux bwrap then Landlock; darwin Seatbelt is single). A probe bound of 0 would mean unbounded in Node `spawnSync`, so it must be positive and finite. Denial signatures are case-insensitive stderr substrings; runner-failure rules are exit-gated (Landlock exits 125) so a confined command that merely prints the signature is not misclassified.
