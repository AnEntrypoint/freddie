# AGENTS.md — sandbox-local

## Rationale

- `src/index.js` `static Config` is an inline schema call because the config catalog walks `static Config` statically. The schema defaults every field; an empty `runnerCommand` means "not configured, use the platform chain", and `runnerFailureSignatures` without `runnerCommand` throws.
- `src/index.js` runner selection (fail-closed): a sole candidate (`win32: ['windows-acl']`) is selected without a probe, and its execution-time refusal still fails closed through the `windows-acl-run:` stderr signature and exit 127. With several candidates the first probe not `unusable` wins.
- `src/index.js` claimed enforcement (`STATIC_ENFORCEMENT` and probe results): bwrap's mount profile and Seatbelt's deny-file-write* profile govern every promised file effect by construction, so passing probes are `full`; the Landlock launcher's probe distinguishes full from per-ABI-partial; `windows-acl` is always `partial` because WRITE_RESTRICTED needs Everyone in both restricting lists for process initialization: an external object granting Everyone write stays writable and NTFS hard links can alias a granted workspace file to a path outside it. The backend enforces the remaining ACL-addressable surface but must not advertise the absolute promise.
- `src/index.js` denial signatures (`windows-acl` entry): pwsh/.NET "Access to the path '...' is denied.", cmd "Access is denied.", node EACCES "permission denied". The windows-acl runner's failure exit is its own `RUNNER_FAILURE_EXIT` contract, distinct from Landlock's 125.
- `src/index.js` ACL grants: temp grants are revoked with the provider (`revokeAclGrants`), so a clean shutdown leaves no temp ACEs. Workspace ACEs deliberately stand (the reuse cache; an unclean shutdown leaves them for the next provision's exact-ACE skip). On a workspace-grant failure, disposing the grant only frees the SID; a standing ACE (apply succeeded before a post-apply throw) is the intended end state, so nothing is revoked.
- Runner selection is by platform first, probes second: chains are probed in preference order only with more than one candidate (Linux bwrap then Landlock; darwin Seatbelt; win32 windows-acl are single). A probe bound of 0 would mean unbounded in Node `spawnSync`, so it must be positive and finite. Denial signatures are case-insensitive stderr substrings; runner-failure rules are exit-gated (windows-acl exits 127 with `windows-acl-run:`; Landlock exits 125) so a confined command that merely prints the signature is not misclassified. Keep the Landlock tuple aligned with `examples/acp-agent/partial-landlock.cordis.snapshot.yml`.
- windows-acl write grants: the workspace SID is per workspace (derived from the canonical path) and its ACE stays standing as the cross-session reuse cache; every live session gets a RANDOM private temp directory with its own capability revoked on dispose; a fresh provider always picks a new path so crash residue is inert. Provisioning is fail-closed and revokes half-materialized temp grants; cleanup failures are reported, not thrown, so cordis teardown proceeds. The rung reports partial enforcement (WRITE_RESTRICTED keeps Everyone; NTFS hard links alias one file object). Runner argv defaults to the built `lib/runner.js`, else source via tsx.
