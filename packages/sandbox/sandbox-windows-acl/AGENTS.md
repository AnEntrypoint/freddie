# AGENTS.md — sandbox-windows-acl

## Rationale

- `src/win32-abi.js` `GRANT_MASK`: `FILE_GENERIC_WRITE` minus `READ_CONTROL` plus `DELETE` and `FILE_DELETE_CHILD` (displays as "Modify"), so confined delete/rename/git work inside granted trees. `WRITE_DAC` and `WRITE_OWNER` stay OUT deliberately: they would let the child take ownership or rewrite DACLs and escape the allowlist (the security boundary). `SE_GROUP_LOGON_ID` (bit 31 set) and other high-bit flags are compared with `>>> 0` because JS bitwise ops are signed 32-bit.
- `src/win32-abi.js` lock files open shared read/write but NOT delete: a deletable lock file could be removed and recreated under the holder, letting two processes hold "the same" lock on different files. `INHERITED_ACE` marks ACEs read back from a DACL that are not this module's explicit edits.
- `src/acl.js`: grants are read-merge-write under the per-path `withPathLock`; the descriptor block (which contains `oldAcl`) is freed before applying and only the descriptor may be freed (freeing the ACL pointer corrupts the heap). `hasExactGrant` skips the apply when the identical ACE exists (re-propagation is eager: minutes on large workspaces); any implausible ACL header/size reads as "no exact grant" and falls back to the merge path. Cleanup failures on error paths are best-effort so they never mask the original error.
- `src/index.js` `manageDacls: false` means the sandbox seam's grant already materialized the ACEs and this instance must neither add nor remove any. When it owns the DACLs, `writableDirs` ACEs are STANDING (per-workspace reuse cache; `dispose()` never revokes them or the next provision re-propagates the tree) and the temp ACE is REVOCABLE (removed before the private directory is deleted; the ambient temp root is never granted). The temp grant is recorded in `grantedPaths` BEFORE granting because `grantWrite` can throw after a successful apply and the fail-closed catch must still revoke it (revoking an ungranted path is a no-op merge). Init failure cleanup never leaves a revocable grant or SID allocation behind; standing workspace ACEs are not revoked.
- `src/index.js` restricted-token default DACL: it names only the user's ambient SIDs, none of the restricting SIDs, so new objects the confined process creates (anonymous pipes, sync objects) would fail the write pass-2 check (`ERROR_ACCESS_DENIED`/EPERM) and break piped-stdio grandchild spawns. `setTokenDefaultDaclGrant` merges a full-access ACE for a restricting SID: the PRIVATE temp SID when present (so default-DACL objects in one session's temp tree cannot acquire the shared workspace capability), else the workspace SID, else Everyone under read-only. New-object creation stays gated by the parent object's DACL. `TOKEN_DEFAULT_DACL` is exactly one pointer and `SetTokenInformation` copies the ACL.
- `src/index.js` spawn wait: `waitForExit` is deliberately NOT started at spawn; `WaitForSingleObject` blocks the thread and would starve the pipe drains while the child runs (pipe-buffer deadlock). Drains resolve after the child closes its pipe ends, so the wait then returns immediately.
- `src/runner.js`: both `--workspace` and `--temp` are validated in both modes so a provider passing a bogus root fails at the runner boundary, never mid-child. The runner ignores its own CTRL+C (the confined child on the same console handles its own) so it survives to revoke grants and mirror the exit code. Cleanup failures are reported on stderr and never mask the child's exit code. Exit codes mirror full-width uint32 (verified on Windows 11 build 26200, Node 24: NTSTATUS `0xC0000005` reads back as 3221225477 through `GetExitCodeProcess`, `process.exitCode` and `spawnSync`), so no re-mapping.
- `src/spawn.js`: quoting doubles a trailing backslash run so it cannot escape the closing quote. Child pipe ends must be inheritable; `bInheritHandles=1` is required for redirection; the child is created `CREATE_SUSPENDED` so job assignment precedes any of its code, with no other creation flags (suspended/no-window variants are unusable under the restriction). If the child was created suspended but is not in the kill-on-close job, failure paths `TerminateProcess` first (else it hangs suspended forever); a `ResumeThread` failure closes the job (kill-on-close). The host closes its copies of the child's pipe ends so `ReadFile` sees EOF at exit; the failure path captures `GetLastError` before any `CloseHandle`. Drains back off with `setTimeout(1)`, not `setImmediate` (which would busy-poll). Un-inheriting the host-side handles is best-effort hygiene and deliberately unchecked.
- `src/token.js`: the TokenGroups/TokenDefaultDacl size probe is expected to fail with `ERROR_INSUFFICIENT_BUFFER`.
- Mechanism mirrors github.com/huoyaoyuan/windows-acl-restrict-poc @ 10e4dfb: a WRITE_RESTRICTED token whose restricting SIDs include distinct workspace and temp write SIDs; the intersection check also inherits ambient write ACEs of the keep-alive SIDs. Unlike the POC every failed Win32 call throws `Win32Error` (API name + exact code) and a child is never spawned unrestricted. Boundaries: writes are restricted; reads, network, and process visibility are not; console isolation is unavailable (CREATE_NO_WINDOW/CREATE_NEW_CONSOLE children die with STATUS_DLL_INIT_FAILED 0xC0000142) so children share the host console; writable directories must be caller-owned (owner-implicit WRITE_DAC).
- Restricting lists (verified Win11 26200): read-only [logon SID, EVERYONE]; workspace-write adds the workspace SID and optional temp SID. Logon SID + Everyone are required (early DLL init and CNG fail without them). Authenticated Users is absent from both lists (closes the C:\ root tree escape; WMI/CIM unavailable, 0x80041003); INTERACTIVE/LOCAL are absent (closes Public-tree writes). S-1-2-1 is excluded: the POC's `WinLocalLogonSid` creation fails (87) and `WinConsoleLogonSid` still dies with 0xC0000142. Under read-only a standing grant ACE from an earlier workspace-write stays inert because no write SID is in the restricting list.
- The token default DACL gets a full-access ACE for a restricting SID (write SID under workspace-write, Everyone under read-only), otherwise new anonymous pipes fail pass-2 at creation (spawn EPERM). GRANT_MASK excludes WRITE_DAC/WRITE_OWNER so the child cannot retake ownership. Grants are idempotent: an exact existing ACE skips `SetNamedSecurityInfoW`, which would otherwise re-propagate across the whole tree (minutes on large workspaces). Every read-merge-write of a DACL runs under a per-path exclusive `LockFileEx` lock (lock files: `<GetTempPathW()>\freddie-acl-locks\<first 16 hex of sha256(lowercased path)>.lock`, opened without FILE_SHARE_DELETE). Free only the security descriptor, never the ACL pointer inside it (heap corruption); ACE SIDs are inline after the 4-byte mask.
- koffi notes: 3.1.1 crashes on a NULL OVERLAPPED so a zeroed one is passed; an explicit environment block trips ERROR_INVALID_PARAMETER in CreateProcessAsUserW, so the runner rewrites TMP/TEMP in its own environment and the child inherits; Node clears stdio inheritability so raw spawns re-enable the inherit bit and pass std handles explicitly (the child starts suspended and is assigned to a kill-on-close job); pipes drain by `PeekNamedPipe` polling and exit is awaited only after both drains to avoid the pipe-buffer deadlock. ABI constants and struct layouts are pinned against MinGW headers by `verify/abi-probe.cpp` (regenerate: `g++ -std=c++20 -municode -O2 -o abi-probe.exe abi-probe.cpp -ladvapi32`); struct sizes are asserted at load. Argument quoting follows CommandLineToArgvW (double backslashes before quotes, including the closing quote).
- Runner argv contract: `[node, runner.js, --workspace <dir>, --temp <dir>, --mode <read-only|workspace-write>, [--write-sid S-1-4-.. --temp-write-sid S-1-4-..], --, argv...]`. With both SID flags the caller (the seam) owns grants (`manageDacls: false`); without them (standalone) `--temp` is a root and the runner creates and removes a random private child. Failures print `windows-acl-run: <detail>` and exit 127. Renaming a workspace derives a new SID and leaves old ACEs as inert residue. Temp directories must not sit inside the workspace or overlap a writable directory (`path-boundary.js`).
