## Rationale

- `src/index.js` host-exit sweeps: a termination failure for one target is swallowed because host exit cannot await or report it, and one process or terminal must not prevent final termination of the others.
- `src/index.js` `disposeManagedProcesses`: terminates with escalation, then awaits whole-tree exit (`waitForExit`), not just the direct child's settlement, so a TERM-trapping descendant cannot outlive the fiber; both sets stay authoritative during the waits so a shorter process-level exit bound can still force-kill them. Spawn-failure rejections already settled and left `live`. Ownership is released (`live.delete`) only when the whole tree is gone for the same reason; with no survivor `waitForExit` resolves immediately after settlement.
- `src/index.js` PATH resolution: a failing candidate falls through to the next one and only the final miss produces one stable error.
- `src/index.js` `spawnTerminal` and `src/terminal.js` `write`/`resize`/`inspectForeground`: local PTY work (node-pty) is synchronous, but the provider seam returns promises so remote transports fit and invalid viewports reject consistently; the `async` keeps rejection semantics (hence the `require-await` lint pragmas).
- `src/spawn.js` `OutputCollector`: when over cap a whole head chunk is dropped (length is at least 1), otherwise the head is trimmed so the retained window is byte-exact at the cap; a diagnostic tail (an LSP server's stderr) must hold the last `maxBytes` regardless of chunking.
- `src/spawn.js` spill file (security): random suffix, exclusive `wx` create (fails on any existing path including symlinks) and owner-only mode defeat spill-path prediction and symlink planting in shared tmp dirs. A failed close retains the descriptor so finalize can retry; a failed unlink leaves at most `maxSpillBytes`, never an unbounded file; a delayed writeback failure keeps the in-memory result but stops advertising the file.
- `src/spawn.js` `killGroup`/`taskkillProcessTree`: outcomes are deliberately unchecked; an already-absent tree (taskkill status 128), exit races and a missing taskkill binary (`spawnSync` reports, never throws) are as tolerable as `ESRCH` for a POSIX group signal.
- `src/spawn.js` `detached` is set only off win32: it gives teardown a tree root on POSIX (its own process group); Windows terminates by root pid through `taskkill /T`. A failed spawn has `SPAWN_FAILED_PID` so all signalling is a no-op.
- `src/spawn.js` liveness: Windows has no group-liveness probe, so the direct child's exit is the observable boundary (`taskkill /T` already took the tree). On Linux a group of only unreaped zombies still answers `kill(0)` but can run nothing and cannot be signalled into quiescence, so members are inspected only after direct-child settlement to keep live polls a single syscall.
- `src/spawn.js` escalation: `kill(sig)` is the tier primitive (not on the handle; `terminate()` is the only consumer-facing verb) and guards on tree liveness, not outcome settlement, because a TERM-trapping helper can outlive the settled leader and must stay signalable while a fully dead tree (possible pid reuse) must not be re-signalled. Tree exit is observed from the first tier on even when inherited pipes delay `done`. The SIGKILL `graceTimer` survives direct-child settlement (cleanup deliberately does not clear it; `kill()` re-probes liveness) and stays ref'd: a parent exiting before it fires would orphan a trapped survivor. It self-bounds at `graceMs`.
- `src/spawn.js` abort and stdin: the caller owns timeout classification, this layer only reacts to abort. Batch stdin is written and closed up front and its errors (EPIPE) are ignored (`ignoreStdinWriteError`) because exit and captured output are authoritative.
- `src/spawn.js` stream close: only harness-collected pipes are force-destroyed at the drain boundary (a `pipe`-mode stream belongs to the caller). A surviving descendant that inherited a pipe cannot hold the outcome open: after `exit` the same bounded grace that governs kills bounds the close wait. A spawn `error` has no meaningful close outcome.
- `src/terminal.js` Windows SIGINT: there is no process-group signalling, so a `\x03` input write is the Ctrl-C path (conhost turns it into a console-wide `CTRL_C` event); node-pty's signal kills throw on Windows, so no signal reaches the inspector.
- `src/terminal.js` teardown swallows: exact-identity signalling contains both exit races and PID reuse; without a captured identity node-pty is the only root kill primitive; a same-tick exit during a signal counts as success; a failed final process-table scan preserves already-captured identities; the exit callback is authoritative for top-level TERM/KILL.
- `src/terminal.js` `descendants`: new members are adopted only while the numeric root pid still carries the spawned shell's start identity, so a recycled pid's tree and session cannot donate an unrelated process's children; adopted members keep their own start identities, rechecked on every signal.
- `src/terminal.js` `stopShellWindows`/`settleExitIfGone`: node-pty's Windows `kill(signal)` throws and its bare `kill()` delegates to a console-list agent that fails without a parent console, so `taskkill` tree escalation (fenced on the shell's start identity, bare kill on an identity miss) is the teardown path. That termination also does not reliably fire node-pty's exit notification, so tiers verify the shell's absence through the inspector, and a verified absence with no exit event is itself the outcome (otherwise `done` would never settle).
- `src/windows-inspector.js` koffi structs mirror `tlhelp32.h` (`PROCESSENTRY32W`) and `minwinbase.h` (`FILETIME`); the `568`-byte size check pins the x64 layout. `taskkill` outcome is unchecked for the same reasons as in `spawn.js`.
- Inspector identities pair `pid` with creation/start identity; liveness and signalling must recheck both. Tree listings place children before their parent. An unreadable Windows process state is a detector miss, never authority to signal a reused PID. `terminateForHostExit` remains local-only synchronous cleanup.
