## Rationale

- `src/index.js` `childEnvironment`: the subprocess provider supplies its own scrubbed ambient base; these entries are deliberate terminal-specific overrides layered after it.
- `src/index.js` pwsh dialect: pwsh ignores `PS1`/`PROMPT_COMMAND`, so its prompt is installed by the startup bootstrap; `NO_COLOR` keeps the renderer quiet.
- `src/index.js` bash `PROMPT_COMMAND`: re-asserts `PS1` after the marker because bash runs `PROMPT_COMMAND` before rendering each prompt, so a command that overwrote the variable cannot survive to the next prompt and prompt readiness keeps working.
- `src/index.js` sandbox confinement: `mode: policy.mode` is restated because object spread does not preserve the discriminant's narrowed type.
- `src/index.js` `startupSession` pwsh path: the prompt function is written through the session and the first marker prompt is awaited (the same readiness contract as bash initialize). The first send also pins UTF-8 output (shared pwsh-local preamble) because the session decodes PTY bytes as UTF-8 and an unpinned console writes its host code page for non-ASCII. The banner-to-prompt gap can outlast the silence bound, so the wait loops over follow-up sends until the controlled prompt is visible (viewport or retained scrollback), bounded by the send deadline.
- `src/session.js` `acceptsStdinWait`: the same foreground group may still expose the wait that existed before `terminal.write`, so every poll is observed; a departure before the exact-settlement threshold still makes a later return to that wait post-write evidence.
- `src/session.js` pre-write inspection failure: while cancellation owns the slot the slot must not be released, because `interruptOnce`'s in-flight foreground signal could land on a successor's foreground group. The interrupt path's post-signal tail resumes polling, whose guarded catch propagates a persistent failure. A retained settled operation implies that same in-flight interrupt, so the guard admits only an unsettled active send.
- `src/session.js` after awaited provider work: `this.closing` and `this.active` are re-checked because closing can race the awaited provider write or inspection even though static analysis sees only local assignments.
- `src/session.js` local listeners: they are an optional observation path; output processing and terminal teardown continue when an observer fails.
- `src/session.js` prompt handling: bash can print `PROMPT_COMMAND` before the kernel publishes its return to the foreground process group, so the marker is retained and polling is the authority that accepts it only after bash owns the foreground. An interactive child also inherits `PROMPT_COMMAND`, so silence (`idleSilenceMs` plus `handoffGraceMs` once a prompt was seen) remains the bound on waiting for shell ownership; a child marker must not suppress readiness until the absolute timeout.
- `src/session.js` `closeOnce`: readiness polling stops but the active operation is retained so teardown settles it as `session_exit`; an in-flight send is never mis-settled as `stdin_read`/`inferred_idle`/timeout during the grace period.
