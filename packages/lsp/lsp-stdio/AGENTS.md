# AGENTS.md — lsp-stdio

## Rationale

- `src/connection.js` spawn: stdin/stdout are piped protocol streams framed here; stderr is a collected bounded tail (no spill). The spawn seam merges explicit config `env` after its ambient scrub, so a configured credential or `FREDDIE_*` fact reaches the child deliberately.
- `src/connection.js` failure model: a close records `closeReason` so later requests reject immediately instead of hanging; a spawn-level failure never emits close, so the rejection is both the fatal cause and the close boundary; a child-stdin error (server closed fd 0 while alive) is fatal so pending requests reject at once; `write()` records sync or callback failures on the connection and rejects all pending requests, so its call sites only consume the promise (`.catch(() => {})`), including for a caller that stopped awaiting and `$/cancelRequest` (best-effort). A framing/JSON failure corrupts the stream irrecoverably: fail the instance and `terminate()` the group (SIGTERM, then SIGKILL after the grace) so helpers do not outlive the leader. Server notifications are ignored (MVP host).
- `src/host.js` open item (`lsp-source-replacement`): revisit stable-handle identity only if a real query observes replacement between canonical containment and the provider opening the stream.
- `src/index.js` setup: an async plugin callback must observe its own disposal before Cordis runs effect cleanup (unload waits on it), so the fiber's disposal aborts `setupAbort`. All server-local settings resolve before registration so a bad later command cannot publish an earlier provider. Timers must be positive (`deadline()` treats `<= 0` as the no-timeout sentinel, so a server ignoring shutdown would hang disposal); byte caps must be positive (`slice(-0)` keeps everything, `maxMessageBytes: 0` makes every response fatal). Teardown removes every route before process teardown so no query enters a draining provider.
- `src/index.js` query path: an already-aborted signal is honored before provider I/O (never starts a server); the document is read inside the workspace queue but before spawning (queued query sees current bytes; an invalid source never leaves an idle pooled process); disposal may have snapshotted the instance map during host I/O, so `assertActive` re-checks before the synchronous get-or-create. A transport failure (child died idle or failed the next write) replaces the transport once and retries transparently because queries are read-only; a dead slot is disposed before eviction and only evicted if still current. The queue tail follows the actual prior work and never rejects, so aborting callers do not deserialize the queue.
- `src/instance.js` queue: a query serializes behind prior work but observes abort DURING the wait (a hung earlier query must not block a later tool's timeout); the tail tracks `this.queue`, not the abortable view. A handshake rejection is pre-caught (queries attach the real handler); a failed or aborted handshake tears the instance down so a poisoned `ready` cannot fail every later query for the workspace. `initialize` sends `processId: null` (the server may live in another PID namespace or machine and would monitor an unrelated process); an omitted position encoding defaults to utf-16 and anything else is rejected.
- `src/instance.js` document lifecycle: a canceled backpressured write or failed stdin makes the stream unusable before `didClose` can arm, so it tears down (the pool evicts). `didClose` is skipped on a dead/disposed instance (it would race teardown and overlap the next document lifecycle); a close-write failure keeps the settled outcome but invalidates the instance. `findReferences` always sets `includeDeclaration: true`. On abort, `$/cancelRequest` is followed by a bounded wait for the server to honor it, then the instance terminates so nothing outlives the query. The workspace URI is preserved from the fs provider (it owns URI syntax for the execution platform) instead of reparsing `spec.cwd`.
- `src/instance.js` server requests: `workspace/configuration` answers every item with the one static config; lifecycle bookkeeping requests get `null`; `workspace/applyEdit` is rejected (this host never applies edits or runs commands). Graceful shutdown failure or timeout is ignored because `forceTerminate` process-tree cleanup is authoritative.
- Advertised client capabilities: UTF-16 positions only (any other negotiated encoding is a protocol error), workspace folders/configuration, markdown/plaintext hover, link support; no dynamic registration. `workspace/applyEdit` is rejected (the host never applies edits). `textDocumentSync` legacy enum implies open/close for Full/Incremental; the options form needs explicit `openClose: true` because omitted defaults to false.
- A query abort sends `$/cancelRequest` and grants a bounded grace; a server that does not settle is torn down so the request cannot overlap the next queued query's document lifecycle. Teardown awaits are unbounded on purpose: the seam already committed to SIGKILL, so quiescence is the postcondition.
- Framing bounds header and total message size so a hostile server cannot exhaust memory.
