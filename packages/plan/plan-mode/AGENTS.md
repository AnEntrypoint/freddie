# AGENTS.md — plan-mode

## Rationale

- `src/index.js` pre-step listener: `agent/pre-step` runs outside `Session.append` publication, so it can append the log-only `plan/mode` event inside an open turn without re-entering the session. A failed append stays pending for a later accepted in-turn pre-step; policy cannot block the step. With no open turn the selection commits immediately, and the pending intent is deleted only after `append` succeeds so a failed durable write stays retryable.
- `src/index.js` `plan` projection: a pure fold serving `{active, wanted, running}`. `command/run` records the logged `/plan` selection, its paired `command/done` keeps only successful ones, and `plan/mode` records and clears it, so pending state is a pure replay quantity (restarts, other tabs and cold reads recover it from the log). The unit and the `/plan` command are `ctx.inject` children that activate only when a projection/command registry is composed (headless assemblies unaffected).
- `src/index.js` `/plan off` while an exit awaits the next pre-step repeats the queued wording; only a truly inactive session reads "already inactive".
- `src/index.js` plan review (`EXIT_PLAN_MODE` tool): the `plan-review` intent is presentation only (a capable UI renders a review decision; either way the answer is one of the labels). A dismissed review (`ASK_CANCELLED`) gets its own message because the generic channel message names `ask_user_question`, which the model never called; aborts keep their own message. A review outliving the plugin fiber fails (`disposed`) because an approved selection could never be appended without the pre-step listener. On approval, plan guidance persists for the rest of the tool batch and the silent selection appends at the next accepted in-turn pre-step, before request assembly.
