# AGENTS.md — client

## Rationale

- `src/api.js` `cwd` is resolved absolute before the handshake: the child spawns relative to THIS process's cwd but resolves the wire cwd again inside the child, so a relative value would double-resolve (`worker` becomes `worker/worker`). Notification events are validated at the wire boundary (`validatedSessionEvent`) so a malformed runtime surfaces as a protocol error, not type-invalid data; only `assistant/message` is read into, so only it must carry kind-tagged content blocks.
- `src/client.js` failure model: unsubscribing drops the queue by contract, while a runtime-death `fail()` keeps it so delivered notifications stay drainable. A spawn failure destroys pipes without an input `end`, so pending requests are failed explicitly. Writes racing the runtime's death EPIPE on stdin; the exit edge is the real signal, so the stdin stream error is only non-fatal (the race timing is not deterministically reproducible). Transport `close()` happens once all stdio settled (stdout `end` already drained every tail frame). A dead runtime fails requests with process context (exit code + stderr tail) instead of writing into a destroyed pipe. Request timeouts abort through an `AbortController` so the transport drops its pending entry (no per-call retention against a hung method; server-side work still runs to close). A failed shutdown request is diagnostic only: the dispose ladder is the authoritative teardown.
- `src/dispose.js` ladder: close stdin and allow a cooperative flush; on POSIX `SIGTERM` (Windows signals all force-terminate); then force-kill with a bounded exit wait. Grace timers are `unref`'d so they never hold the parent loop alive.
- `HarnessClient` runs outside any harness context, so it spawns directly instead of through `freddie-subprocess` (the seam's documented exception for SDK-managed transports). Its private teardown ladder is stdin EOF, SIGTERM, SIGKILL, resolving only after actual exit; on Windows it skips to forced termination because Node maps both signals to `TerminateProcess`.
- No wire-level cancel exists: a timed-out request keeps running server-side until the runtime closes. `HarnessClient.close` is permanent; a failed handshake replaces the client with a fresh instance.
- A throwing subscription filter fails only that subscription, never siblings or the read loop. Session subscriptions follow descendants discovered from `subagent.started` edges client-side.
- Mirrors the Python SDK's `HarnessClient`/`DeepSeekHarness` shapes (this checkout carries no `python/`).
