# AGENTS.md — mcp-client

## Rationale

- `src/connection.js` `GENERATION_CLOSE_TIMEOUT_MS`: the SDK stdio transport owns two 2 s termination graces; one more second waits for the process-close event that proves the old generation is gone. A timeout fails closed rather than overlapping children.
- `src/connection.js` supervisor: the initial sync throws on registration conflict only when `failOnStartupError` is set (re-syncs and reconnects always contain conflicts); the `syncChain` tail survives a failed sync (the enqueuer reports); a connection up longer than `maxDelayMs` (the stability window) ended the previous outage and resets the attempt budget; give-up disposal is enqueued on `syncChain` so it cannot race an in-flight sync's phase-2 swap; the reconnect timer is `unref`'d; the tool-list-changed handler is registered before connect so a change during initial sync queues behind it; a failed re-sync keeps serving the last good list; disposal clears current ownership before closing, so only a live supervisor logs attempt failures; dispose awaits both `settling` and `syncChain` so `disposers` is final.
- `src/connection.js` `ready`: settles when the first attempt finishes, success or not, and reports the real error; `settling.then` is a microtask while stdio `onclose` is a macrotask, so a server crashing after a successful initial sync cannot flip `client` to `undefined` first. `generation.close()` failures are ignored (transport already gone).
- `src/index.js` load order: reconnect config is resolved first (fail loud, including programmatic construction that bypassed Schemastery), then the `serverName` namespace is reserved (a duplicate fails THIS instance and leaves the earlier one intact); the async entry blocks activation on the first connection + discovery so tools exist when the fiber activates, and rejects the fiber only under `failOnStartupError`. The entry stays explicitly `async` (Cordis treats a prototype-bearing ordinary function as a constructor).
- `src/tools.js` sync is two-phase: fetch/build the next generation without touching the registry, then swap. A registration conflict on an `mcp__<serverName>__` name means a foreign registration occupies the namespace: roll back so the model sees the full generation or none.
- `src/tools.js` call path: model arguments may be any JSON value when the model misbehaves, so non-objects fall back to `{}` and the MCP server returns a specific missing-param error; a legacy `toolResult` shape is normalized to content; the SDK's `any[]` content is a trust boundary validated by `extractText`; MCP `isError` throws so `ToolRuntime` produces an error result. Image decode and admission helpers always throw `Error`.
- Tool identity is `(serverName, rawName)`; public name is `mcp__<serverName>__<rawName>`, normalized to DeepSeek function-name limits (64 chars, `[A-Za-z0-9_-]`) with a 12-hex SHA-256 suffix appended only when normalization is lossy. The raw name is the only thing sent on the wire; the public name is never parsed back.
- Tool sync is two-phase: fetch the whole next generation first (any failure leaves the previous generation registered), then swap. A registry conflict in the swap rolls back to zero tools for that server.
- Calls own the raw `tools/call` request (no SDK pre-validation of output schema) and list without touching the SDK per-page output-validator cache. `client.request` still needs a permissive zod schema because the SDK parses internally.
- Connection supervisor: one outage shares one attempt budget with doubling delay up to `maxDelayMs`; a connection surviving the stability window closes the outage. Exhaustion unregisters tools; only disposal (including HMR) revives. Every `syncTools` call is serialized so dispose-previous/register-next swaps never interleave.
- The plugin entry stays explicitly `async`: Cordis treats a prototype-bearing ordinary function as a constructor whose returned Promise is not startup work.
- Stdio transport env reuses the subprocess seam's credential scrub; the MCP SDK owns the actual spawn.
- MCP content decoding is a network trust boundary: required spec fields (mimeType, text) are guarded with fallbacks; image blocks decode only canonical RFC 4648 base64 and a raster MIME set, else the whole result projects images as text.
- `src/connection.js` `jscpd:ignore` wraps delay validation that parallels llm retry-policy and is not extractable.
