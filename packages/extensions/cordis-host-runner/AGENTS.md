# @freddie/freddie-cordis-host-runner

## Rationale

- `guard.js` `denyContext` and the ctx facade are twins of the browser half's guard (`@freddie/freddie-cordis-client-runner`, `CTX_VERBS`): the rule is "a service must never hand sandboxed code a Context", and each half tests against the Context class of its own face. Preserve the separate host and browser Context ownership at these security boundaries.
- The facade forwards verbs lazily (`ctx[verb]` read only when called); timer mixins additionally require the `timer` Service declaration before Cordis resolves them. It is not the real ctx: writes are rejected so package code cannot stash state on a throwaway object. `in` reflects the facade API plus declared services (live or not) without resolving or wrapping.
- `sandbox.js`: fresh vm contexts lack `btoa`/`atob`/`TextEncoder`/`TextDecoder` (and `Buffer`); the sandbox provides host closures over `Buffer`, never `Buffer` itself. The TypeScript-annotation heuristic in `parseErrorMessage` looks only at the offending line, so an ` as ` inside a description string does not produce a misleading remove-annotations message. A stubbed vm (browser worker) refuses `Script` itself; the compile gate's error is then the only context.
- `guard.js`: VM-realm schemas and canonical values are rebuilt as host objects (JSON round trip on tool `execute` and `harness.handle` results) so non-JSON output fails that call instead of poisoning the session log. The tool-registry facade's `get` returns a name/description/parameters view, never the live `ToolDefinition`, because its `execute` would bypass `ToolRuntime.execute` (policy, guards, normalization). The `inject` service gate reads the name-keyed map cordis resolves on the fiber before `apply` (array and `{required, optional}` forms alike), which is what lets cordis park a half whose provider disappears.
- `sandbox.js`: not containment (host-realm helper functions remain an escape route); `vmTimeoutMs` bounds only the synchronous portion. Parse gate is `new Function` (works without a real `node:vm`); `vm.Script` only supplies the source-line-and-caret prelude. `new.target` parses in a function body but not at the vm top level (accepted); a page CSP without `unsafe-eval` throws unwrapped `EvalError`. The browser half never reaches this module.
- `lifecycle.js`: a host half settles as a child fiber of the `cordis-dynamic` group and is disposed before a startup failure rethrows; a settled-but-inactive fiber waits on its declared `inject` services that do not exist yet. Stop is an ordinary awaited `fiber.dispose()`.
- `typert.host.js` / `typert.remote-client.js` are hand-owned and imported only as modules (package `exports`); no generator or comment-parsing reader exists.
- `invariant.js`: no runtime invariant; the registry is process memory with no event stream, and its one relation (running definition owns a settled host-half fiber and handler table) is established and unwound inside single awaited verbs.
