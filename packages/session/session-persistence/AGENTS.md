# AGENTS.md — session-persistence

## Rationale

- `src/index.js` `SessionPersistence` is the abstract Service Definition. Its abstract surface, each documented by the JSDoc block above its slot, in order: `locate(meta)`, readonly `supportsRawArtifacts` (a backend declaring `true` must override `readRaw`), `create(meta)`, `append(id, events)`, `load(id)` (documented as the resume preparation), `inspect(id, signal)`, `readFrom(id, fromSeq, signal)`, `list(signal)`, `listSnapshots(signal)`. The backend-agnostic write-path orchestration first-party backends compose is `PersistenceCoordinator` (re-exported).
- `src/coordinator.js` `create`: metadata is snapshotted before queueing so caller mutation cannot diverge key and header; a tracked, preparing or persisted id (in ANY scope, since load/resume identify by id alone) rejects creation; creation is lazy (no artifact until the first append); the method is `async` so synchronous failures reject rather than throw.
- `src/coordinator.js` `append`: the whole batch is validated and deep-snapshotted in one traversal BEFORE waiting on the per-session chain (a check followed by `structuredClone` would reread accessors and could sanitize an exotic value into a valid-looking record). Every append route (public service, write-behind drains, HMR seed/suffix adoption) converges on `appendCore`, where legacy-shape rejection lives so a stale plugin cannot persist a retired shape; the unknown-type guard is read-side only (an append-time refusal would stall a live session's durability; see the session-log-version-mechanism Agent Note). Seqs must continue the stored log contiguously; the durable write is the transaction (state advances as soon as it commits).
- `src/coordinator.js` reads: an unsupported format is surfaced unwrapped (a refusal over an intact log, not corruption); interrupted turns get synthetic closers only for missing ones; a repair that changed the durable revision reloads the committed graph instead of pairing the old view with a newer revision; truncate-only repair does not close the open turn.
- `src/coordinator.js` `serialize`: the chain tail swallows this op's rejection for the NEXT waiter (the caller still sees it) and is deleted only if still the installed tail; adoption runs inside the id's chain using core helpers, never public methods.
- `src/coordinator.js` write path: the disposer registers BEFORE the listeners (Cordis tears effects down in reverse, so admission closes before the final drain and backend close); a backend close error is surfaced only when the drain succeeded (it must not mask the drain's `AggregateError`); session disposal is observe-only so `retire` contains its own failure; HMR does not replay `session/created`, so existing live sessions are seeded on install. Constructor seed events never emit `session/event`, so the seed suffix beyond the persisted prefix is appended explicitly. `live.init` rejections are observed by flush/dispose through the controller (hence the empty catch).
- `src/coordinator.js` live adoption (`initFor`): an ownerless state from public create()/load() is claimed by the FIRST live session only if BOTH cwd and seed prefix match (a different cwd would append through the stored header's cwd; a seed mismatch could filter a fresh session's leading events as already written), else it is an id collision. An id already stored is adopted via `adoptLivePrefix`, NOT cold preparation (which crash-repairs open turns as interrupted, wrong for HMR while the live Session may still append the real step/turn end). A brand-new session registers meta lazily, binds `owner` (so a later different session reusing the id is a collision), then persists its seed once. A flush that raced one last enqueue during pending init cancels the automatic wait.
- `src/preparations.js`: the read starts immediately so a same-tick serialized append queues behind it; the deferred settles only once the entry is ready.
- `src/write-behind.js`: admission to a barrier closes in the same job that observes the empty queue, before callers resolve, so a later enqueue starts its own automatic window instead of being stranded behind a settled barrier.
- `PersistenceCoordinator` serializes every per-id operation on a promise chain; serialized public methods must not call each other (deadlock), they call unserialized `*Core` helpers. Unknown event types are refused unless the writer marked them `ignorable`; unsupported format versions must say "upgrade the harness", never "corrupt". Legacy v0 events are upgraded or rejected before validation, and current-looking malformed events are left for validation to reject.
- On `session/created` adoption cases: a tracked id is a no-op or ownerless claim; an untracked id with an artifact at the same cwd that is a seq-aligned prefix of the live events is adopted (persisting the live suffix); an artifact at another cwd or a non-prefix is a collision; no artifact registers meta lazily and persists the seed once.
- Revision-retry loops converge once the durable log is unchanged for one read/check round trip; continuous external writers may delay them. `readFrom` is a detached physical suffix read with no cache, torn-tail truncation, or closers.
