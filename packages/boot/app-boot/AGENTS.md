# AGENTS.md — app-boot

## Rationale

- `boot()`: re-check `ctx.get('loader') === undefined` after every await. A surface can dispose the whole tree during startup, taking the Loader with it, and reading `ctx.loader` afterwards throws a TypeError over an app that exited as asked.
- `boot()` catch: `await ctx.fiber.dispose()` cannot reject and replace `cause` (cleanup failures are contained per observer and a repeated call returns the settled result; framework/README divergence 6, observed with throwing sync and async cleanups). The deepest `cause` stack is appended because the transactional Loader wraps a failing apply once per tree layer.
- `mountRootInclude`: `cordis:group` is registered beside `cordis:include` because an agent preset outside this workspace cannot resolve `@freddie/cordis-plugin-group` by name; both builtins load through the ambient module pipeline. The bootstrap include id is pinned (`PINNED_BOOTSTRAP_INCLUDE_ID`) because it appears in Loader failure chains, and a random id would make startup diagnostics and snapshot fixtures unstable.
- `watchUserPatches`: the root Include's non-patch options are re-read on every refresh, so a writer changing them between refreshes is not reverted by a user-layer reload. An `INACTIVE_EFFECT` on watcher registration means the tree was disposed while the watcher opened; it returns a no-op disposer.
- `PROFILE_TEMPLATES`, `INSTALLATION_OWNED_PROFILE_TUPLES`: every shipped template ends with the default-on bundles (`agent-team-profile`, `dream-rsi`), and each tuple lists the bundle lists earlier installs wrote for that profile name, so `loadProfile` upgrades an untouched profile to the current template while any other list stays user-owned. A list equal to an old tuple cannot opt out by removal; the profile patch disables the bundle's rows instead (see packages/bundle/AGENTS.md).
- `resolveProfileDir`: `node_modules` is an invalid profile name because the launcher-maintained flat module fallback lives at that sibling path (`profiles/node_modules`).
- `PROFILE_PNPM_WORKSPACE`: `nodeLinker: hoisted` gives out-of-tree plugins a flat `node_modules` whose missing peers (cordis and friends) fall through to the healed `profiles/node_modules` fallback, so every plugin shares the installation's single cordis instance. pnpm >= 10 reads these settings from `pnpm-workspace.yaml`, not `.npmrc`.
- `ensureSymlink`: any `lstat` failure counts as a missing link (a real problem resurfaces on `symlinkSync`). `unlinkSync`, not `rmSync`, replaces a wrong link because `rmSync` treats a Windows junction as a directory and throws EISDIR unless recursive. `EEXIST` on the final `symlinkSync` is concurrent launches healing the same fallback: success only when the winner wrote the identical link; that race window cannot be staged deterministically from the public API (hence the `v8 ignore`).
- `healProfilesModuleFallback`: first resolution wins (the `links` map is the visited set, matching Node's nearest-wins). `peerDependencies` are walked too: Service Definition packages (`freddie-subprocess`, `freddie-compaction`, ...) are peers of their implementations, never plain dependencies, yet out-of-tree plugins import them directly. A declared-but-uninstalled dependency is skipped instead of failing the whole boot, since it cannot be a loader-visible plugin.
- `packageDirFromAnchor`: `createRequire(...).resolve.paths()` returns `null` only for builtins, which no bundle name is, so the `?? []` branch is unreachable (hence the `v8 ignore`).
- `assembledActivationRejections`: rejection reasons already folded into the boot diagnostic stay visible through one `setImmediate` checkpoint so the `installFailLoud` guard ignores them. Origin: Loader rc.5 derives and drops a rejected promise after a fiber fails (not reproduced with a plain throwing plugin `apply`, so treat as unverified).
