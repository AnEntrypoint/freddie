# AGENTS.md — open-in-app

## Rationale

- `src/index.js` open route: launches the availability map's already-verified launcher, never a re-detection, so a click cannot be steered at an application this host never proved it holds.
- `src/catalog.js` `GIT_FOR_WINDOWS_DISPLAY_NAME_PREFIX`: Git for Windows registers as "Git version <x.y.z>"; a bare "Git" prefix would also match "GitHub Desktop".
- `src/resolver.js` `fixedLocatorWithTrustedIcon`: an OS-shipped entry's icon path is trusted, not probed; a missing file surfaces as a 404 at extraction, and only an unset variable such as `${SystemRoot}` drops the icon claim.
- `xcode` locator: `xed` is the supported open verb; the bundle launch follows only when the CLI lost the association.
- `github-desktop` locator: `github open <path>` is GitHub Desktop's supported open verb; the Electron binary reaches it only by running the packaged CLI as node (`ELECTRON_RUN_AS_NODE`), and that adapter process is the one to hide (`windowsHide`).
- `runShellOpen`: the opener is never aborted (`neverAbortedSignal`). The watch window already decided the outcome, and terminating a shell opener that raised the user's window would race the answer the route gave.
- Security: every route passes an EMPTY trust list to `isTrustedApiRequest`, pinning it to loopback like `client-connection`'s `PRIVILEGED_METHODS` (`host.openPath`); connection's fence is a reachability policy, not authentication, so nothing widens it and config has no `trustedHosts`. The open route validates at the wire: `application/json`, 64 KiB ceiling, string `app`/`path`, resolved-and-available catalog id, absolute path naming an existing directory. A refusal that leaves the body undrained reaches the client as a socket cut, so bodies are drained first.
- Resolution: lazy, once per plugin life; a failed resolution logs once and yields an empty catalog rather than a permanent 500. An ENOENT launch re-resolves that ONE entry; new installs wait for the next process. Three per-command deadlines (resolve, icon, launch watch) are independent; a launcher still running when the watch window closes counts as launched (kitty, JetBrains stay foreground).
- PATH names resolve in-process against this host's `PATH`/`PATHEXT`, not through `ctx.subprocess` (which resolves in a provider's world, possibly a remote sandbox); host commands use `freddie-native-command` (argv, no shell); apps spawn detached on `scrubbedParentEnv()`. SSH launches (env markers only, never config) yield an empty catalog. `shell-open` goes through the OS open verb because `explorer.exe <dir>` does not reliably raise a window.
- Every locator proves an artifact this host holds (bundle dir, executable on disk, PATH hit); an Uninstall record alone never counts. `reg.exe` output is parsed by `REG_*` type token because the `(Default)` marker localizes; registry keys use backslash on every host. Undetected by design: macOS bundles renamed beyond the listed spellings or outside `/Applications` and `~/Applications` (README Known Limitations; no Launch Services lookup, no disk scan).
- Icons: macOS `.icns` to 128px PNG (`plutil`+`sips`); Windows `ExtractAssociatedIcon` 32px via PowerShell `-File` with positional args (no quoting hazards); Linux desktop entry `Icon=` via hicolor theme (largest first) then pixmaps only, not the active theme. Failure resolves null and the route answers 404; no placeholder art (a wrong icon reads as a wrong app). `shared.js` is the browser-safe `./shared` subpath: constants only, no `node:` imports.
