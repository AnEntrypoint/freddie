# @freddie/freddie-host-apiproxy

## Rationale

### Carrier and validation (`fetch/handler.js`, `api/rpc.schema.js`)

- Route schemas are identity pass-throughs; payload-shape validation was removed repo-wide. Accepted tradeoff: malformed input (including `session.export` query params) fails downstream in the business layer, which does the second parse.
- Exception, witnessed live: a request with no payload reached handlers that destructure it and answered `handler failure: TypeError: Cannot destructure property ...` (500, leaking an internal message) on `session.history`, `session.rename` and `agentPreset.read`. The handler substitutes `{}` for an absent payload: destructuring yields `undefined`, the handler's own field check answers a business `bad-request` naming the field, and a present payload passes untouched.
- Layers: 500 = implementation crash (impls never throw business errors); 400 = body not JSON; 415 = wrong media type; valid JSON with a bad shape is 200 + `bad-request`. A bad envelope salvages a string `rpcId` from the raw body, else `INVALID_REQUEST_RPC_ID`.
- Cross-site write fence: browsers send "simple" POSTs (text/plain, form encodings) without a CORS preflight, so a malicious page could run side-effectful RPCs blind (`session.prompt` would still execute). Only `application/json` is accepted; anything else needs a preflight this server never answers.
- SSE sends a `: connected` comment on open (no baseline frames, so an idle stream would emit zero bytes; comments are not frames). A mid-stream failure becomes one `stream/error` frame with a fresh rpcId, never a silent end (reads as a normal disconnect).
- Session-log export: a preparation failure answers 500 without echoing the error (it can carry absolute host paths into the browser error bar); a mid-stream failure must fail the download, not ship a truncated archive.
- `fetch/client.js`: `pickDirectory` uses caller-signal-only (a native dialog is user-paced and outlives the unary deadline).

### Session and preset composition (`api-proxy.js`)

- `PROCESS_INSTANCE_ID` is minted once per host process: a changed id on reconnect means the process restarted under the socket (stale JS/CSS), so the client reloads instead of resyncing.
- The running preset is read from the log, never the header (written once at creation): a session that switched while blank ran its turns under the newer composition. This covers `session.list`, cold resume, the `session.create` echo and adoption. The stored preset wins over the one a request names, and a forked child inherits its parent's, since rebuilding differently would replay tool calls the model can no longer make. Header-only summaries skip the log; attaching resolves the switch from events.
- A `session.list` row and the strict `session/list` Typert row (`@freddie/freddie-session-controller`, one shared zod codec on host and client) carry the same fields: `agentAvailable` and `projections.kind` (`sequenced` = attached session's live registry cut, `cached` = the persisted projection cache) on top of the freddie-only `errored`, `agentPreset`, `readOnly`, `extraHome`, foreign-root rows included. The legacy route itself parses as pass-through, so the fields cost the browser nothing, and a strict parse of a legacy row with the Typert schema succeeds and strips nothing. The Typert producer re-derives each field from the same sources (the `sessionListMetadata` unit, `resolveSessionPreset`, `persistence.listForeign`, the bounded cold probe, whose bound it reads from `ctx.apiProxy.coldBlankProbeMaxBytes`); a field added to one producer must be added to the other.
- Presenters live in the scope chain: a live agent's chain passes through its preset, a cold read passes the preset's standing key, no scope sees the global layer. An unrecorded (pre-roster) preset uses the default preset's layer; a deleted or broken preset degrades the read, never fails it.
- `agentPreset.select` only recomposes a blank session (history was produced under its preset's tools); the blank check is re-read inside the queue and the log records the switch after the swap committed. Authoring is privileged (`PRIVILEGED_METHODS` in freddie-client-connection): reading a composition is reconnaissance, copy/remove/openDocument manage the roster and drive the desktop. Shipped presets (`trust !== 'user'`) are not writable, and the directory comes from the id resolved against the Host's roots, so no browser payload carries a path.
- `errored`: the latest `turn/end` reason wins; a fresh `turn/start` clears a stale error; cold sessions use the last closed turn. Cached blank/errored hints are prefix facts verified cold; a row cached before `errored` existed falls back to the probed fold. Logs without a cwd are pre-project legacy and are not served.
- `imageLimits` projection unit is registered here, not in the attachment Service Definition (freddie-llm depends on freddie-attachment: a cycle). It is boot-constant, so `view` reading the live service is sanctioned.
- History baseline: both awaits (`presenterScopeFor`, whose standing mount registers preset-owned projection keys) happen before the cut, or a cold read misses those keys and an attached session pairs events cut at N with a baseline folded to N+1. A fork's cut extends through trailing out-of-band appends up to the next `turn/start`; a subagent source's fork joins the nearest owning ancestor's workspace.
- Adoption checks ownership first (`agent-busy` beats a cwd conflict) and re-checks identity after the await for every path yielding a live agent. Workspace rename uniqueness and the same-title no-op ride the create chain so they see earlier queued renames.
- `session.cancel` cannot tell which connection calls: the UI's Stop and an in-harness agent's own probe (e.g. bash hitting `/api`) look identical, and the latter would silently kill the agent's own turn mid-tool-call. Cancelling a running turn needs `confirm: true` (the Stop button sets it), else a named refusal. `interrupt` does no catalog/history/parent lookup so a live child stays interruptible while its parent is offline.
- `session.search`: host visibility is the authorization boundary. Globally ranked results are consumed and each hit must name a visible session and a current message of it before its snippet is emitted. `openAt: 'never'` is supported (unavailable, not `internal`). Known gap: `internal` search errors echo provider details; redact before exposing beyond the single-user local deployment.
- Approvals: the proxy answers `ctx.approval` over the mux (stable rpcId, settled by `POST /api/respond`); entries survive disconnects (mux-open replays them), withdraw on the ask's abort, and disposal cancels all. Settle synchronously if the signal already fired (dispatch rides a microtask; a late listener leaves a zombie frame on every replay). The audit `approval/asked` event is the newest undecided, unclaimed one with the same `callId` (callId-less asks only take callId-less records); none means the request bypassed the audit path and the fail-closed default answers. Responses route by rpcId (approvals, then questions; one UUID space) and the payload's audit id must match.
- Mux baselines: background-task baselines use the non-resuming `ctx.agents.get` (listing never revives a cold session; an empty set sends nothing); the task push fence compares the exact owner instance (correct during scope teardown) and an unowned task changes every subscribed session's set.
- Model discovery failures answer `model-discovery-failed` with only caller-sent details, never the credential.
- Known gap: `describe` reports placeholder `version: '0.0.1'` (should read apps/cli's package.json).

### Platform (`native-path-opener.js`)

- macOS without a LaunchServices record defers to the content-type handler. Linux uses `$BROWSER` (xdg-settings needs a launcher this package must not ship). Windows names no browser without reading UserChoice; its `.html` association is the browser in the ordinary case.
