# AGENTS.md — web-app bundle

## Rationale

- `product-telemetry-otel` (disabled): `endpoint`, `serviceName`, `serviceVersion` are required with no default so no default collector receives every deployment's events; enabling sends events off this machine. Enable only in a profile layer supplying all three; collector credentials go in env-sourced `headers`, never a committed patch.
- `tools`: `mode` is `FREDDIE_TOOLS_MODE` (native|code|both), a temporary process-wide Code Mode opt-in until the web UI owns it per session.
- Agent plane: the base keeps agent rows for the single-session TUI; this bundle disables them (not deletes, so a base reorder cannot resurrect them) and presets mount them per session. Host-plane rows that stay: `shell-env` (web-app registers FREDDIE_WEB_URL through it; a preset realm would hide it from the shell), `jobs` registry (only `tool-jobs` moves), skill registry (only `tool-skill`/`skill-filesystem` move), `goal`/`goal-round-driver`/`command-goal` (Remote endpoints resolve `goals` on the host), `token-meter` (process-wide projection units), subagent registry and providers, and `tool-subagent-report` (registers a continuable setup on the singleton). Reasoning: .agents/notes/implemented/architecture/2026-08-10-host-plane-ownership-after-presets.md.
- `agent-presets`: the shipped `config/agent-presets/` root (system trust) is patched in by apps/cli composeProfile; `$FREDDIE_HOME/.agent-presets` is the package default and carries shell-access trust, since a preset is a composition.
- Agent Teams in presets: the `standard`, `code` and `cordis` presets mount the four legacy delegation rows (`tool-subagent-control`, `tool-subagent-list-agents`, `tool-subagent`, `tool-subagent-fork`) in preset scope, where the bundle's host-row disables cannot reach them. Each row is `disabled: !!js "ctx.get('agentTeams') !== undefined"`: a preset mounts when a session is created or cold-read, and the web URL line waits for Loader settlement, so the check sees the Team service whenever the Team bundle is in the profile and leaves the legacy tools untouched when it is not. A copied user preset keeps its own rows; its `send_message` is then shadowed by the Team-scoped one. `minimal` mounts no delegation rows, and the Team bundle sets `excludePresets: [minimal]` on `tool-agent-team` because that preset's complete persona suppresses the Team policy section while ten Team schemas would still join its catalog (28 tools with and without the bundle, 38 without the exclusion).
- `web`, `web-fetch-http` and the `tool-web` row: the host mounts the `web` service, the search provider and the fetch provider from the base layer; this bundle disables the host `tool-web` row and the `standard`, `code` and `cordis` presets mount it per session with `fetch: true`. The fetch guard (public destinations only, resolved-address validation, pinned connect, per-hop redirect checks) lives in `packages/web/web-fetch-http`; see the bundle-level bullet. The `minimal` preset mounts no fetch tool.
- `time-context`, `tmux-context`, `tool-session-query`: the base rows are disabled here and the `standard`, `code` and `cordis` presets mount them per agent, so the `minimal` preset gets none of them. The browser provider stays a host row (its exclusive slot registers once per process) and excludes `minimal` by preset id.
- `session-query-sqlite`: this row restates the base config in full because a patch replaces the whole `config`; it carries `openAt: first-search` for the same reason and with the same cost profile as the base row (see the bundle-level bullet).
- `web-startup`, `webserver`, `web-runtime`: startup provides `webStartup` from parsed flags; `--help` provides neither service, so no server binds. `web-runtime` samples LAN trust once after bind and provides `webRuntime`; `connection` concatenates its own authorities onto `ctx.webRuntime.trustedHosts`.
- `client-hmr` is a row, not a child of `web-runtime`: its node half is a client-side package a host bundle cannot import.
- src/index.js `apply`: WEB_RUNTIME_SERVICE is provided only after resolveLanTrust samples bind-dependent trust, which releases dependent rows.
- src/index.js `announceWhenTreeSettled`: the URL line and browser handoff are readiness signals (supervisors RPC on seeing the line, the browser requests the page on open), so they wait for Loader settlement so siblings such as the /api route owner have mounted; a tree without a Loader announces at once. A tree disposed mid-boot (early SIGTERM) stays quiet because reading the torn-down port would turn a clean shutdown into a crash; a failed boot is the Loader's to report.
- src/index.js `browserSharesThisHost`: under SSH the operator reaches the loopback URL through a forwarding address this process cannot derive, so no browser handoff. `DISPLAYED_LOOPBACK_HOST` only mirrors the webserver schema's loopback host, which is the source of truth.
- src/index.js `BROWSER_OPENER_PROGRAM`: on win32 `open` resolves at PowerShell spawn, so the launcher is ref'd until it closes (Windows then holds the URL); a nonzero exit becomes the parent's manual-URL warning.

## Comment-sweep notes
- apps/web is served buildless (its index.html plus apps/web/src/*.js through frontend-static distRoot/distIndex).
- LAN trusted-host entries are port-less IP literals: DNS rebinding needs an attacker-controlled name, an IP-literal Host is safe on any port, and an OS-assigned port is unknowable before bind. SSH launches suppress browser handoff (loopback is not reachable from the operator's browser).
