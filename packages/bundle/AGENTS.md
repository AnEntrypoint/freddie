# AGENTS.md — bundle patches

## Rationale

- All bundles: a patch replaces the target row's whole `config` (last write wins per `id`), so a mode-varying row is restated in full by each mode bundle. Row order carries no load semantics.
- All bundles: `!!js` runs as `with (ctx) { eval }` (framework/loader/src/config/utils.js), so `require` is undefined; no fs probes at this layer.
- `session-title-all-prompts-llm` (disabled): alternative to `session-title-llm`. session-title refuses a second provider ("already registered"), so flip one on and the other off in the same edit. The first-prompt provider stays enabled: it costs one auxiliary model request per session where all-prompts costs one per new prompt over a growing input.
- `gm-client`, `tool-gm`: always mounted, unguarded. The Gm constructor does no I/O; `ensureDaemon` runs on the first call and fails loud there. A require() probe threw at boot and an env gate silently lost the tools.
- `session-query-sqlite`: `openAt: first-search` with `path: ':memory:'` (base and the web-app restatement) makes Web content search work. The service is ACTIVE at boot without importing libsql, so boot stderr stays empty; the libsql WASI warning appears at the first search. The index is per process and rebuilt on the first search: measured 22 s and about 420 MB more RSS over 84 session files (54 MB), then 1-3 s per search; 3 small sessions took 0.3 s. A durable `path` shortens restarts but a path has exactly one owning process (README: second-process sharing is unsupported), so no bundle ships one; set it in a later layer only for a single-process deployment. `openAt: never` restores the typed `session/search-unavailable` fallback.
- `session-telemetry-otel`: mode is `FREDDIE_TELEMETRY_MODE`, default DISABLED; FULL/FEEDBACK_ONLY upload session-log records unredacted over OTLP/HTTP. The collector URL comes only from `FREDDIE_TELEMETRY_OTLP_URL`: no default host, and an uploading mode without it stays DISABLED and logs why. Any non-empty `FREDDIE_TELEMETRY_DISABLED` (even '0'/'false') makes the launcher append `disabled: true` for this row after every layer (apps/cli/src/profile-boot.js). Exports carry `.anonymous-user-id` as user.id. Shutdown drain: exporter `timeoutMillis` 1000 is both attempt timeout and retry deadline, `maxExportBatchSize` == `maxQueueSize` makes one batch, and `shutdownTimeoutMillis` 3000 is the outer bound because the SDK awaits forceFlush outside `exportTimeoutMillis` (.agents/notes/implemented/bug-fix/2026-08-03-cli-signal-shutdown-escalation.md).
- `inspector` (disabled; `enabled: false` is the package default): Runtime.evaluate on its target is a root shell in the Host realm, so no bundle enables it. Flip it in a later layer only while a human debugs; the bind is asserted loopback with no field that widens it.
- `browser-use-chrome-devtools-mcp` (disabled; kept off by the default-on audit): apply() resolves the pinned `chrome-devtools-mcp@1.9.0` entry and throws when absent, and the package declares no dependency because the tree once carried a supply-chain dropper. Degrading the missing-entry case to a warning would make default resolution execute whatever file sits at `node_modules/chrome-devtools-mcp/build/src/bin/chrome-devtools-mcp.js` as a `node` child at every session start with no operator action, and MCP tools take no approval (the tool pipeline's `ask` decision comes only from hooks and auto-review), so an installed server would hand the model an unapproved browser. Enable per profile after installing the pinned server, naming it with `entryPath` so presence alone never executes it.
- `computer-use`, `browser-use`: empty exclusive provider slots; no tool or prompt.
- `tool-subagent-fork`: stays `one-shot`; a continuable child's report tool and prompt section would precede the inherited history a fork reuses (.agents/notes/implemented/architecture/2026-08-10-fork-children-stay-one-shot.md).
- `compaction-image-offload`: inert until an adapter reports IMAGE_OFFLOAD_REQUIRED (none does).
- `auto-review`: acts only while a session selects `auto`; fail-closed (unreadable policy, reviewer error, timeout deny). `advertise: true` is the default and adds `auto` to the preset table.
- `web`, `web-search-browser`, `web-fetch-http`, `tool-web`: search runs through ctx.gm's `browser` verb against Google (no credential, 60s). The provider throws WEB_PROVIDER_BLOCKED on a consent/CAPTCHA wall, the signal to move to a stealth engine. `fetch: true` with `fetchProvider: http`: the model chooses the target, so the guard lives in `packages/web/web-fetch-http` (`src/address.js`, `src/network.js`, `src/policy.js`): it resolves every hop itself, refuses the whole request when any resolved address is non-public, and connects only to the validated address, so a live call to `http://127.0.0.1:<port>/secret` (directly, via `localhost`, numeric spellings, redirects and a rebinding resolver) is refused with a typed reason and the listener sees no request. The row's `timeoutMs: 45000` sits above `tool-web`'s 30 s `fetchTimeoutMs` so the tool budget fires first (`TOOL_TIMEOUT`). The provider bypasses the launcher's HTTP(S) proxy because a proxy would resolve names and void the pin; a proxy-only host cannot fetch. Search already sends the model-authored query text to google.com (and resolves result redirects with a GET to google.com) with no credential; that flow predates the default-on audit and is unchanged.
- `llm-pi-ai`: dormant bare mount; `providers: {}` registers no route (ensureRegistrationFacts skips registerAdapter) but exposes the catalog under the `llm-pi-ai` settings namespace. It stays empty: a catalog route that names no `apiKeyEnv` defers to pi-ai's ambient credential discovery, so a shipped default route could spend a key nobody assigned to it.
- `hmr` disabled in `acp-app`/`sdk-app` (one stdio connection must never see a replaced bridge) and in `headless` (the launcher's watch-only fallback keeps patch layers live). `session-title-llm` disabled in acp/sdk: no title surface to read.
- `agent-team-profile`, `dream-rsi`: on by default through the shipped profile templates (`PROFILE_TEMPLATES` in @freddie/freddie-app-boot), not through base rows: a release package must not depend on experimental packages, and these bundles already carry them. Team tools shadow same-named legacy controls (the agent's own tool scope wins), so the bundle disables the four `tool-subagent*` rows while the Subagent services and providers stay mounted; workflow children and teammates still spawn (verified live with a scripted provider). Web presets mount those four rows in preset scope, so each carries `disabled: !!js "ctx.get('agentTeams') !== undefined"` and falls back to the legacy tools whenever a profile drops the bundle. A profile whose bundle list equals an old shipped tuple is renormalized to the template on load, so opt out with `disabled: true` rows for `agent-team` and `tool-agent-team` in the profile patch and re-enable the four legacy rows. Team tools are ordinary tools: they take no approval of their own and every teammate runs under the same sandbox and approval services. `dream-rsi` mounts only the context plugin, which adds nothing until gm records a grounded replay or automatic strategy; its invariant companion is left out because no shipped composition provides `invariants`.
- `skill-badge` (disabled): its `freddie-badge` skill pushes "powered by freddie" badge markdown with a remote Shields.io image into agent output, a branding action no default should take; dsh ships its counterpart disabled too.
- `tool-str-replace-editor` (disabled): a second editor beside `tool-fs`'s `edit` and `write`; the shipped `minimal` preset composes it with the persistent shell instead, and both in one catalog would give the model two ways to edit.
- `time-context`, `tmux-context`, `tool-session-query`: on by default as base host rows (acp, sdk, headless) and as rows in the Web `standard`, `code` and `cordis` presets; the Web bundle disables the host rows because an agent-plane listener or tool belongs to a preset, and `minimal` must stay a fixed-prompt bare runtime (measured on the Web composition: `minimal` has 28 tools with or without them, no `session_*` tool, and its first request carries only the user prompt). `time-context` sets `refreshIntervalMs: 60000`: one reading of about 270 bytes at a session's first step and another only after a minute; the reading is appended after the reusable prefix (five scripted requests at interval 0 and at 60000: identical system block, each request begins with the previous one byte for byte), so it costs tokens, not cache reuse. `tmux-context` is inert without tmux: on win32 or without a well-formed `$TMUX_PANE` it mounts no listener and never spawns (measured before the guard: one sandbox-runner process per turn on this Windows host; after: none; a forced-POSIX run with `TMUX_PANE=%1` and no tmux spawned once, then never), and its command is a constant plus the numeric pid. `tool-session-query` authorizes by exact `cwd` equality between caller and target (a session in another workspace and a nonexistent id return the identical error; live sessions are searchable), bounds hits with `maxSearchResults` and inline size with the base `spill-policy` row (`maxInlineBytes: 50000`), and its descriptions tell the model it reads other sessions and that the content is untrusted data. The first search per process builds the in-memory index and prints the libsql WASI notice once on stderr (see `session-query-sqlite`).
- Unmounted packages: `workspace-changes` and `tool-present` (nothing reads `workspace/changes` or `deliverables/presented`, so recording would spawn git each turn for no consumer), `mcp-resources` (no connection plugin registers a provider, so no tool would appear), `lsp`, `lsp-stdio` and `tool-lsp` (need language-server binaries), `hooks-claude-code` and `hooks-codex` (run commands from a hook file), `webhook` and `webhook-github` (inbound HTTP listener plus secret), `e2b` (credential), `subagent-acp`, `subagent-claude-code`, `subagent-codex` and `subagent-freddie-sdk` (external binaries or credentials), `web-search-deepseek`, `web-search-exa` and `web-search-perplexity` (credentials), `session-persistence-sqlite` and `storage-sqlite` (alternative stores; jsonl stays the format).

## Comment-sweep notes
- Bundle packages' invariant.js and index.js are minimal by design: the substance is `cordis.patch.yml` (`freddie.bundle.patch`), and rows belong to the packages that mount them, so there is no runtime invariant to audit. The same holds for other invariant.js companions that declare "no runtime invariant" (stateless seams and process-boundary transports).
