# freddie-session

## Rationale

- `src/chunk-rows.js` `continues`, `validateRow`: packed run times must stay exact. Two safe-integer times can be further apart than a double subtracts exactly (`2^53-1` vs its negation), so a rounded gap would decode to a different timestamp. `continues` refuses a gap that is not a safe integer; `validateRow` re-walks `seq0`/`time0` plus every `dt` and fails at the first value leaving safe range, because float arithmetic past it silently corrupts.
- `src/chunk-rows.js` `continues`: a tool-call run needs `name` equal in presence and in value across members; a mixed run has no row representation.
- `src/index.js` `Session` constructor: a seed is validated to the same invariants as `append` (lossless-JSON `data`, `seq` contiguous from 0, valid surface transition planned before the event enters `log`), so replay/fork cannot build a live log no backend could store.
- `src/index.js` `Session` constructor: `session/end-seed` is appended inside the constructor so it is already in `events` when a backend captures the creation seed (no load-time write), and skipped when the log already ends with it so reopening does not grow the log.
- `src/index.js` `requestHeader`: the folded header is returned by reference and deep-frozen on every update, so an in-place mutation throws instead of desyncing later comparisons against the log.
- `src/index.js` `deriveMessages` / `src/surface.js` `deriveEventMessage`: an empty-content `assistant/message` (a max-tokens step hosting only usage) derives to `null` and never enters the transcript; a non-message event derives `null` and the switch is deliberately non-exhaustive (merge-extensible union, no `assertNever`).
- `src/surface.js` `deriveEventMessage`: `user/message` content projects verbatim. Do not add per-type framing here; a producer bakes framing into `content` (see `packages/context/agent-instructions/AGENTS.md`).
- `src/index.js` `create`/`enter`/`announce`: `enter` returns the detach disposer, yielded inside the effect BEFORE `announce`, so a throwing `session/created` listener rolls the attach back. `announce` sets `announced` before emitting: Cordis emit can reach earlier listeners then throw, and rollback must still pair that partial creation with a disposal edge; the flag also blocks a listener from creating a second lifecycle edge.
- `src/index.js` `enter`/`detachEntered`: detach requested while announcing or appending is deferred until that dispatch unwinds; `detachEntered` compares the store entry so a stale detach capability cannot remove a later same-id session.
- `src/index.js` `announce`: a synchronous listener throw vetoes publication; an async listener assigned to a void listener slot has its rejection logged (too late to roll back) instead of becoming unhandled.
- `src/index.js` `flush`: a listener's rejection value is rethrown unchanged (Cordis listeners may throw non-Errors), hence the `Promise.reject(error)` lint suppression.
- `src/invariant.js`: a `tool/result` whose `surfaceOp` is not `append` is a content rewrite (already validated by `Session`) and only needs an open turn; `session/end-seed` is unconstrained because an unbalanced seed legally places it inside an open turn; staged transitions are keyed weakly per event because a later `internal/dispatch` listener may veto and validation is pure.
- `src/repair.js` `interruptedTurnClosers`: closers are ordered tool results, then `step/end`, then `turn/end` (providers reject dangling assistant calls; `turn/end` with an open step breaks the invariant); `pendingCalls` is a `Map` so insertion order keeps transcript order; closers reuse the last event's timestamp so recovery is deterministic.
- `known-event-types.js` is the maintained persisted-event type set. The persistence coordinator accepts a known type or `ignorable: true` and refuses unknown required types; update the set when adding an event. No generation command is registered.
