# @freddie/freddie-tools

## Rationale

- `code-mode.js` `createRunCodeTool`: `description` and `parameters` are getters installed after `defineTool` (the definition is minted before a runtime is known), so the schema follows the loaded runtime's language. Argument validation stays on the static spec (one required string `code`). Without a mounted runtime `resolveFlavor` degrades to TS; only the doc-catalog harvest reads that path.
- `run_code` scheduler (`drive`): one driver lane runs every ordered stage (dispatch-start append, prepare, finalize/finish, context deferral, settle append); only the launched body overlaps. Starts and commits are in submission order, parallel calls overlap up to `maxParallel`, an exclusive call runs alone and holds its barrier through commit. Mode is re-read via `executionMode()` right before each start (registry mutation while queued can flip it).
- `drive` creates the wakeup promise before inspecting the queues so a settle or submission between the checks and the `await` is never lost.
- `settle` resolves the program's value immediately; log shaping and the `tool/code-dispatch` append are tracked `logWork` (drained in `drainDispatches`) so a slow log-content listener never delays a binding or holds a slot. `commit` waits while `logWork.size > maxParallel` (each task retains a full result).
- `tool/code-dispatch` logs `normalized.logged`, a sibling parse of the dispatched value, so a tool mutating its args cannot desync the record.
- `commit` forwards `concludesTurn` from the nested result; only a successful result can carry it, so a policy-converted failure cannot end the turn through a recovering program.
- Binding rejections reach the program as the bare message (the worker wraps them in `ToolCallError` with the binding name); native content and internal error metadata stay outside the program-facing failure contract.
- `functions` is null-prototype plus `defineProperty`: a tool named `__proto__` becomes an own key and the runtime host resolves binding names as own properties only. The bound set is `registry.schemas(exec.agent)`, the view the SDK section declared.
- `run_code` has no `presentResult` on purpose: the generic card keeps the call title and reads durable content without copying a large raw result into the host view payload.
- `index.js` `errorMessage` fallback must be total: a hostile thrown value can trap `instanceof`, property access and string coercion.
- Code-mode collapse: the prompt's collapse section uses `modeFor`, the same predicate the executor denies by (`collapses`). Mode resolves nearest-scope-wins along the scope chain; SDK and collapse sections are registered per scope, shadowing an identical global body at no cost.
- A collapsed call (visible in scope, denied only by the collapse) ends before the policy pipeline so listeners, approval and guards never see a call that can only fail; its denial names the `run_code` route. An unknown tool keeps the dispatch-stage `UNKNOWN_TOOL` path. A pre-dispatch abort is honored ahead of the denial.
- `finalizeContent` is captured before argument materialization (an arguments getter can replace it). The abort path retains it; `UNKNOWN_TOOL` and invalid-args failures of a non-aborted collapsed call drop it.
- Assembly validates the runtime language before projecting schemas so a language with no SDK renderer fails with the renderer-table error, not the flavor-table error.
- `RUN_CODE_NAME` is reserved unconditionally (any agent may pick a code mode). `view(scope)`: the scope's own layer is chain-blind, inherited entries shadow nearest-last, restrictions intersect across the chain, and `run_code` is inserted last per scope outside capability filtering.
- `schema.js` presentation runs on replay of logged args from possibly older schemas: it validates softly and returns `undefined` (generic card) instead of the hard `ToolArgsError` execute raises.
- `py-types.js` `RESERVED` includes `__debug__`: not a keyword, but CPython rejects assigning it (TypedDict field, parameter, keyword argument).
- `py-types.js` walk validates the whole schema tree once, then trusts it; unsupported or malformed schemas degrade to `Any`. `oneOf` text is built by template concatenation (lazy ConsString), not `Array.join`, to keep deep chains linear.
- Class bodies are assembled after their children (declaration order equals reference order). Open objects state openness in-band with a `# Additional keys...` line because `mode: 'code'` omits native schemas. A closed empty object still needs a `pass` body.
- Union length is uncapped on purpose: `A | B | ...` is valid Python at any length (only CPython `compile()` recursion limits it, irrelevant to prompt text), unlike list nesting where more than 200 open brackets is a tokenizer `SyntaxError`, hence `MAX_LIST_NESTING` degrades to `Any`.
- A missing `properties` is an empty property map (as in the validator and the TS renderer), not an unknown shape. An empty top-level `className` marks the context-free `jsonSchemaToPy` entry: read it from the call, not `frame.className` (frames derive names such as `1`); objects with properties then degrade to `dict[str, Any]`. Field names that are not legal attributes, or are leading-double-underscore non-dunders (name-mangled in class syntax), degrade the whole object.
- Tool methods are emitted as one ordered member stream. A docstring must follow the `async def` (as first body statement) or it documents the wrong thing; the `...` stub is only for description-less tools. Names not usable as `tools.name` (exotic, keywords, any leading underscore: mangling, `object`/`type` attributes, special-method lookup) are listed as `# tools[...]` comments; a class body of comments only needs `pass`.
- `py-types.js` `isBareIdentifier`: bare Python names use `XID_Start`/`XID_Continue` plus NFKC stability (CPython normalizes identifiers, JSON keys are compared as written, so unstable names take the subscript path). Predicate is deliberately stricter than `isidentifier()`. Engine Unicode tables are versioned independently of CPython: a character newer than the interpreter's tables (e.g. U+1E4D0, ZWJ/ZWNJ in tail position) is emitted bare and breaks the whole SDK parse; an older engine only degrades to subscript. `camelCase` reads engine tables at three more points (split set, head test, `toUpperCase`), independent of that predicate; closing it needs the target interpreter version, owned by the backend (`docs`/language-dispatch note). `ts-types.js` keeps its own ASCII rule (ECMAScript identifiers differ: `$`, no normalization).
- `py-types.js` escaping: `UNPRINTABLE` (C0/DEL/C1 `Cc`, escaped `\xNN`; NUL makes CPython reject source) and `LONE_SURROGATE` (`\uNNNN`; not UTF-8 encodable) guard `describe`; NEL/LS/PS are legal raw in source (tokenizer, not `splitlines`); `pyScalar` and the `# tools[...]` comment go through `JSON.stringify`, whose escapes are all valid Python escapes. Docstrings double backslashes, escape quotes, and cannot end in a backslash. Non-integral numeric `Literal[1.5]` deviates from PEP 586 on purpose (advisory text, must only parse); `pyScalar` uses `BigInt` digits for beyond-safe integers so the emitted value is the exact double.
- `py-types.js` `MAX_LIST_NESTING` is 180: CPython rejects more than 200 open brackets; worst site is an argument annotation reached via `oneOf` arms only (180 `list[` + `Literal[` + paren = 182). Class names: base capped at `MAX_CLASS_NAME_BASE` at propagation and in `allocateClassName` (linear text, O(1) allocation via `nextClassCounter`); joins are NFKC-normalized and capped by whole code points (no lone surrogate). TS flavor needs none of these.
- `code-mode.js`: `TYPESCRIPT_FLAVOR` is only the no-runtime fallback (doc-catalog harvest); a mounted runtime without a `RUN_CODE_FLAVORS` entry fails loud like `requireCodeRuntime`. Adding a backend language edits `CodeSdkLanguage`, `SDK_RENDERERS` (index.js), `RUN_CODE_FLAVORS`, plus the prose naming languages (code-runtime READMEs, `CodeRuntime.language`, `docs/subsystems/code-runtime.md`, this package's README, `ToolRuntime.Config` `mode`). Program-result rendering caps `JSON.stringify` indentation at 10 chars and compacts deeper subtrees to stay linear. `CodeRunFailedError` (`CODE_RUN_FAILED`) becomes a structured `isError` result carrying failure kind plus logs.
- `index.js` `requireCodeRuntime` reads at use time, not via `inject`, so `mode: 'native'` never needs a code runtime; assembly and `run_code` read separately, so a mid-reload language swap could pair a program with the wrong SDK (binding deferred until a second backend ships; see the code-mode-language-dispatch agent note). The collapse predicate resolves through `modeFor`, never `defaultMode`, so a preset-assigned `code` agent under a native deployment is collapsed. The scope's `presentAs` is one cell (two answers are a contradiction), scoped only.
- `index.js` `view`: restrictions filter only the INHERITED surface (global plus ancestors), never the scope's own layer, so a delegation child's own reporting/structured-output tools survive its capability filter; ancestor contributions from presets must still be filterable. Guards are monotonic (any guard denies, none force-allows), global then scope chain farthest first. `ask` decisions resolve through `ctx.get('approval')` opportunistically: no ApprovalService, no agent, or an unmount degrades to deny; `allowed-once` proceeds and the three non-grants deny with distinct reasons. Post-execute `accept` may replace `value` or `content`; `block` becomes `isError` with `feedback`; deferred context survives accept and is discarded on block. Cancellation never abandons a started body: it drains, then the outcome becomes `ABORTED` (`ABORTED_BEFORE_DISPATCH` when never started). The `tools/code-dispatch-log` waterfall is contained: a throwing listener logs the original content. `UNKNOWN_TOOL` carries `reachableFrom` when only the collapse denies the name.
- `json-schema.js` enforced subset: any JSON root, one scalar `type`, object `properties`/`required`/boolean `additionalProperties`, array `items`, scalar `enum`/`const`, exact-one `oneOf`; unsupported keywords reject (never accepted unenforced), and `violations` lists every offending path. Object-root consumers (subagent/workflow structured output) add `assertObjectJsonSchema`. Validation and rendering walk with explicit frames, not recursion. Realm-agnostic record/array tests exist for cross-realm values.
- `presentation.js`, `types.js`: type-only modules in the TS source, intentionally empty at runtime after the buildless JS conversion (`presentation.js`: provider-neutral `presentCall`/`presentResult` render intents; `types.js`: durable Tool event vocabulary). `testing.js` fixtures use content blocks as the canonical JSON value; product tools must declare domain-owned DTOs.
- Comments are removed except tool pragmas (`v8 ignore`, `jscpd:ignore`, `oxlint-disable`). Nothing in this package reads comments at runtime or generates from JSDoc (typert compiles from explicit metadata).
