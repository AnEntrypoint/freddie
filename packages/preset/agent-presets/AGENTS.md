# AGENTS.md — agent-presets

## Rationale

- `src/authoring.js` `copyComposition`/`removePreset`: the roster check only sees discovered presets, so a composition-less directory still occupies the name and gets a readable `PresetExistsError` (`occupied` treats every stat failure as "nothing usable here"). A failed copy removes the half-copied directory (it would be invisible to discovery at best, mountable-but-incomplete at worst). Removal re-checks that the resolved path lives under the writable root, beyond the id pattern.
- `src/discovery.js`: an unreadable composition file reports the same as an unparsable one; YAML errors show the first line only (the reason renders on a roster card); a stat failure means the directory is not a preset, not an error; unreadable metadata is never fatal (the preset shows its id); sort is declared `order` first, then id.
- `src/metadata.js`: absent metadata is the common case (every duplicated preset carries none) and malformed display text never fails discovery.
- `src/index.js` settings: deliberately not `installSettingsSection`; that helper re-judges derived facts across attach/detach/change, and `defaultId` reads through on every call, so both hooks would be no-ops.
- `src/index.js` `agent/created` warning is advisory: a throwing synchronous listener VETOES publication, and composing an agent outside the roster is legal (`recompose` binds exactly such a bare agent; ACP, SDK-server and headless entries create one). Known false positive: a session created bare and bound later by `recompose` warns once before its first bind (no shipped flow does that). The failing check is the invariant companion at assembly (see `.agents/notes/implemented/architecture/2026-08-10-host-plane-ownership-after-presets.md`). The `agent-preset/selected` notification carries stable identity only, emitted after the durable record (the commit point).
- `src/index.js` registration: a directory claiming an id registration refused can only have appeared later; the deployment keeps it and warns once per declaration. Declared ids must match `PRESET_ID` (one roster vocabulary across `resolve()` and every surface). Withdrawing a declaration disposes its standing mount, since a mount nobody can resolve still holds live watchers; joined sessions keep their generation until the scope disposes. `this.ctx` is the CALLER's context (Cordis rebinds it per read), so the withdraw effect unwinds with the declaring plugin.
- `src/index.js` bindings: the binding held privately is the only re-link authority, so nothing outside the roster can move a composed agent to another preset.
- `src/index.js` `duplicate`/`remove`: the roster check refuses ids from any root (a user directory named like a shipped preset is shadowed by it); a settled standing mount under the id is stale and dropped, sessions already joined keep theirs. A stored default naming a not-yet-existing preset is deliberate (the roster is a live directory), but deleting the default preset unsets it, exposing the deployment default beneath (else every session without an explicit pick fails to start).
- `src/index.js` `ensureStanding`: declared presets serve the mounted generation until withdrawn; file presets compare a `compositionStamp` taken BEFORE the file is read (an edit racing the mount leaves a stale stamp, never a silently current one); an unreadable stamp serves the current generation (a mount survives its file disappearing). Rows and base URL live on the declaration so `mountPreset` cannot tell declared from discovered. The stale-pointer delete is guarded (`standing.get(id) === pending`) so a racing caller's next generation is not dropped. Open item: reclaim a superseded generation once its last joined agent is gone; needs a joined-agent count on `StandingMount` (inc in `mount`/`composeFrom`/`recompose`, dec when the agent's scope key dies), since the subtree is not inert (`freddie-skill-filesystem` watches its roots) and settings-page saves make "composition changed" a per-save event.
- `src/invariant.js`: imports through the package name, not `./mount.js`: a module shared between the two build entry points becomes a third chunk the published `files` list does not carry (`verify-built-package-invariants` rejects it). The assembly check fires only when `context.agent` exists (a scope-only assembly is not an agent) and at assembly, not publication, because an unjoined agent is legal until it addresses a model. It fails because an unjoined agent resolves `tools`, `system-prompt` and `skill` against the empty global layer.
- `src/mount.js`: the entry-list config carries the tree-carrier `EntryGroup.key` so Loader `internal/config` interpolation stays literal (a `!!js` expression belongs to its row's fiber). Inline rows are `structuredClone`d because `EntryGroup.update()` mints ids into rows lacking one, which would otherwise leak into the plugin's own array. The harness base is captured before the subtree exists (it is where a row's package name resolves from). `pruneDisposedMounts()` runs first: standing mounts live until whole-tree teardown, so it only sweeps torn-down runtimes (tests, HMR). A teardown failure of the failed subtree is swallowed; the mount error is the actionable one.
