## Rationale

- `src/index.js` `validatePwshArgs`: the escalation pairing (`sandbox_permissions` with a non-empty `justification`) is the shared rule both enforcing families validate identically through `validateEscalationArgs`.
- `src/index.js` description gate: the language-mode and named-pipe sentences are Windows-restricted-token behavior, but the gate is only "any confining executor is mounted" (`escalationModes` non-empty). That conflation is safe while every shipped composition pairing `tool-pwsh` with a confining executor is win32-only; a future POSIX pwsh-sandbox composition must gate both sentences on the platform (tracked in the pwsh-tool-and-executor Agent Note).
- `src/index.js` output schema: the foreground result wire shape mirrors `freddie-tool-bash`'s by contract; consumers of one must accept the other (pwsh-tool-and-executor Agent Note).
- `src/index.js` background start: undeclared input keys are allowed, so omitting `run_in_background` from the schema still needs the explicit `enableRunInBackground` enforcement. The caller owns cancellation until `ctx.jobs` commits detached ownership, and task preflight finishes before the starter can spawn a process.
- `src/render.js` markers: the exit marker must stay last because `parseExitStatus` anchors there; the escalation hint is added before it and only when the composition exposes escalation. A timed-out command is still reported as interrupted even if it trapped termination and exited 0.
- TODO(background-infrastructure-outcome) in `src/background.js` `processOutcome`: widen `ShellProcess` with an explicit infrastructure-failure outcome and map spawn failures and `sandbox.runnerFailed` to task `failed`. The current contract aliases a spawn failure with a signal-less kill and a runner failure with an ordinary wrapper exit; real nonzero command exits must remain `completed`.
