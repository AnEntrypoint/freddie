## Rationale

- `src/activation-setup-registry.js`: a registration is marked `removed` before disposal so a snapshotted `apply()` cannot install after revocation reports completion; an installer revoking itself before its record exists has that record disposed and the batch invalidated; on installer failure every rollback is attempted and the installer failure stays authoritative.
- `src/assistant-output.js` TODO: `finalAssistantOutput` folds the whole suffix per settlement; if a long continuable epoch profiles hot, scan backward for the last non-empty message and fold text deltas only on the no-message fallback.
- `src/child-agent.js`: `origin: 'subagent'` is navigation only (the descriptor stays authoritative for mode/continuation); `delegationDepth` is durable so the recursion budget survives persistence and resume (`src/depth.js` trusts it: validated at the session boundary). The `subagent:delegation` context is `order: 120`, after `sandbox:policy` (110) and `approval:policy` (115).
- `src/index.js`, `src/invariant.js`: a throwing `subagent/provider-added` listener unwinds the yielded rollback (fail-loud registration). Provider availability is checked at admission only: a published one-shot run may outlive provider removal and a cold-resumed Activation records its initial provider name without dispatching through it.
- `src/lifecycle.js`: the terminal observer is attached before `start` dispatch (promise reactions still run after the synchronous start, preserving start then end). A continuable epoch reports telemetry from the suffix after `boundary` only (a cold resume replays earlier turns); a teardown failure overrides the epoch outcome and withholds its output (an answer this harness could not durably release is not a result). `blocked` (pre-step rejection by hook/policy) maps to `refusal`; a clean ending and no accounting turn share one rule.
- `src/out-of-process.js`: any `statSync`/`accessSync` error means the path cannot serve as the child cwd. A rejection queued at cancellation returns `aborted`; other transport failures are flattened with diagnostics and the `onError` sink cannot reject the result.
- `src/projection.js`: a fold must never throw, so a malformed descriptor folds to no value. `stateVersion` is 2 because the identity gained `seq`; older checkpoint rows must refold. `src/run-settlement.js`: merge-extensible stop reasons stay failures with provider detail.
- `src/list-children.js` prerequisites: the `sessionProjections` check runs before any read even with zero candidates (mode/label are the row's strong contract; a missing capability is a deployment error, never an empty success). `ctx.get('sessions')` is a strict global read, never the caller-scope-bound `ctx.sessions` proxy, which would throw for consumers without their own injection. `sessionProjectionCache` is optional acceleration only. Backend abort failures normalize to a stable cancellation; the merge is live-preferred (a live record wins its id wholesale).
- `src/list-children.js` rows: live rows read the registry watermark cache with zero log reads; a live child without identity is the creation window before the provider appends its descriptor. Damage from any unit's fold/schema degrades to one `corrupt` diagnostic, never a failed listing; the no-value sentinel is `null` (`undefined` means a dropped key), both mean no value. Cold rows: a throwing cache read falls through to the authoritative re-fold; a cached identity is final only when `seq >= seedLength` (a creation-window checkpoint may carry a fork seed's ancestor descriptor); a vanished child gives an `unavailable` row; a session id names a slot, not a lifecycle, so a `sameLifecycle` mismatch (deleted and re-published under another owner) is `corrupt`.
- `src/continuation.js` structure: the lock `tail` absorbs rejections so one failed critical section cannot reject later callers. Cordis effects unwind in reverse order, so the private scope's disposer is registered first and the drain second (drain runs before scope release). Agent provider/model and delegated policy overrides are snapshotted before any await (a later parent switch belongs to the parent's future); only fresh creation seeds delegation policy onto the child log, cold resume replays persisted events.
- `src/continuation.js` authority: a delivery arriving after disposal began waits for release, then cold-resumes; a stale caller is rejected even when the target is absent so a replaced same-id Agent cannot probe state; cold resume authorizes the persisted header (exact live direct parent) before folding and folds only the own suffix (`seedLength`) since a fork seed replays the parent's log with possibly an ancestor's descriptor.
- `src/continuation.js` drain/dispose: admission closes synchronously before the first await; in-flight materializations stay tracked until handle install or rollback. Roots are snapshotted after closing admission and merged with earlier calls for the same root; only strict descendants are owned. Every transaction opens before the first await (top-down cancellation in one synchronous span, child-first release), `activation.disposal` is assigned synchronously as the admission cutoff, quiesce precedes the final flush, and edge data is captured while the child is live.
- `src/continuation.js` materialize: no id pre-check (child lock serializes, `AgentRegistry.enter()` is the collision boundary); creation owns rollback before handle transfer, afterwards failures dispose the handle, remove the Activation and roll back parent ownership. Each accepted inbox id leaves exactly once (dequeue or discard) so `stateOf()` can tell quiet from not-yet-admitted; the start edge publishes before any turn. Waking sends publish inbox events synchronously, so the Activation is marked busy first; parent-originated delivery acquires ownership before the message enters the inbox.
- `src/continuation.js` settle/finish: settlement is re-checked inside the child lock and disposal begins in the same critical section (a concurrent delivery either wins admission first or waits and cold-resumes). The Activation stays registered until disposal settles. The settlement notice is delivered before ownership release (while the parent still counts the child; otherwise a parent watcher could find itself childless and quiet and dispose an Agent whose `cancel()` clears the inbox holding the notice); ownership is released even on failure; `settle` is emitted only after the outcome is known.
- `src/continuation.js` `notifySettlement`: a parent already tearing down is not woken (waking spends a model request per tree layer and `cancel()` does not arm against a later turn); the notice is injected and is lost only to that parent's own `keepInbox: false` cancel. An idle parent gets one turn; a busy parent is steered (one `Inbox.claim()` batch per boundary, and no window where a retiring driver strands the notice).
