## Rationale

- `src/index.js` `Config`: `agentOptions` and `toolFilter.allow` use `.default(undefined)` on purpose: Schemastery would otherwise materialize an omitted `agentOptions` as `{}` and an omitted filter as `{ allow: [] }`, which would deny every tool.
- `src/index.js` `apply` validation: direct `apply()` bypasses Schemastery's numeric constraints, so `maxDepth` is asserted here (an omission stays capless; the schema default only runs through the loader). An explicit `toolFilter` naming neither `allow` nor `deny` is rejected at load instead of failing every delegation. A numeric `maxDepth` the provider cannot enforce fails at `mount`, the earliest point the provider's capabilities are known.
- `src/index.js` job outcome: product providers aggregate startup and rollback failures, so an aborted signal only maps to `killed` when the error is not an `AggregateError` (cancellation must not hide a failed cleanup). An unknown stop reason (the union is merge-extensible) is a failure, never partial output reported as success; the thrown error keeps the partial answer so it still reaches the parent.
- `src/index.js` result: content blocks already cross durable JSON boundaries elsewhere; the tool registry performs the authoritative lossless snapshot of `output`.
- `src/index.js` background: the validator permits undeclared keys, so schema omission also needs the execution-time `enableRunInBackground` check. Continuable work defaults to background because it is independently scheduled; one-shot keeps its foreground default because its background result requires Task collection. A continuable start resolves at inbox acceptance (the child owns its own turns), so the call neither waits for nor collects a result; one-shot job preflight finishes before the starter can spawn and the task-owned signal covers startup, with no `readOutput` because the child session owns intermediate detail. The continuable description promise (completion notice) is the continuation service's own behavior and holds whenever that path is reachable.
- `src/index.js` provider lifecycle: the tool mirrors provider availability because sibling load order and HMR replacement can change it while this fiber stays active; listeners are registered before the presence check so no synchronous change is missed. The `tool:<name>` prompt section follows availability without manual lifecycle (empty text is omitted while the tool is absent) and stays owned by this plugin fiber. A late provider is logged so a misspelled name stays visible.
- `src/index.js` `isConcurrencySafe`: children never mutate the parent session; the one parent-owned write (`tasks.start`) is a synchronous commutative insertion. Non-agent callers provide no parent, so delegation ownership fails closed.
