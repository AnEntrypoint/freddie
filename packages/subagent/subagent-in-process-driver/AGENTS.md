## Rationale

- `src/index.js` stop reasons: a `blocked` pre-step discarded the claimed prompt, so the task was declined (`refusal`) and the caller must not read the run as done. Disposal can tear the owner down before the loop records its ordinary `aborted` end (yielding `disposed`), so a cancelled non-`completed` run reports `aborted`.
- `src/index.js` start: delegated policy overrides are captured before the first await because a later parent switch belongs to the parent's future. The abort listener is re-checked after registration because agent creation detaches its creation-only listener before returning; the check closes that handoff without treating an already published child as a failed start.
- `src/index.js` settle: the result channel owns run faults; disposal reports only a failure to release the published handle after both operations settle. `droppedUnrun` is deliberately unread: a one-shot prompt is claimed by its awaited first turn almost immediately and the owner's teardown is the `cancelled` flag; a cancellation with no accounting turn resolves `error` through `toStopReason(undefined)`, which never overstates success. Output follows the seam's canonical selection rule (`finalAssistantOutput`), so a partial answer survives cancel and truncation.
- `src/structured.js` capture tool: `ToolArgsError` becomes an `isError` result with `INVALID_ARGS`, so the model retries within the same turn like a schema-validated `defineTool` call. Capture is two-phase, keyed by this execution: later transformable waterfalls may still turn the success into an error, and `ToolRuntime` has already frozen model-bound arguments at the actual input boundary.
- `src/structured.js` guard: terminal within the step. Guards run after the whole pre-execute waterfall and compose monotonically (deny or abstain, never allow), so a later prepended listener cannot resurrect dispatch; calls preceding capture in the same response stay untouched. The commit observes the immutable authoritative result after the complete pipeline and outer error normalization (`tools/result` cannot transform the outcome), so no wrapper sits outside the commit verdict.
