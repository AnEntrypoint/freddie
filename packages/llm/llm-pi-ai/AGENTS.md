# AGENTS.md — llm-pi-ai

## Rationale

- `registrationFacts`, `providerInfo`, config `displayName`: the registry captures `providerInfo()` (id and name) and the retry policy at registration, so a rename must re-register or selectors keep the old label. `displayName` defaults to the route key, not the installed provider's name, so a catalog route does not rename itself just because it gained a profile.
- `resolveApiKey`: a profile naming `apiKeyEnv` fails `MISSING_CREDENTIAL` on a miss. Only an unnamed credential defers to pi-ai's environment discovery; handing pi-ai `undefined` would let it pick up an unrelated ambient key (`OPENAI_API_KEY`) and bill another tenant. Without the credentials seam the launch environment is the whole credential plane.
- `apply`: one `auth` (store plus auth context) per plugin instance, reading through `ctx` per call, so it stays correct across collection rebuilds and a sign-in survives them. Sign-in flows register regardless of routes (signing in is what makes a route worth adding) and via `ctx.inject(['authorization'])` because headless and ACP compositions have no sign-in surface.
- `ensureDirectory`: `directory.replace(entries)` is an atomic swap validated first, never dispose-then-register: a collision with another adapter family's route (a profile keyed `deepseek-official`) would otherwise empty the Models page. `declared` means absent from the installed catalog, not from settings.
- `ensureRegistrationFacts`: `registration.replace(routes)` is atomic on the same adapter instance; a conflict keeps the previous routes serving and `registeredFacts` advances only once the registry holds the new set. Zero routes is the dormant bare mount.
- `registerModelDiscovery` is namespace-wide because the provider being added does not exist yet; the stored credential and deployment-owned headers come from `storedDiscoveryProfile` inside the host, so the curated UI never carries them.
- `discoverModels`: a catalog route is answered from the installed catalog (it carries context windows and output caps no listing reports). An unchosen protocol is asked as `openai-completions` because refusing would withhold the action from the case it exists for; the cost is a misleading 401 from an Anthropic gateway, hand-entry remains. A typed key wins over the stored one (it may replace the failing key); the stored resolver stays lazy so a typed key cannot fail over a credential it supersedes.
- `streamWithSnapshot`: profile, model, collection and credential come from one snapshot captured before any await, so a mid-request configuration change affects only the next call. `SDK_RETRIES_DISABLED`: the agent recovery layer owns visible attempts. `swallowAbortedSdkTeardown`: the stable signal already owns SDK termination.
- `modelInfo`: only a deployment-configured `maxTokens` is a request default; the catalog's sizes the model only.
- `credentialStoreFrom.list`: records outside `RECORD_SCOPE` are skipped; other plugins write formats pi-ai never agreed to.
- `resolveRouteModels`: `...base` spread, never enumerate; enumeration would drop reasoning spellings, compat quirks, model headers and upstream additions.
- config `modelFields`: schemastery materializes absent arrays as `[]` and absent dicts as `{}` (verified), so `input` has no default (empty reads as "no answer", the catalog applies) and `reasoningEfforts` is `union([const(false), dict])` to keep absent (inherit catalog) distinct from `false` (disable). An empty route `defaultInput` is rejected: nothing below can answer.
- `reuseCatalogProvider`: `stream`/`streamSimple` delegate through `base` so implementations holding state on themselves keep working.
- `NEVER_A_CATALOG_API`: absent replay state is foreign even when the source names this provider/model. `anthropicReportsAliasesAsModel`: Anthropic reports aliases and fallbacks as `model`, unlike Completions' informational `responseModel`.
- `registerPiAiFlows`: `recordKeyForWouldThrow` keeps a future upstream id outside the record grammar from failing the whole mount. `signInOnlyModels` is separate because login serves no requests; pi-ai persists through the shared store, making it the record's single writer.
- Each configuration resolution is an immutable snapshot (profiles plus a `Models` collection); an operation captures a whole snapshot before its first await because `Models.streamSimple()` is lazy. Credential store and auth context stay stable across snapshots.
- Catalog routes reuse the installed pi-ai provider (it owns implementations such as Bedrock's separate Smithy entry point); other routes are built by `createProvider` from a deliberately narrow protocol table (Bedrock, Vertex, Azure, Codex need environment, SigV4, or OAuth this config cannot express).
- Reasoning efforts: a model without reasoning metadata reports only `off`, which is surfaced as no capability (omitting the option is byte-identical). Describing a model never throws for a profile default it cannot take; the request path refuses. Declared `reasoningEfforts` decide every level explicitly because pi-ai defaults absent keys as supported for the five base levels but unsupported for `xhigh`/`max`.
- Discovery: catalog routes answer from the installed catalog without network; only unknown routes are interrogated (OpenAI-style bearer `GET {baseURL}/models`, Anthropic `x-api-key` + `anthropic-version` at `/v1/models`, one page, size ceiling on bytes actually read). Azure and Codex are not interrogated because guessing would report an auth failure as an empty provider. The base URL is treated as a prefix so gateway path segments survive; the probe key is validated before the header is built.
- Credential records: grants are JSON images (explicit `undefined` members dropped) because the credential store refuses unrepresentable values; reads without a credential service answer "nothing stored", writes throw `NO_CREDENTIAL_STORE`.
- Stream mapping: pi-ai flattens failures to `error.message`, so classification reads wording (size-refused bodies are invalid not transient; mid-response wire closes are truncation); pi-ai usage folds reasoning into output; empty stop is `EMPTY_RESPONSE`.
- Unknown-model defaults: text-only modality is the floor because under-claiming refuses before the message is durable while over-claiming fails mid-turn.
- `catalog.js` drift gates: the modality, thinking-level, thinking-format, cap-field and compat-field lists mirror pi-ai types; a pi-ai upgrade is reviewed against them.
