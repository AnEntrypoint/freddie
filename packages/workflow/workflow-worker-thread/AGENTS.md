# AGENTS.md — workflow-worker-thread

## Rationale

Host side (`host.js`, class `WorkerRun`):

- Constructor: `workerData` rides the structured clone; args are plain JSON by the seam contract, so the clone is total and doubles as the caller-isolation copy (a clone failure throws loud out of `start()`).
- `cancel`: a no-op once settled, once a terminal source is claimed, or once cancelled. Without the settled guard the ordinary consumer path (await result, then dispose, then cancel) would arm a grace timer nothing clears, pinning the run and its Worker until grace expires. The grace timer is `unref`'d so it never holds the process open; on expiry it closes the terminal boundary, ends stranded agent starts before settling (so ends precede `workflow/end`), then terminates the worker.
- `dispose`: claims the public transaction before invoking child/provider disposal, because a provider callback can re-enter `handle.dispose()` and must join the same promise. It reaps children independently since `cancel()` is a no-op after settlement, so a settled workflow does not wait on quiescence before starting survivors' disposals.
- `onMessage`: the first death signal is the logical delivery barrier (Node may emit `error`, then deliver an already-queued `message`, then `exit`); nothing after it may create a child, narrate after `workflow/end`, or compete with the outcome. `Phase`/`Log` narration is suppressed after cancel (messages in flight while the cancel crossed the boundary). `AgentEnd` is NOT suppressed: cancelled children report their paired agent-end with outcome `cancelled`, which with termination-path synthesis keeps one end per started child on every stop path.
- `onChildStart`: refuses after a terminal boundary; a child must never start on an already-aborted signal (a provider subscribing only to future abort events would never observe it).
- `startChild`: result forwarding is attached before the handle is published but runs in a later microtask, so `ChildStarted` posts first even for an already-settled scripted provider. `onChildDispose` acks an already-disposed child too (the worker-side wrapper awaits it).
- `onResult`: first-wins is decided when the Result reaches the host. Ownership is claimed before cleanup invokes provider disposal (which can re-enter `cancel()`), so post-result cleanup cannot rewrite the result. A non-cancelled result that crossed an in-flight cancel is reported `cancelled` (the vm `drive()` post-settle check, moved to the receiving side).
- `onWorkerDeath`: admission closes before cleanup callbacks. When death is the terminal source it claims before reaping or synthesized callbacks (either can re-enter `cancel()`): a death that arrived first stays an error, a cancellation accepted before death stays cancelled, an earlier Result/grace outcome is preserved. A queued message may precede `exit`, so the final `exit` sweep only joins/starts disposal for registry survivors and does not repeat provider cancellation.
- `post`: only a teardown race can throw (payloads are JSON); the failure is logged and dropped.

Worker side:

- `runtime.js` constructor: compile first. The host pre-parses the identical wrapper, so a syntax error is unreachable in production, but the session still maps it to an error result; `lineOffset` compensates for the wrapper line so stacks carry the script's own line numbers. Hooks are plain data properties on the context (a script overwriting its own hooks only sabotages itself).
- `runtime.js` `drive`: cancelled before the body runs (start signal aborted, relayed before `go`) means the script must not execute; cancelled while running reports `cancelled` even when the script settled without touching a hook; any failure after cancel reports `cancelled` with the canonical reason. `renderThrown` is total, so `drive()` resolving keeps the `result` never-rejects contract.
- `runtime.js` `agent`: cancel is re-checked after the concurrency acquire (the await yields at least a microtask tick), after a host start refusal (a refusal racing our own cancel reads as cancellation) and after the start round-trip (a cancel can land before the continuation; the fresh child is disposed). A rejected child result is a host-relayed infrastructure fault, distinct from a child that failed and resolved: the lifecycle is paired, then FATAL propagates, since an ordinary throw would dissolve to a per-item `null` in the combinators. A completed run without `structured` after an honored `outputSchema` is a child failure. A cancelled RUN kills the script; a child that failed for its own reasons resolves `null` (scripts `.filter(Boolean)` per the CC contract).
- `runtime.js` `parallel`/`pipeline`: hook failures are `WorkflowError`s built outside the script's realm and fatality is recognized by `instanceof` against this realm's class, so a script-built object cannot forge it. An ordinary stage throw drops the ITEM to `null` and skips its remaining stages; a fatal error kills the whole script.
- `realm.js`: `renderThrown` is total (a throwing accessor/`toString` falls back to a fixed label). A property read that runs script code is converted to `MaterializeError`. Arrays with own non-index properties are rejected because JSON would silently drop them. Copies use `defineProperty` so a `__proto__` key becomes an own data property, and `Object.keys` matches `JSON.stringify`'s property selection.
- `session.js`: a child's settled promise gets a no-op consumer because an unconsumed rejection after a failed start or teardown would kill the worker. A cancel doubles as the gate release: `drive()` checks the cancelled state before the body, so the script never executes.
- `index.js` `assertBodyParses`: parse only; the script object is discarded. `start` captures `ctx.subagents` while the call is still traced through the holder: Cordis strips the engine-provider shadow when the handle returns, so re-resolving later would walk the inactive engine fiber after an HMR unload and break the seam's holder-owned lifetime. `workflow/end` carries outcome data only; the value stays with the holder.
- `worker.js`: `workerData` is untyped at the `node:worker_threads` boundary; the engine is the only spawner and always supplies a `WorkerInit` shape.

- Worker child handles expose session identity, a settled outcome, and awaitable disposal over RPC; child Agents stay on the host. Infrastructure rejection of a result retains the fatal workflow distinction.
