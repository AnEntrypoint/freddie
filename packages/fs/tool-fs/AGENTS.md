# @freddie/freddie-tool-fs

## Rationale

- `read_image` is composition-conditional: without a mounted attachment store the deployment cannot durably commit image bytes, so the tool never registers (execute keeps a defensive re-check for direct callers). Every gate runs before any filesystem I/O so a refusal never leaks partial reads or attachment writes; the image is persisted before returning so the block references a durable object when the tool/result event is appended. Dimension refusals stay recoverable tool errors so an oversized image never enters durable history (it would ride every later request past provider dimension rejections).
- `edit`/`write`: the per-call sandbox policy (approved mode, then session override, then backend default, plus the session cwd root) is resolved before anything executes; the mutation is a single-slot decision from the policy plugin (`{ version }`, `createIfAbsent`/`replaceIfVersion`, or `FS_NOT_OBSERVED`), and the bare default is an unconditional mutation with no stat. Sandbox denials map to the shared `[sandbox: ...]` marker (recognized from bash); stale/not-observed failures get a model-facing remedy.
- `read`: an observation race fails closed because guarded mutations re-check the version in-lock; a read makes one stat (absence, type and size routing, present version) and streams when the file is large or size is unknown. The structured line window is persisted into `meta` (the raw output object is not on the wire) so the read card survives replay; result-time presentation declines to `undefined` on malformed or obsolete meta.
- `read-render.js` extension lookup is own-property only: `foo.constructor`/`foo.__proto__` must map to no language, or a function would reach `lang` and fail tool-output validation.
- `presentCall` for `edit` uses `oldText: old_string || null` to match claude-agent-acp's Edit arm; a call-time `write` presenter cannot see prior content, so `oldText: null` also stands for an overwrite, and the result-time card repeats the diff because completed views replace the pending view.
- `read` and `read_image` share `read-target.js`: a directory error inlines a shallow, name-sorted listing (dotfiles and `node_modules` skipped) so the model recovers in the same turn. Read caps (line, char, byte, window) must be positive integers or windowing misbehaves silently. Window scanning caps the current line so one newline-free giant line cannot grow memory.
- `read_image` gate is stricter than host upload preflight: the exact routed provider/model must declare `image` input explicitly, unknown capability refuses. Downscaled reads report on-disk dimensions and the multiplier back to original coordinates. Magic-byte validation at the attachment service stays authoritative over the extension check.
- Session cwd for tools is `exec.agent.session.header.cwd`; non-agent calls return `undefined` so the backend applies its own default, never `process.cwd()` at the tool boundary. `write` allows empty `content`; `edit` rejects `old_string === new_string`.
- Replayed `meta` narrowing (read window: 1-based integer offset, non-negative `totalLines`, strictly increasing line numbers, none above `totalLines`; diffs: non-empty) declines to `undefined` for the generic card. Diffs are one three-line-context card per applied hunk; pure insertions use `oldText: null`.
- `FS_STALE_VERSION` and `FS_NOT_OBSERVED` get a model-facing remedy (re-read / read) appended at this boundary with code preserved and the original chained as `cause`; provider messages stay machine-oriented. A sandbox denial keeps its structured code because `ToolRuntime` fills `result.error` only for `HarnessError` instances.
