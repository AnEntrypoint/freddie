# @freddie/freddie-fs-local

## Rationale

- `fsio.js` target keys: a file's own `realpath` wins (a symlinked file resolves to its target); an absent file resolves the nearest existing ancestor and re-appends the missing suffix so the key is stable across creation of those directories. A path through a regular file (`afile/child.txt`) can never exist, so it maps to the structured taxonomy, not raw `ENOTDIR`; on Windows `realpath` reports `ENOENT` for that case, so the ancestor is stat-ed to restore the distinction. `ENOENT`/`ENOTDIR` both mean absent, other metadata failures are real faults.
- `DIFF_BASIS_READ_CHUNK_BYTES` bounds each non-abortable `FileHandle.read` so cancellation is observed between chunks. The basis buffer holds `size + 1` bytes: the extra byte detects growth after stat without retaining per-read buffers; the bounded reader checks the opened file itself so an external replacement after `probe()` cannot cause an unbounded allocation. A descriptor-phase errno costs only the optional basis (`before: null`, consumers fall back to whole-file); a committed write never fails for a presentation-only pre-read, but cancellation (`FsError`) still propagates.
- Hard-link creation: link errno values vary by platform and filesystem, so after a failure the target entry is inspected to tell a collision from missing hard-link support.
- Windows overwrite: if the observed target vanishes during staging, the protected DACL already copied to the temp file stays authoritative for recreation. After the commit, owner-only staging residue cannot turn the write into a failure.
- Guarded writes and edits check the stale guard first: an edit based on an old read reports `FS_STALE_VERSION`, not `FS_EDIT_NOT_FOUND`/`FS_AMBIGUOUS_EDIT` against newer content, and a missing target uses the same code on guarded and unconditional paths. `createIfAbsent` onto an existing file is refused (a blind overwrite needs a read first). No expectation means an unconditional but still atomic write; an unconditional edit still runs read, match and write inside the per-target lock.
- `before`/`after` diff texts are LF-normalized so a CRLF overwrite does not read as every line changed; line-ending restoration is a storage detail the applied-hunk diff ignores.
