# @freddie/freddie-tool-fs-search

## Rationale

- `glob.js` excludes each VCS name with two negated globs: the bare form prunes the directory during traversal, the `/**` form still excludes contents when the search root is at or inside that directory (where the bare form, matched against root-prefixed paths, never fires).
- A glob result that fits under `maxResults` is shown whole in modification-time order (the tool's contract, which answers age questions).
- `grep.js` spill artifact holds the complete result (previewed per line, no inline cap) so the recovery file is the full search; `saveText` failures are best-effort: they never fail the search or hide the inline result, the footer reports the unsaved remainder.
- `search-core.js`: `spawn()` can throw synchronously (NUL in argv, abort between the check and the call, platform-package resolution), so the abort re-check after the catch is real despite static narrowing.
- Spawn-backed, not a `ctx.fs` method: tools run the packaged `@vscode/ripgrep` binary through `ctx.subprocess.spawn()` with fixed argv templates (never `ctx.shell`, no shell quoting, no background task). Model values are plain argv elements, patterns in `--flag=value` form and targets behind `--`. `--no-config` is always prepended because the spawn is unconfined and `RIPGREP_CONFIG_PATH` could inject `--pre`. A single-file runtime uses the executable `-rg` sidecar (pkg cannot spawn from its virtual filesystem); resolution is lazy so a missing binary fails the first search as `SEARCH_FAILED`, not Loader composition. Returned paths are workdir-relative and follow-up-readable only where workdir and `read` root are the same workspace (documented v1 requirement, unchecked).
- Exit 0 is results, exit 1 is zero results, else `SearchError`: abort/timeout `SEARCH_ABORTED`, bad regex/glob `SEARCH_INVALID_PATTERN`, launch/parse failure `SEARCH_FAILED`, stdout over `rawOutputMaxBytes` or still truncated `SEARCH_RAW_OUTPUT_OVERFLOW`. Raw stdout is an internal transport, parsed whole in memory, never spilled; the recovery artifact is the formatted result via optional `ctx.spillStore.saveText()`.
- `grep` parses `rg --json` NDJSON (no colon splitting); a non-UTF-8 line gets a placeholder preview, malformed records fail the search. `include` must be one positive glob (no `!`, no comma list outside braces); `pattern` may be whitespace but not empty.
- Search card `meta` is persisted with the session log and re-sent each request, and `freddie-spill-policy` shrinks only `content`, so `capMetaBytes` (default 64 KiB) drops trailing groups/paths and marks `truncated`; `total` is preserved and a single oversized item is kept rather than emptying the card. A zero-result meta is a valid empty card. Text and card use the same retained items so both agree on what survived the cap.
- Over-cap `glob` sampling (when `sampleOverCapGlobResults`) is round-robin across top-level entries; absolute paths outside the workdir group by their first real segment.
