# freddie-acp

## Rationale

- `turnEndToStopReason` (`src/codec.js`): `cancelled` is reserved for explicit client cancellation (`interrupted`, `session/cancel`) and disposal, both settled out of band via `cancelRequested`. A turn `aborted` by a hook or another owner is ordinary quiescence and reports `end_turn`.
- `apply` (`src/index.js`): ACP handlers run outside the plugin's injection scope, so `ctx.agents` and `ctx.logger` are captured during apply, never read lazily inside a callback.
- `settleAfterQuiescence`: `session/event` enqueues output synchronously before the agent goes idle, so reading `record.outputTail` after `whenIdle()` includes every committed output task. `max-tokens` and other non-terminal endings are not prompt-level stop reasons; they settle as `end_turn`.
- `session/event` handler: only committed assistant text/images reach the wire; raw chunks, reasoning, tools, plans, titles and retry markers are presentation or trace data and stay off the automation channel. One per-session chain (`outputTail`) keeps block and message order across asynchronous attachment reads.
- Error contract: `assistantBlockToAcp`, the admission codec and the same-process agent seam always throw `Error` values, so `outputError` and `admissionFailure.message` are read without narrowing.
- `approval/request`: a machine policy channel for ACP clients such as freddie-subagent-acp. Only one-shot options (`allow-once`, `reject-once`) are offered and an unknown client response never becomes a durable grant.
- `initialize`: single-version agent; the spec's "same version if supported, else the latest supported" both resolve to `PROTOCOL_VERSION`.
- `newSession`: no preset composition. The ACP bundle keeps model-facing rows in the host plane, so this agent reads them from the global layer; a deployment that configures a roster must join one here first (`@freddie/freddie-agent-presets` README, "Composing a child agent").
- `prompt`: the one-prompt slot (`record.inflight`) is reserved before the first asynchronous route or attachment operation, so concurrent prompts and cancel see admission as in flight. Agent liveness is checked before admission (no rich content persisted for a retired destination) and after it (an agent-loop reload may race storage). No await may separate the final `throwIfAborted` from `followup`: a cancel that wins admission must never enqueue a late turn. A synchronous `followup` throw resets `messageQueued` so error mapping sees the pre-operation boundary.
- `cancel`: admission is not Agent work. Unrelated producers are preserved until this prompt is in the durable inbox (`messageQueued`); with no prompt, cancel targets autonomous work on the addressed Agent.
- `quiesce`: cancel the bridge's own work before any await, because a descendant drain can block on persistence or scoped cleanup while top-level agents keep running model and tool calls. Teardown keeps the prompt boundary: a rich admission already writing stops before its slot settles, and committed output conversions drain while attachment services are still available. Continuable subagents outlive their turn and their Activations own descendant teardown, so only these sessions' forests are drained child-first BEFORE the top-level agents are disposed (no descendant holds a released runtime; other frontends sharing the Context stay live). `ctx.get('subagents')` is read structurally so this package does not depend on the subagent package.
- Teardown `AggregateError`: the production consumer logs it through `String`, which renders only the message, so every per-session diagnostic (nested causes, aggregate members) is embedded in the message via `errorChain`.
