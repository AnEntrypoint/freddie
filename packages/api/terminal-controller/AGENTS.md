# @freddie/freddie-terminal-controller

## Known gaps

- **Browser consumer: none, and none can be built on these endpoints yet.** Nothing in `packages/client/**` or `packages/extensions/**` calls the `terminal` namespace or `ctx.webTerminals`. The only terminal surfaces the page has are `TerminalBlock` in `ui-primitives` (ANSI output blocks for tool results) and the runtime's read-only mirror of agent-owned PTY output from `terminal/activity` mux frames. The seven endpoints (`environment`, `shells`, `list`, `create`, `write`, `resize`, `close`) start, type into, resize and close a shell, but none returns output: `retain` and `follow` are unported, `TerminalController` does not inject `remoteStream`, and so a UI over them could send keystrokes and never show a screen. An interactive terminal needs, in order: `follow` moved onto the `remote-stream` carrier with a frame schema (as `session-controller/src/frames.js` does for `session/follow`); a screen renderer (upstream `ui-sidebar-terminal` uses xterm.js and its fit addon, a new vendored browser dependency that needs owner approval and a supply-chain scan first); and a place to mount it (freddie has no right sidebar, only the `conversation.view` ring and the single `details` column, so upstream's tab-per-terminal model needs the tab host the client capability audit ranks as a separate port).
- The package therefore declares no `freddie.client` entry, and `./client` (`ctx.webTerminals`) is a library export for a Client assembly that supplies the missing stream and a renderer. `packages/api/remotes` mounts only the `./remote` namespace in the page, which is inert: every `terminal.*` method is pinned to loopback in `packages/client/connection` (`HOST_SHELL`), because a shell runs with the Host user's own permissions, so a trusted-host browser gets 403 from them regardless.
- Upstream `ui-sidebar-terminal` is absent from upstream's `packages/client/README.md` package table, so the table-derived client capability audit did not classify it.

## Design notes

- Client remote descriptors carry no `scope`: a scoped descriptor resolves its Agent from the calling Client Context, so every endpoint takes the Session id as an argument and the Host looks the Agent up.
- Shell discovery omits a candidate that fails to resolve: the subprocess provider reports a lookup miss as a plain Error, indistinguishable from a transport failure.
