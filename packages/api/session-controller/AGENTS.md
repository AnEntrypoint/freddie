# @freddie/freddie-session-controller

## Rationale

- `list-codecs.js` holds the one `session/list` row codec and both manifests import it: the row is a wire contract shared by two faces, and the earlier pair of hand-copied schemas both lacked the freddie-only fields. Every field is optional except the dsh five, so a strict parse of a legacy `session.list` row succeeds and strips nothing.
- The row carries every field the legacy `session.list` row (`packages/host/apiproxy`) carries. `errored` reads the `sessionListMetadata` projection the apiproxy registers, gated on `!running` like the legacy fold. A deployment with no apiproxy has no such unit, so the row answers `errored: false` rather than inventing a second fold.
- `agentPreset` calls `resolveSessionPreset` from `@freddie/freddie-agent-presets`, the function the legacy producer calls, and no injected service replaces it: `AgentPresets` exposes no per-session accessor, and `composedPreset(agentCtx)` reads the live scope chain, which a cold or foreign row has no agent to supply. The package is a `peerDependencies` entry, like the siblings that import it. An attached row resolves against its event log (a blank session may have switched preset, and the newest `agent-preset/selected` wins); a cold or foreign row resolves against its header, because listing must not read logs.
- Foreign rows come from `ctx.get('sessionPersistence')` (`extraRoots`, `listForeign`), so the controller takes no dependency edge on the JSONL backend. A foreign row is `readOnly: true` with `extraHome`, never shadows an id already listed, needs a `cwd`, and a root that fails to list is skipped with a warning so one stale mount never hides the primary corpus.
- A cold row settles on a cached `blank: false`; any other cache state (a miss, a cached `blank: true`, a row cached before `errored` existed) falls back to a bounded log probe folded through the projection registry's own `sessionListMetadata` unit, so the fold is never duplicated. The bound is `coldBlankProbeMaxBytes`, read from the apiproxy service (default 1024 bytes when it is absent; 0 disables). A probe that cannot run leaves the row visible, never hidden. Without the probe, a session killed before its projection cache row was written listed `blank: false` here while the legacy list said `blank: true` (witnessed live).
- `api-session/status` carries `errored` as a third argument and the Client model applies it in `setRunning`, because the roster row would otherwise keep the `errored` value it was listed with after the next turn ends. A Client that sends or receives only two arguments keeps the row's value.
- `frames.js` carries no list row: the `session/control` frames move projection values, so `errored` already rides them inside `sessionListMetadata`.

## Known gaps

- **Browser consumer: none, by design.** The web page drives sessions through the legacy `/api/session.*` routes and the `events.mux` channel (`packages/client/runtime` `SessionManager`, classified SAME as upstream `ui-session` in the client capability audit). That path already covers what a browser needs: list, history pages, prompt and cancel, and live events for every attached session. This package's Typert route serves out-of-process Clients (an SDK, a second frontend, a CLI) and the eight command verbs and `follow`/`control` streams are for them. The package therefore declares no `freddie.client` entry, `packages/api/remotes` does not list its `./remote` export among the browser externals, and no UI package reads `ctx.sessionModel`. Add a `freddie.client` entry only for a browser feature the legacy path cannot serve, such as a second live view of a session that cannot ride the mux.
- The `session.*` methods are unpinned by decision in `packages/client/connection`, so a browser on a trusted host may call them; nothing in the shipped page does.
