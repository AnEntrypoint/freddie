# AGENTS.md — Repository scripts

Gate scripts invoke pnpm shell-free, normalize repository-relative glob paths to `/` at ingestion, and keep platform adaptation in the gate that needs it instead of a shared platform layer.

## Rationale

- `gen-third-party-notices.js` `INSTALLED_PACKAGE_STORES`: workspace-local link farms (`native/landlock-run/node_modules`) can expose a dependency that is not linked at the repository root; both stores are backed by the root lockfile.
- `publish-npm-baseline.js` `WorkspacePackageSet.discover`: every published package, vendored `framework/` included, must be `@freddie/`-scoped so publication never carries an upstream name that would squat it on the registry.
- `release/bump.js` `planShared`: the root manifest carries the freddie family version too. `publish-npm-baseline.js` rejects any non-vendored member whose version differs from the root's.
- `patch-if-npm.mjs`: pnpm applies `patches/*@<version>.patch` itself before any lifecycle script, so patch-package on top would re-apply an already-patched file and fail; the postinstall hook runs it (over the same diffs, copied as `<name>+<version>.patch`) only for npm and yarn.
- `publint-all.js`: the packed-file view uses `readdirSync`, not `globSync`, because `**/*` skips dot-prefixed segments while `npm pack` publishes dotfiles inside included directories.
- `release/families.js` `publishOrder`: install edges are checked acyclic on their own graph (a peer edge into an install edge would otherwise read as a cycle). The order is then emitted over both edge kinds, dropping a peer edge when the peer is already on the stack or installs the declaring member. A cycle mixing both kinds can still emit a consumer before something it installs and nothing downstream detects that, so the emitted order is verified against the edges it must honour. `FreddieFamily` has no build-artifact gate: every package ships `src/` as authored, so the base no-op `verifyBuildArtifacts` applies.
- `release/process.js` `attemptEchoed`: streams are piped and echoed because `'inherit'` would leave nothing to capture.
- `release/publish.js` `publishTarball`: passes no `--access`; the sequences do not share one access level, so a flag would override the manifest that decides it (each package's own `publishConfig.access` field; no script checks it against the family).
- `release/verify.js`: the publish order is resolved before the build so an install-edge cycle surfaces at the first gate, not while pack is writing tarballs.
- `release/verify-packed-install.js`: installs with `--omit=optional` because the Landlock platform packages need a musl toolchain and one build per architecture, and a consumer that cannot install them must still start. Their entry package is a plain dependency of `sandbox-local`, so its tarball arrives through `--from`.
- `rescope-vendor.js` `GENERIC_SKIPS`: files where a bare upstream name is product data, not a package reference: `Symbol.for('schemastery')` and the `vendor:` field (upstream identifiers); `cordis` as an agent-preset id (renaming it changed which preset the creator flow stages and which id the roster reports; the preset's prompt names it to the model); `cordis/*` extensions event domain and wire id (catalogs, producers, consumers, generated typert descriptors); the `cordis` UI locale namespace and input-trigger source id.
- `rescope-vendor.js` `excluded`: the script itself, `.agents/notes/` (records of what was true when written), `scripts/snapshots/` (recorded model payloads quoting documentation verbatim), `docs/rescope.md` (states both names on purpose), `pnpm-lock.yaml` (regenerated by `pnpm install`), framework `LICENSE` files (legal artifacts; package READMEs follow the rename). `POSTCONDITIONS` / `EXACT_EDITS`: the framework README divergence log owns its `@freddie` scope entry (deletion or duplication is rejected); the `pnpm-release-age` edit drops `minimumReleaseAgeExclude` rows because rescoped packages are never fetched from a registry. Exact edits are all classified before anything is written (a half-applied tree is worse than an untouched one) and each write re-reads its file because two edits can target one file.
- `pnpm-workspace.yaml` `packages`: `native/landlock-run` is developed with its harness consumers but keeps its native build and publication scripts; `apps/*` are product assemblies (`apps/cli` owns the `freddie` bin); `examples` is ONE member so every leaf's `cordis.yml` resolves plugins by walking up to `examples/node_modules`, for dependency resolution only. `linkWorkspacePackages`: `framework/` packages keep the semver ranges they inherited, so those names must resolve to this workspace's copies.
- `pnpm-workspace.yaml` `overrides`: the floors for `dompurify`, `hono`, `@hono/node-server`, `brace-expansion`, `protobufjs`, `qs`, `undici`, `ip-address` and `fast-uri` are security patches for transitive dependencies several levels deep behind third-party packages (mermaid, `@modelcontextprotocol/sdk`, e2b, express-rate-limit, glob); each resolves to one version across the tree, so forcing the patched version is a plain bump. `fast-uri` needs `>=4.1.4`: v4.x forked from v3.1.2 and never merged v3.1.6's fix forward, so an older `>=3.1.4` floor missed the vulnerable v4.x range (host confusion via skipped IDN canonicalization; SSRF via hostname percent-decoding; GHSA-qw65-cvwx-89v3, GHSA-58mr-gqgx-xq4g).
- `pnpm-workspace.yaml` `allowBuilds`: pnpm 10+ makes an unlisted install/build script a hard install error, so every such package is listed and the default is deny. Allowed: `esbuild` (native binary), `node-pty` (persistent PTY backend, ConPTY on Windows), `koffi` (`MoveFileExW` write-through publication for JSONL durability on Windows), `libsql-plugkit-client` (postinstall downloads `plugkit.wasm`, ~12MB, from AnEntrypoint/plugkit-bin Releases; no native compile). Denied: `@google/genai` (transitive of `llm-pi-ai`'s pi-ai; its `prepare` is Google's own build step and only the published dist is imported), `protobufjs`, `node-addon-require-builtin`.
- `check-expected-filenames.sh` excludes `framework/**` from the golden-filename policy.
- `prepare-ci-bubblewrap.sh`: Ubuntu's package transaction scans the hosted image's full dpkg database and runs post-install hooks; CI needs only the signed-archive payload, so the pinned `.deb` is checksum-verified and extracted into the ephemeral runner directory.
- `gen-third-party-notices.js`: SPDX evaluation fails closed (`OR` needs one permissive alternative, `AND` needs all; unknown identifiers are non-permissive). `DEV_ONLY_AREAS` (root tooling, test infrastructure, docs site, demo leaves, launcher build workspace) never reach a user; a runtime declaration anywhere else is disclosure-relevant because any plugin package can be mounted from a user's `cordis.yml`. pnpm 11 truncates long virtual-store names to `<prefix>_<hash>`, so `virtualManifest` falls back to a content scan when the prefix scan misses. Workspace globs come from the workspace declarations and are normalized to `/` because `fs.globSync` returns native separators. The CLI entry is guarded so importing the module neither regenerates the file nor exits. Tier policy: `.agents/notes/implemented/process/2026-07-30-generated-third-party-notices.md`.
- `release/*.js` scripts are commands and importable modules (`isEntry` guards `main()`). Rationale: `.agents/notes/implemented/process/2026-08-10-npm-release-sequences.md`. Pack runs without credentials and produces every tarball from one commit; publish uses exactly those bytes, in recorded order, so an interrupted run leaves a self-consistent prefix. Install edges are honored absolutely; peer edges order what they can and are dropped (and reported) when they would deadlock, since sibling packages declare each other as peers and npm treats an unmet peer as a warning.
- `release/bump.js`: git's `--sort=v:refname` places `4.0.1-rc.1` above `4.0.1`, so semver precedence is compared here. A vendored package's baseline is the higher of its manifest and last tagged version because a vendor re-sync restores the lower upstream version. A prerelease does not consume its release numbers (`4.0.1-rc.1` leaves `4.0.1` free). `BUILD_INPUTS` cover packages whose `files` select untracked `lib/` output, where a source change alters the tarball with no published path in the diff.
- `release/publish.js`: retries only registry writes that did not settle (`E409 Failed to save packument`); a rejected payload (`E403`, malformed manifest) never clears on retry. Every retry re-reads the registry first because `E409` can answer a write that landed, and republishing an existing version fails permanently. Same integrity is skipped; differing integrity fails (content changed without a version bump).
- `release/process.js` `attemptEchoed`: `spawnSync` returns after exit, so output is not live and stdout is echoed before stderr (npm's `+ name@version` confirmation appears before its `npm notice` lines).
- `release/families.js`: the vendored family accepts `src` and declaration maps in payloads because its manifests export `./src/*`; the harness policy in `publication-payload.js` (no source or map members, since a published map resolves nothing) does not apply. `verify-packed-install.js` reads tarballs by directory contents, not an order file, since a directory may hold cross-sequence tarballs, and installs the vendored family's pack output too so verification does not depend on registry versions.
- `test-fixture-cleanup.js`: fixtures junction the real `scripts/`, `node_modules` and tsx directories; Windows recursive deletion follows MOUNT_POINT junctions into their targets, so links are unlinked first. Removal retries 50 x 200 ms because Windows releases child and antivirus handles asynchronously (EPERM under load).
- `migrate-packed-session-fixtures.js` is a temporary branch-convergence command; removal is proposed in `.agents/notes/proposed/process/2026-07-26-remove-packed-session-fixture-migrator.md`.
- `rescope-vendor.js`: the generic pass rewrites only delimited complete package-name tokens (a quote or `name: ` immediately left and the matching quote, optionally after `/subpath`, immediately right), which excludes `cordis.yml`, the Loader's `cordis:` prefix and `cordis-config-entry`, and keeps it idempotent. Markdown fences always follow the rename; prose only under `docs/`. Each `EXACT_EDITS` `find` is written against pre-rename text because exact edits run before the generic pass. An edit state is `pending`, `applied` or `invalid` (partial, moved or duplicated).
