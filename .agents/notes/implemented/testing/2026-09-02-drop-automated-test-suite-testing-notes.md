Status: implemented

## Problem

The [buildless-workspace decision](../architecture/2026-09-02-buildless-workspace-no-transformation-at-launch.md) removed the entire vitest-based automated test suite in full: every `tests/**`/`test/**` directory repo-wide, `docs/testing.md`, `vitest.config.ts` and every `vitest.*.config.ts` variant, the coverage gate (`test:coverage`, `test:coverage:partitioned`, `scripts/coverage-partitions.ts`, `scripts/coverage-uncovered-locations.cjs`, `scripts/coverage-exempt.ts`), the `dsh-llm-replay`/`dsh-acp-snapshot` snapshot tiers, the keyless web browser e2e lane and its required CI gate, the real-API e2e CI workflow, and the `dsh-llm-mock-server` support package. This repo's testing policy is now "no automated test suite — verify live," recorded in that architecture note.

## Decision

The 14 `implemented/testing/` notes and the 4 `implemented/process/` coverage/GUI-testing notes above are consolidated into this note and their files deleted, **except** the three noted below as partially superseded, which are edited in place instead (vitest mechanics stripped, surviving product/architecture facts kept, pointer added here) and NOT deleted:

- `2026-06-22-fork-child-replay-seed-boundary.md` — kept: `seedLength`/`seed_length` is a real, currently-shipped `SessionHeader` field and SQLite schema column (schema version 4), still read and written by `dsh-session`'s fork API (`packages/session/session-persistence-jsonl/src/format.js`, `packages/session/session-persistence-sqlite/src/schema.js`) independent of any test harness.
- `2026-06-22-subagent-snapshot-replay.md` — kept: `GenerateOptions.sessionId` is a real, currently-shipped core API field (`packages/llm/llm/src/index.js` and 30+ other live source files), used for request routing/telemetry beyond replay.
- `2026-08-03-opt-in-reasoning-chunk-browser-stress.md` — kept: `Notifier.markFrameDirty()`'s rAF-coalesced publication architecture is real, currently-shipped client code (`packages/client/runtime/src/client/sessions/notifier.js`, `session.js`).

All 18 originals described the vitest suite, coverage gate, or browser lane as present-tense shipped reality; none of that machinery exists in this checkout any longer (confirmed: no `vitest.config.ts` under this repo, no `scripts/coverage-partitions.ts`, no `dsh-llm-mock-server` package, no `apps/web/tests/`).

## Alternatives considered

**Keep the notes as historical record without consolidating.** Rejected: all 18 described present-tense shipped reality for systems with zero remaining code or config in this checkout (except the three narrow product facts pulled out above). Leaving them active misrepresents current behavior to any future reader.

**Archive instead of delete.** Rejected: most of the 18 notes are narrow implementation detail of specific vitest/Playwright/istanbul mechanics (exact CLI flags, CI job wiring, fixture file layouts) with no future decision value once the tooling itself is gone — closer to "completed testing machinery" than a durable boundary rule. The few genuinely reusable facts (below) are folded into this note's Consequences instead, per the consolidation rule's requirement to preserve unique rationale before deletion.

**Delete outright with no consolidating note.** Rejected: several of the 18 notes recorded evaluated, non-obvious lessons (a real BlockAssembler bug found by property testing; a documented security threat model for CI secrets; measured coverage-partitioning tuning data) that would otherwise be lost to git history alone, which the consolidation rule forbids relying on as the sole copy of rationale.

## Consequences

- If a regression test discipline returns, these evaluated techniques and findings remain worth re-reading rather than rediscovering:
  - **Property-based testing found a real bug on its first run**: a `fast-check`-driven arbitrary-chunk-stream suite over BlockAssembler caught a duplicate-`block-end`-at-the-same-index bug that had survived 100% line coverage of the happy paths — evidence that per-file line coverage does not prove interleaving correctness for protocol-shaped code (chunk streams, event logs, schema conversion, inbox scheduling). Generator quality (biasing toward small index pools and short strings to force collisions) was the value lever, and a property flake from a timeout was correctly treated as a real defect rather than something to retry away.
  - **Record real fixtures from the actual product, don't hand-author mocks.** The snapshot tier's fixtures were harvested from real recorded `session.jsonl` logs rather than hand-built mock chunk scripts, so the same artifact served as both replay input and behavioral expected output — a hand-authored fixture format was explicitly rejected because it would not be "a genuine product of the system." The web e2e lane made the same choice (session-log-as-fixture) after surveying LibreChat, ai-chatbot/AI SDK, lobe-chat, open-webui, OpenHands, Chainlit, continue, cline, and langfuse: the dominant proven architecture for apps owning their own backend is an in-process fake/replay model behind the real backend contract with everything downstream real; browser-level SSE interception (`page.route`) cannot exercise incremental rendering because `route.fulfill` cannot stream (playwright#33564), and real-model browser tests rot in CI (open-webui's suite grew to 120-second timeouts before being deleted).
  - **A secret-bearing CI job must be a separate workflow file from the keyless default gate**, so the always-green, forkable, no-secret gate's trigger and credential policy never couples to one that needs a repo secret. The real-API e2e note recorded a full threat model worth re-deriving from if live-API CI returns: GitHub withholds secrets from `pull_request`-triggered fork and Dependabot runs (the real boundary — a job-level `if:` skip is UX, not the security boundary); anyone with push/write access can already exfiltrate any repo secret via a workflow, so "everyone who can open a PR can steal the key" is false — only the write-access set can, and could already steal any secret; `pull_request_target` combined with untrusted fork code and secrets is the catastrophic footgun to never introduce; going public requires assuming exposure and rotating, since logs become world-readable and fork-PR-approval gating is not the same as withholding the secret from an approved run.
  - **A red coverage or long-running CI signal should degrade gracefully into an actionable location, not a discovery exercise.** The istanbul custom-reporter note is a reusable technique independent of any coverage gate's continued existence: `ReportBase` subclasses can emit clickable per-line/per-column uncovered-location records instead of forcing a local HTML-report rerun; report generation runs before threshold validation, so records land right above the failure lines.
  - **Measured coverage-partitioning tuning data**, useful as a starting point if per-file coverage instrumentation returns: native Windows single-worker-per-partition parallelism avoided worker loss and Node 24 CJS lexer failures seen at higher in-process fan-out; 2 partitions measured ~405s on Windows, 8 partitions ~112-122s, but 16-way was rejected as pushing peak concurrent execution units too high alongside build and other gates on a 16-core runner; Linux 2-partition measured ~277-282s (halving the ordinary path's 4-way instrumented worker fan-out) versus 4-partition restoring it. Heavy suites that solely perform whole-workspace compiler analysis or drive subprocess fixtures contributed zero unique coverage data when instrumented (verified by audit, not assumption) — a useful category to recheck before assuming a new heavy suite needs coverage instrumentation.
  - **A scriptable wire-fault server is the right tool for socket-level fault injection that mock/interception libraries cannot express.** `msw`-style in-process interception cannot simulate socket destroy, mid-SSE disconnect, stall, or pre-listen connection refusal for a real HTTP adapter and subprocess — those require an actual listening server. If wire-fault testing returns, an importable Node HTTP server (OpenAI-compatible endpoint shape, one explicit scripted behavior consumed per request, fail-loud on script exhaustion, a `random` weighted-selection mode with a logged reproducible seed) is a validated design; it revealed (not decided) that clean partial EOF is not retried under the retry package's existing default policy, distinct from connection reset/refusal/idle-timeout/valid-empty-completion which do recover.
  - **The three-tier GUI test-structure cut (protocol isomorphism in Node / object-layer state-machine orchestration with programmable fakes and deferreds / assembled-presentation semantic snapshots through the real loader)** is a reusable general shape for testing a multi-environment GUI stack (Node host, data-protocol layer, browser object layer, React/DOM), independent of vitest specifically: each tier tests only its own layer, and upper tiers never re-test lower ones.
  - **Browser determinism barriers, if browser testing returns**: `networkidle` never resolves while an SSE stream is open, so it is unusable as a completion barrier; polling persistence files as a completion/durability barrier is slow on NFS and superseded by an explicit host-side idle signal; a single-shot DOM sample race-conditions against streaming because any hop from data-yield to React commit can coalesce chunks — streaming incrementality must be asserted from the authoritative persisted event log, not sampled DOM state.
  - **Coverage-fixture and snapshot-fixture format lessons, if a snapshot-comparison tier returns**: separating the "durable persisted format" from "committed test fixture projection" (the envelope-projection note explicitly kept runtime JSONL persistence unchanged while only test-committed snapshot rows omitted `seq`/`time` envelope fields) avoids conflating a reviewable-diff concern with a wire-format decision.
- Any future re-introduction of automated testing infrastructure in this repo starts from a clean slate architecturally (buildless plain JS, no `tsx`/`vite-tsconfig-paths`) — see [buildless-workspace-no-transformation-at-launch](../architecture/2026-09-02-buildless-workspace-no-transformation-at-launch.md) for why there is currently no test to verify any of the above, and why verification is exhaustive live execution in the same change as the work instead.
- The three partially-superseded notes above remain active with their vitest-specific mechanics stripped and a pointer to this note.
