# Agent Note: the three dsh Remote controller packages — job, session, terminal

Status: implemented

## Problem

freddie had already ported dsh's Remote *transport* — `packages/api/remotes` (BFF policy and lookup), `packages/api/gateway` (the Typert host dispatcher and the Client Remote endpoint), `packages/client/connection`, `packages/host/webserver`, with `packages/host/apiproxy` as the legacy fallback — but none of the *controller* packages that own the business behavior behind that transport. dsh's `packages/api/README.md` table names the three this pass ports:

| dsh package | role | ctx key |
|---|---|---|
| `job-controller` | Streams one background job's observation record to the Client | `ctx.jobController` / `ctx.remote.job` |
| `session-controller` | Owns Session commands, history streams, live control state, and Agent/Session identity policy | `ctx.sessionController` / `ctx.remote.session` |
| `terminal-controller` | Session-owned interactive shells, screen recovery and browser terminal control | `ctx.terminalController` / `ctx.remote.terminal` |

The gate the task set before any code: dsh's controllers might need artifacts generated by `packages/typert/generator`, which freddie does not ship (it is a build-step codegen tool and freddie is buildless). If they did, the instruction was to stop and report rather than hand-fabricate generated code.

## Decision — the typert/generator verdict

**Not required at runtime; the port proceeded.** Evidence, all read from the real upstream source through gm `fetch`:

- Every dsh controller `package.json` declares `"./typert": "./lib/typert.host.js"` and `"./remote": "./lib/typert.remote-client.js"` in `exports` and lists both under `files`, while `src/` contains **no** such file and the package owns a `tsdown.config.ts`. Those two files are build outputs; `job-controller/tsdown.config.ts` is `clientBundle('@deepseek-ai/dsh-api-job-controller', ['lib/types/index.js'], { hostPhase: true })`.
- No controller *source* file imports a generated artifact at runtime. The only references are type-only: `import type {} from '@deepseek-ai/dsh-api-job-controller/remote'` (job client entry) and `import type {} from '@deepseek-ai/dsh-typert-registry'` / `.../typert-protocol` (session agent, terminal types).
- dsh's own `packages/typert/README.md` confirms the split: "`generator/` | Analyzes source types at build time and generates the reflection, schemas, and Remote descriptors that runtimes load".
- On the Host side freddie needs nothing generated anyway: `TypertGatewayService.resolveDescriptor` prefers a strict definition from `ctx.typert.local` and falls back to `resolveSrcDescriptor`, which reads the `@Remote` markers that `@freddie/freddie-typert-protocol` already attaches.

So the only generated thing a port actually needs is the Client-side `./remote` descriptor manifest, and freddie already owns a hand-written precedent for exactly that: `packages/gm/gm-client/src/typert.host.js` and `src/typert.remote-client.js`. Each ported package hand-owns both manifests in that shape, listing **only endpoints freddie can really serve** (see below). Nothing was fabricated to look like generator output.

## Decision — one shared constraint, and the policy it forced

freddie's Remote layer is **unary**: `packages/client/connection/src/rpc-host.js` serves one HTTP POST → one JSON response on `/api`, `websocket-downlink.js` opens exactly two fixed event downlinks (`events.mux`, `events.host`), and `ClientRemoteService` exposes `$mount` / `$on` / `$dispatch` with no `$stream`. dsh's controllers lean on `@Remote({ mode: 'stream' })` and `ClientRemote.$stream` for six endpoints (`job.list`, `job.follow`, `session.follow`, `session.control`, `terminal.retain`, `terminal.follow`).

Policy adopted for all three packages:

1. **Port the business logic faithfully.** Stream generators ship as plain async generators over freddie's real seams.
2. **Register only genuinely-callable unary endpoints**, and put only those in the typert manifests. An async generator cannot ride a unary carrier, so registering one would ship an endpoint that always fails.
3. **Never fake data and never throw on a missing capability.** Client stream runners resolve `ctx.remote.$stream` defensively and take the model's existing terminal-failure path (roster dropped, observation failed) instead of inventing an API or raising.
4. **Use freddie's real error channel.** dsh throws `RemoteError(code, message, details)`; freddie's protocol exports no `RemoteError`, so typed business failures ride `TypertLookupFailure`, which `rpcFailure` already preserves verbatim instead of collapsing into `internal`.
5. **Document every dropped endpoint** in the package README's `## Known Limitations and Deferred Work`.

## Decision — `@freddie/freddie-job-controller`

`packages/api/job-controller`, `JobController extends TypertRemoteService` with `super(ctx, 'jobController', { namespace: 'job' })`, `static inject = ['jobs', 'typert']`, and `ctx.effect(() => ctx.jobs.attachController('job-controller'))` — `JobRegistry.start` refuses work for an owner no attached controller serves, so without that the package could not control anything it exposes.

- `kill(agent, request)` is the one registered Remote method. It reads `jobs.get(request.jobId, agent)` first, then `jobs.kill(request.jobId, agent, 'cancelled by the user')` in the same synchronous span, and folds both registry refusals — `unknown job …` and `job … belongs to another session` — into one `job/not-found` `TypertLookupFailure`. The human kill is not the model's own, so the owning agent still receives the completion notice and a shell tool waiting on the job reads the reason in its result.
- `list(agent, signal)` mirrors the roster through `src/rows.js` (`streamJobRows` + the `OutputWaiter`/`sleep` pair in `src/wake.js`): one whole-set frame on open, then one after each coalesced burst of `ctx.jobs.onJobsChanged` commits. Not registered — see the policy above.
- The session rides freddie's existing Typert `agent` lookup rather than a `request.sessionId` field, so the wire carries `agentId` and the lookup's own cold-resume and `session-not-found` policy applies; `kill`'s body carries only `jobId`.
- Client half: `ClientJobsModel` (rosters with an identity-stable snapshot) plus `ClientJobs` (`ctx.jobs`) with reference-counted `watchRows` and a `kill` passthrough. `src/invariant.js` registers the manifest name and asserts the registry reports a serving controller while `ctx.jobController` is live.

**Not ported: `job.follow`.** dsh streams one job's retained output from an absolute byte offset through `JobRegistry.readAt`, and its README states both reads are non-consuming. freddie's `JobRegistry` has no `readAt`, and its `read` *is* the consuming model-facing cursor — it marks a terminal job reported. Porting `follow` over `read` would let a browser tab swallow the completion notice the owning agent is owed, so the per-job observation stream and the Client observation model stay deferred until the registry grows a non-consuming byte-offset read. `observeMaxFrameBytes` is omitted with it, since it budgets output frames for `follow` alone.

## Decision — `@freddie/freddie-session-controller`

`packages/api/session-controller`, `SessionController extends TypertRemoteService` with `super(ctx, 'sessionController', { namespace: 'session' })`, injecting `agentDefaultModel`, `agents`, `llm`, `sessionProjections`, `sessionQuery`, `sessions`. Every method is cold-safe: a persisted Session reads without resuming its Agent.

Five endpoints are registered and appear in both manifests: `list`, `search`, `modelCatalog`, `page`, `projections`. `page` reads a message-aligned slice of a durable `SessionAddress` (`throughSeq` inclusive cut, `beforeSeq` exclusive bound, `turnWindow` extending backwards across whole turns). `projections` answers `null` — not a failure — for a Session that does not exist. `list` takes no request: dsh's request fields have no freddie reader.

Identity policy lives in `src/agent.js`: a `session` address naming a subagent Session is rejected with `session/agent-busy`; a `subagent` address whose parent, mode or descriptor does not match is rejected with `subagent/unauthorized` / `subagent/catalog-diagnostic`. All ride `TypertLookupFailure`.

- `follow` / `control` ship as plain async generators and are in neither manifest. `follow` yields one `snapshot` frame then every event after the cursor, gap-checked by seq, and promotes the Agent in the background when the opening read came from persistence; `control` yields one projection `baseline` then a frame per `ctx.sessionProjections.onChanged` unit change.
- **Projection ownership stays with the gateway.** dsh's list registers `sessionListMetadata` and `imageLimits`; freddie's `packages/host/apiproxy` already registers both (`sessionListMetadata` at `stateVersion` 2, carrying `errored`), and `sessionProjections.register` refuses a duplicate key at a different version, so the ported list *reads* them. A deployment without the apiproxy serves rows with no projection block instead of failing.
- **No Typert lookup/Context configuration.** `ctx.typert.lookups.configure('agent'|'session')` and `contexts.configureHost('agent')` are already installed by `packages/api/remotes`, and `configure` throws on duplicates.
- `observeSession` → local `sourceFor` (attached store, then `ctx.sessionQuery.readSession` with projections restored over the persisted log); `cachedSnapshot` → `snapshot`/`restore`; `cachedPredecessorTitle` omitted. Seed lineage reads `header.seedLength ?? 0` and `events.slice(n)`.
- Client half is `ClientSessionModel` (`ctx.sessionModel`) and **mounts the `session` namespace itself**, so it is deliberately absent from `packages/api/remotes`' contribution list — listing it there would mount the namespace twice.
- **Not ported:** `initializeDefaultModel` (DeepSeek-vendor account behaviour) and the native-desktop path endpoints plus `nativeOpen`; no `Config` was invented for a field with no behaviour behind it. The whole Session *command* surface is deferred — see below.

## Decision — `@freddie/freddie-terminal-controller`

`packages/api/terminal-controller`, `TerminalController extends TypertRemoteService` with `super(ctx, 'terminalController', { namespace: 'terminal' })`, injecting `terminals`, `subprocess`, `sandboxPolicy`, `typert`. Seven endpoints registered and in both manifests: `environment`, `shells`, `list`, `create`, `write`, `resize`, `close`.

- **Screen model:** dsh's `@xterm/headless` grid becomes a bounded `ctx.terminals.read(owner, ptyId, { offset: 0, count: scrollback }).text`. No `@xterm/*` dependency was added.
- **Live output:** `ctx.terminals.subscribe(owner, listener)` activities (`output`/`resized`/`exited`/`closed`) become Host-sequenced `output` and `state` frames.
- **Spawn and size:** `ctx.terminals.spawn(agent, { type: ptyType, name: id, cwd }, signal)`; the PTY name is fixed at spawn and `ctx.terminals.resize`'s return value is the source of truth for `cols`/`rows`.
- **Backend-owned argv:** `terminal-bash` builds argv from its own config plus the sandbox policy, so the controller's resolved shell is reported metadata/title and the `shellPath` acceptance filter only — observed live as a terminal reporting `cmd.exe` metadata while the backend spawned `powershell.EXE`.
- **Discovery:** an unresolvable candidate is omitted, not failed — `ctx.subprocess.resolveExecutable` misses are plain `Error`s, and on this host zsh/bash/fish are absent, so the menu is cmd.exe + powershell.
- **cwd:** `agent.session.header.cwd ?? ctx.sandboxPolicy.resolve({ session }).workspaceRoot`.
- `retain` / `follow` are real Host async generators, registered nowhere and in neither manifest. The Client resolves `ctx.remote.$stream` defensively and surfaces `issue: 'unsupported'` rather than throwing or faking frames. `rename` is omitted (no PTY rename seam); unattended reclamation is omitted (no `inspectActivity`/`shellActivity` equivalent, so `unattendedTimeoutMs`/`activityPollIntervalMs` are not ported); `disposeGraceMs` stays backend config.
- **Client manifests carry no `scope`.** A scoped descriptor would resolve the Agent from the calling Client Context; every endpoint takes the Session id and the Host resolves it by lookup. The Host manifest keeps `scope`.
- No `RemoteError`: Host uses `TypertLookupFailure`, Client uses a local `TerminalViewError` with the same `code`/`details`. Bindings are an in-memory `Map` on `ClientTerminals`; only close intents are durable (`localStorage`).

## Decision — wiring into the Client assembly

`packages/api/remotes/src/client/index.js` mounts `@freddie/freddie-job-controller/remote` and `@freddie/freddie-terminal-controller/remote` inside the existing optional dynamic-import block, so a mount failure logs and moves on instead of unwinding commands/goals or blanking the shell. `@freddie/freddie-session-controller/remote` is intentionally **not** listed there because that package's own Client entry mounts its namespace. All three are in `freddie.client.external` and in remotes' peer/dev dependencies.
