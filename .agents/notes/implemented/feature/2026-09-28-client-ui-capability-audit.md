## Freddie web client architecture (grounding for every port claim)

Buildless plain JS + JSDoc served straight from `src/`: `packages/client/modules/src/index.js` scans Loader entries for `package.json` `freddie.client` + `exports["./client"]` (lines 590-618) and serves each package's `src/` tree at `/plugins/<id>/~<rev>/client/...` (line 705); `vendor-modules` serves vendored ESM of every bare npm import under `/vendor/` and merges them into the one import map (`vendor-modules/src/index.js:1-9`; regenerate with `scripts/generate-vendor.mjs`, whose `ENTRY_SPECIFIERS` :30-86 is the closed list of browser-visible npm packages); `css-manifest` concatenates plain `.css` files into one revved `/styles/app.css` (`css-manifest/src/index.js:1-10`; regenerate `scripts/generate-manifest.mjs`); `hmr` reloads `src/client/` on save. A UI plugin is `export const inject = [...]` + `apply(ctx)` that registers into slots: `ctx.slots.inject(name, () => ctx.slots.register({ name, id|key, order, locale, inject }, webjsxSlot('freddie-x')))` (`ui-jobs/src/client/index.js:12-29`), where `webjsxSlot(tag)` (`ui-slots/src/index.js:33`) names a custom element defined with `defineElement` (`ui-primitives/src/define-element.js:69`; hot-swap-safe versioned tags) and rendered by `webjsx` `applyDiff` (`ui-jobs/src/client/JobListAction.js:1,89`); `ui-renderer` hosts the elements and binds observables to snapshot readers (`ui-renderer/src/client/session-provider.js:31`). Data comes from `props`/inject callbacks and `ctx.remote.<ns>` Remotes (`ui-artifacts/src/client/index.js:4-19`). A new package needs: `package.json` with `exports["./client"]` and a `freddie.client` block (copy `ui-jobs/package.json:14-30`), a row in `packages/bundle/web-app/cordis.patch.yml` (ui-jobs at :230-231) plus a dependency in `packages/bundle/web-app/package.json` (ui-jobs at :84), an `.css` + `.css.js` class-name map per stylesheet, then `node packages/client/css-manifest/scripts/generate-manifest.mjs`. **Seats that exist**: root `AppFrame` with children `sidebar`, `conversation`, `details` (session scope), `shell.overlay` (`ui-layout/src/client/index.js:36-46`); `conversation.view` (list, session scope; chat/trajectory/observability/artifacts register into it, `ui-conversation/src/client/apply.js:217,355`, `ui-artifacts/.../index.js:7`, `ui-observability/.../index.js:16`); `conversation.session.header.{lineage,actions,utilities}` (`apply.js:236-238`); `conversation.chat.{node,turnTail,assistant-actions}`; `details` holds one keyed `conversation.details.tool` (`apply.js:420-430`); `settings.section`, `settings.plugins.tab`, `settings.plugin.item`. **Seats that do not exist**: any right sidebar / dock / tab registry (`sidebarRight|rightbar|dockkit|DockLayout` codesearch over the whole tree: 0 matches), `ctx.resources`, root-scope provide hooks (`provideRoot`: 0 matches). ## gm workflow observations (not fixed)

- `fetch` returns only a truncated `body` inline (about 500 chars) plus a spool file whose JSON escapes newlines; reading a README costs an `exec_js` dump step. A `full`/`save_to` option returning the body verbatim would remove the round trip.
- `codesearch` with `output_mode: "count"` still returned full match arrays, and `-o`/`head_limit` did not bound output when a `context` or wide glob was given; broad regexes produced multi-thousand-line responses. A real per-file count mode and a hard default cap on `content` mode would save tokens.
- `exec_js` results over about 500 chars are elided to a spool-file path holding an escaped JSON string; a plain-text sidecar would avoid unescaping.
