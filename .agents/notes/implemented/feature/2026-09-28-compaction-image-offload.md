# Agent Note: Durable image offload on the compaction seam

Status: implemented

## Problem

An image-capable route can reject a request because it carries too many images. The only way forward is to send fewer, and the choice of *which* images to drop must survive: a transient, per-request omission silently reappears on the next request, so the failure repeats forever. Freddie already had exactly such a transient mechanism — `offloadRequestImagesWithPolicy` in `@freddie/freddie-llm`, applied inside the request path — and no durable one. The prior audit finding confirms the gap: `codesearch image` scoped to `packages/compaction` returned a single hit, `compaction-basic/src/summarizer.js`, which *throws* `LlmError('compaction summary cannot contain image output', 'UNSUPPORTED_CONTENT')` instead of handling images.

Upstream `deepseek-ai/deepseek-harness` ships `@deepseek-ai/dsh-compaction-image-offload`, which closes this gap durably. This port brings that package over as `@freddie/freddie-compaction-image-offload`.

## Decision

### The decision is a session event; the omission is a surface replacement

`image/offload` records *which* occurrences to omit: `{ targets: Array<{ seq, imageIndexes }> }`. It carries no `surfaceOp`, so it never appears on the surface — `ImageOffloadEvent` is not a `SurfaceEventType`. The visible effect lands as ordinary durable message events: one `user/message` or `tool/result` per contributing node, each carrying `{ surfaceOp: { op: 'replace', start: seq, end: seq }, sourceEventSeqs: [seq] }`. This is the same protocol [`freddie-compaction-tool-result-pruner`](../../../packages/compaction/compaction-tool-result-pruner/README.md) already uses, and it satisfies `assertToolResultRewrite`, which permits a `tool/result` replacement that changes only `content`.

The original events stay in the append-only log, so persistence, replay, and exact-log inspection keep the images even though the surface no longer shows them.

### Oldest-first selection over the failed request's own order

`selectOldestImageTargets(session, sourceEventSeqs, count)` walks the events *in the order the failed request sent them*, taking occurrences until the requested count is exhausted. Assistant nodes are skipped because they carry model output. Occurrences are counted depth-first, which includes images nested inside `tool-result` blocks — freddie genuinely nests them there, and `contentHasImage`/`collectImageLengths`/`replaceOldestImages` in `@freddie/freddie-llm` all recurse the same way. Oldest-first means the most recent images survive.

When nothing remains to offload, `offloadOldestImages` returns `false` and the listener delegates to `next()`. Recovery therefore cannot loop: a repeated `IMAGE_OFFLOAD_REQUIRED` with no images left leaves the failure terminal.

### A projection, because the write must be reproducible

`imageOffloadProjection` validates the decision and reconstructs the replacement messages in one pure step, and both the live write and a detached replay call it. Upstream exposes it for `registerMessageProjection`; freddie has no such registry, so the projection is exported directly from `./projection` and called by `offloadOldestImages` before any append. Validation is atomic — nothing is written when a target is malformed.

### The event type is appended as `ignorable`

`KNOWN_SESSION_EVENT_TYPES` is generated by `scripts/gen-persistence-catalog.ts` and names only the types present when it last ran. Rather than regenerate a checked-in catalog from an in-progress tree, the append passes the envelope's `ignorable` marker, which is the established freddie precedent for package-owned types (`workspace/changes`, `deliverables/presented`, `gm/progress`).

## Deviations from upstream

| Upstream | Freddie | Why |
|---|---|---|
| `block.offloaded = true` on the image block | the block is replaced by `{ type: 'text', text: OFFLOADED_IMAGE_TEXT }` | Freddie's transient offload already sends this exact placeholder, so the model sees one representation regardless of which layer omitted the image. An inert `offloaded` flag would be a second, parallel vocabulary. |
| `registerMessageProjection` | no registry exists; the projection is exported and called directly | `codesearch` for `registerMessageProjection` / `SessionMessageProjection` returns zero hits. The pure replay function is kept verbatim so a registry can be adopted later without changing the projection. |
| `compaction/summary-error` listener | not ported | Freddie's compaction seam has no such event. Porting it would attach a listener to a name nothing dispatches. |
| `failure.offloadImages` produced by adapters | no adapter reports a count | Freddie's routes bound images transiently instead of failing. The package owns `IMAGE_OFFLOAD_REQUIRED_CODE` and waits for a producer. |
| `session.eventAt(seq)` | `session.events[seq]` | Freddie's `Session` has no `eventAt`; `events` is the indexed log. |
| `brandString<SessionId>()` | n/a (no construction in this package) | Recorded for completeness of the substitution rule. |
| upstream does not recurse into nested tool results | the visit recurses | Upstream's own JSDoc says "including nested tool results", and freddie nests images there. Following the JSDoc over the literal code keeps the index space consistent with `contentHasImage`. |

## Verification

Executed against the real stack with `exec_js` — a real `Session`, a real `SessionStore`, a real `InvariantRegistry`, and a real `@freddie/cordis` waterfall. No scratch files remain.

### Surface and selection

```
BEFORE  events=0:user/message | 1:tool/result | 2:user/message  nodes=[0,1,2]
SELECT3 [{"seq":0,"imageIndexes":[0,1]},{"seq":1,"imageIndexes":[0]}]
OFFLOAD3 true
AFTER   events=0:user/message | 1:tool/result | 2:user/message | 3:image/offload | 4:user/message | 5:tool/result  nodes=[4,5,2]
NODE 4 user/message -> text,text,text
NODE 5 tool/result -> tool-result[text,text]
NODE 2 user/message -> image,text
FROZEN  true
AGAIN   true
FINAL   events=0:user/message | 1:tool/result | 2:user/message | 3:image/offload | 4:user/message | 5:tool/result | 6:image/offload | 7:user/message  nodes=[4,5,7]
```

The three images at seqs 0 and 1 were selected oldest-first (two in the first message, then the nested one), node 2 kept its image because the count was exhausted, both replacements landed as surface nodes, the replacement messages are deeply frozen, and a second decision went on to the remaining image.

### The `agent/request-error` waterfall

```
plugin name=compaction-image-offload inject=[] Config={}
NODES-BEFORE [0,1]
unrelated code      -> undefined | nodes=[0,1]
code w/o count      -> undefined | nodes=[0,1]
IMAGE_OFFLOAD x2    -> {"kind":"retry"} | nodes=[3,4]
EVENTS-AFTER  0:user/message | 1:tool/result | 2:image/offload | 3:user/message | 4:tool/result
  NODE 3 user/message -> text,text
  NODE 4 tool/result -> tool-result[text]
IMAGE_OFFLOAD again -> undefined | nodes=[3,4]
```

An unrelated failure code and a matching code without `offloadImages` both delegate; the real failure returns `{ kind: 'retry' }` and advances the surface; a repeat with nothing left to offload returns `undefined`, so the loop does not retry forever.

```

```

A canonical decision registers and passes; every malformed shape is rejected before publication. `ignorable: true` is persisted on the event.

## Known limitations

- **No producer for `IMAGE_OFFLOAD_REQUIRED`** — the package is dormant until an adapter reports `offloadImages`. Freddie's routes bound images transiently instead.
- **`compaction/summary-error` is absent**, so the summary-failure half of upstream's recovery was not ported.
- **`foldSurfaceProjection` folds these replacements with zero delta**, because it arms claims only from `compaction/summary` and `compaction/prune`. `measure()` remains exact; the O(1) projection can over-estimate an offloaded surface. This is the documented neutral degradation of the projection, not a new bug.
- **Offload is one-way.** No event restores an offloaded image; the original survives only in the log.
