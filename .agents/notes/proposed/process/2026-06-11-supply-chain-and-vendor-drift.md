# Agent Note: Supply chain checks and third-party drift verification

Status: proposed

## Problem

The handful of true npm dependencies have no advisory monitoring or update cadence, and nothing verifies that genuinely vendored third-party code still matches what it claims to be.

The framework-layer half of this proposal is obsolete. It assumed the Cordis layer was an upstream-tracking copy whose drift from upstream-at-SHA was a defect worth detecting. That premise is void: [the framework layer](../../../../framework/README.md) is first-party, every package was rewritten from TypeScript to plain JavaScript, and there is no upstream to resync against, so "drift" there is the intended state rather than something to check. What survives is the third-party half.

`packages/client/vendor-modules` is the code this still applies to. It serves real third-party npm packages (shiki, katex, micromark, webjsx) to the browser as ESM, generated by `packages/client/vendor-modules/scripts/generate-vendor.mjs`, and a drift or advisory concern there is as valid as it ever was.

## Proposal

1. ~~**Vendor drift check** against upstream at a manifest SHA.~~ Dropped: the framework layer is first-party and has no upstream to diff against.
2. **Dependency advisories**: osv-scanner (or `pnpm audit`) job on the lockfile, scheduled + on lockfile-touching PRs.
3. **License inventory**: a script asserting every framework package carries its LICENSE and that package.json `license` fields match the ancestry table in [`framework/README.md`](../../../../framework/README.md) (we mix inherited MIT with our BSD-3) — CI step.
4. **Renovate** (or a scheduled agent task) proposing npm dependency updates in small PRs that ride the full gate suite. Framework packages are excluded because they are workspace source, not dependencies.
5. **Third-party browser-bundle verification**: assert that the packages `packages/client/vendor-modules/scripts/generate-vendor.mjs` emits match the versions the lockfile resolves, so a regenerated bundle cannot silently carry different third-party code than the manifest claims.

## Plan

3 is trivial — do first. 2 and 4 are config. 5 needs the generator to record what it emitted.

## Alternatives considered

- **`pnpm audit` instead of osv-scanner** — either satisfies the advisory-scanning shape; the choice is deferred to implementation.
- **A scheduled agent task instead of Renovate** — equivalent for proposing small update PRs that ride the full gate suite; framework packages stay excluded either way, being workspace source rather than dependencies.

## Acceptance criteria

- The license inventory script runs in CI and fails on a missing LICENSE or a `license` field that contradicts the ancestry table in `framework/README.md`.
- Advisory scanning runs on the lockfile on schedule and on lockfile-touching PRs.
- The third-party browser bundle in `packages/client/vendor-modules` is verified against the lockfile-resolved versions.

## Risks

The dropped drift check was the part that needed network access and credentials; what remains reads the lockfile and the working tree, so CI friction is low. The residual risk is the opposite one: with no upstream comparison anywhere, a well-meaning contributor could still copy an upstream file into `framework/` wholesale, and only review catches that.
