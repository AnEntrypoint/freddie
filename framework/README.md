# Framework Packages

This directory contains the harness's framework layer: the Cordis kernel, its loader/include/group/timer/hmr/logger-console plugins, the cosmokit and schemastery foundation libraries, and the webjsx client rendering library. **These are first-party packages maintained in this repository.** They began as copies of upstream projects, but they are no longer tracked against upstream releases and are not synced from one — they carry this project's own design decisions, are published under the `@freddie` scope, and are edited here like any other package in `packages/`.

The old `vendor/` directory name said the opposite, which is why it is gone. A reader (or an agent) who sees "vendored" correctly infers *do not edit this, sync it from upstream instead* — and acting on that inference here is wrong in both directions: it discourages fixing a real bug in code we own, and it invites a "resync" that would silently revert years of divergence. Treat this directory as ours.

## What diverged, and why it is not coming back

The clearest single measure: **every package here was converted from TypeScript to plain JavaScript.** There is no `.ts` file, no `tsconfig.json`, no build step, and no `lib/` output anywhere under `framework/` — `package.json` `main`/`exports` point straight at `src/index.js`. That conversion deleted every type-only construct and rewrote every TypeScript-specific runtime pattern (`const enum`s, constructor parameter properties, declaration merging). It is not a patch that could be rebased onto a new upstream commit; it is a different codebase that happens to share an ancestor.

On top of that, the kernel and plugins carry substantial behavioral work that upstream does not have — reentrant-disposal hardening in the fiber lifecycle, transactional config reconciliation across Loader/Include/Group, durable debounced config writes, exact-path config watching with Windows realpath handling, and lazy config resolution. The [Divergence log](#divergence-log) below records each of these. It is written for *us*, as the maintainers: it explains why the code is shaped the way it is, and which decisions were deliberate.

Every package is renamed into the `@freddie` scope (`cordis` → `@freddie/cordis`, `@cordisjs/plugin-<x>` → `@freddie/cordis-plugin-<x>`). Harness packages declare these as peer dependencies, so publishing the harness publishes this framework layer with it; publishing under the upstream names would squat them on a registry we do not own. `pnpm-workspace.yaml#linkWorkspacePackages` resolves those names to these workspaces. Upstream MIT `LICENSE` files are preserved in each package directory, and the ancestry table below records what each package descended from — both because the licenses require attribution and because knowing the origin is genuinely useful when reading unfamiliar code.

To add a *new* package to this layer, see [docs/cookbook/adding-a-framework-package.md](../docs/cookbook/adding-a-framework-package.md).

## Divergence log

Why this log still exists now that these packages are ours: it is the rationale record for non-obvious code. Several entries below document deliberate departures from the shape a reader might expect — places where the straightforward implementation was tried and found broken. Deleting the log would leave that reasoning nowhere. Entries are kept in their original numbering so existing references remain valid.

1. **`hmr/src/index.js`**: no `./locales/*.yml` imports, no `.i18n({...})` call on the `Config` schema, no `src/locales/` directory. Those imports require a runtime YAML loader hook (`@cordisjs/unyaml`) that this project does not carry; the i18n texts only localized config descriptions.
2. **All `package.json` files**: `private: true`, precise `files` entries, a `./src/*` export where one was missing. `hmr` declares `esbuild` as a direct dev dependency because its source imports the `BuildFailure` type and pnpm's strict workspace resolution requires the owner package to name it; `loader` requires `node-addon-require-builtin@^0.1.4` to match the runtime used by published app packages.
3. *(Retired — superseded by entry 19. Per-package `tsconfig.json` files no longer exist.)*
4. *(Retired — superseded by entry 19. Explicit `.ts` internal specifiers no longer exist.)*
5. *(Retired — superseded by entry 19. The `tsdown.config.ts` build-shape overrides no longer exist.)*
6. **`cordis/src/fiber.js` lifecycle hardening**: closes three reentrant disposal gaps. An effect's owner-list wrapper is registered before its setup body runs, so an unload begun from inside setup awaits setup and every collected cleanup; synchronous setup failure removes the wrapper and rolls back collected cleanup. Async cleanup stays owner-visible until quiescence, and internal effect composition joins an already-running cleanup while repeated public disposer calls retain their single-shot result. Effect creation is rejected while the owner is `UNLOADING` (`PENDING` and `LOADING` remain legal), preventing cleanup-time registrations from escaping the unload snapshot. Child fibers register and receive their parent-owned disposer before `internal/plugin` publication, resolve dependency declarations added by that notification before activation, drain effects attached while pending, skip plugin execution when reentrant disposal invalidates the load epoch before its first checkpoint, and contain teardown-notification failures per observer so one callback cannot starve peers or interrupt ownership cleanup. `Fiber.update()` returns its `internal/update` waterfall result, allowing Loader callers to await a restart while preserving synchronous config validation.
7. **`cordis/src/*.js` JSDoc contract documentation**: `@param`/`@returns` tags and contract documentation (disposal semantics, waterfall veto, bail conditions, error cases) across the public plugin-author surface — `Context`, `EventsService`, `Fiber`, `RegistryService`, `ReflectService`, `Service`, `LoggerService`. Comment-only.
8. **Transactional Loader/Include config reconciliation**: Loader imports a changed entry name before disposal, awaits lifecycle settlement, and restores the previous plugin or config when candidate application fails. Loader settlement rechecks service-gated fibers after current tasks drain, rejects failures, and leaves fibers with absent dependencies pending. Group updates start candidates concurrently, await every outcome, contain sibling-start failures after their owning tree is disposed, undo changes and additions on live-update failure, await removal, preserve programmatic option identity, and persist direct or tree-level mutations only after success. Include reads and validates detached candidate content, applies patches to a clone, reconciles the tree, and only then commits its cached content/data; direct refresh failures propagate for the caller to contain. A non-array parse is invalid, patches re-apply on every file or Include-config update, an omitted patch list clears the overlay, and initial content falls back to `initial` only on `ENOENT`.
9. **`hmr/src/index.js` exact config watching**: `registerConfig()` watches one absolute config path outside module roots, including a path under missing parents, serializes and coalesces refreshes, and returns an async disposer that closes the watcher and drains active work. Module watches realpath their existing base directory, attach change listeners before declaring the service ready, and use that spelling for Node module-cache identity; exact config watches realpath the deepest existing watch ancestor and restore the missing suffix. Those native paths prevent Windows short-name aliases from colliding with long-form libuv event paths while exact-config callbacks keep the requested filename. Refresh failures are normalized to `Error`, logged, and broadcast through the parallel `hmr/config-update-failed` event; observer failures are contained.
10. *(Folded into entry 19 — the explicit erased-import marking existed to serve Node's TypeScript transform, which is no longer in the picture. Schemastery keeps its ESM default export and `type: module`.)*
11. **`include/src/index.js` patch-semantics export**: the private `applyPatches` body is the exported pure function `applyEntryPatches(data, patches, warn)` (the method delegates to it), and the `!!js` YAML dialect is exported as `entryListSchema`, so `--dump-config` composes and prints exactly what the include would mount without booting a tree. The extraction exists because config tooling must never reimplement (and drift from) the patch algorithm. `applyEntryPatches` indexes each `insert`ed entry as it is added, so a later patch in the same list can configure or disable a row an earlier patch inserted — building the id index once before the patch loop leaves inserted rows silently unpatchable. That matters because the CLI composes an empty profile root with each bundle's patch layer, the profile's and the home-level `cordis.patch.yml`, and any `--patch` overlays as sibling patch lists at one include level; patches never cross an include boundary, so surface-only rows would otherwise be unreachable from user config.
12. **`include/src/index.js` serialized child-tree mutation and `hmr/src/index.js` main-watcher initial-scan suppression**: every Include child-tree mutation (initial apply, refresh, `internal/update` patch re-application) runs through one per-Include queue, because the group's transactional `update` is not reentrant — two concurrent applies interleave create and rollback on the same entries and strand the Include fiber without ever settling. The HMR main watcher passes `ignoreInitial: true`: the initial scan re-announced files boot had just consumed, and its `add` for a config file refreshed an Include mid-initial-apply; once serialized, a failing initial apply's rollback disposed HMR, whose teardown drain waited on the queued refresh sitting behind that same apply — a deadlock that exited 13 with no diagnostic. `registerConfig()` keeps its own `ignoreInitial: false` watcher because a user patch layer present at registration must apply once.
13. *(Retired — a TypeScript `exactOptionalPropertyTypes` accommodation with no meaning in plain JS.)*
14. **`include/src/index.js` durable debounced writes**: config-file writes are serialized and tracked, transient `EACCES`/`EBUSY`/`EPERM` rename failures retry with a bounded backoff, asynchronous timer rejections are observed, and the latest write drains during Include teardown. Windows can briefly retain a destination handle after a Loader child disposes; a fire-and-forget rename escapes as an unhandled rejection and can lose the persisted `disabled` state. A terminal failure is logged by the asynchronous writer and remains on the queue so `Include.stop()` rethrows it instead of silently declaring persistence complete; ordinary fiber teardown retains its separate error-containment contract.
15. **Lazy Loader config resolution across `cordis/src/{events,fiber}.js`, `loader/src/{index,config/entry}.js`, `include/src/index.js`, and `hmr/src/index.js`**: raw fiber config is retained and resolved through `internal/config` only after declared injections are active. (The same design as [cordiverse/cordis#41](https://github.com/cordiverse/cordis/pull/41), which is worth reading for background.) Provider replacement re-resolves the raw expression, pending updates retain it, and HMR transfers it. Resolution applies only to the entry root, so child plugins mounted by a row keep caller-owned config identity. Include declares the `EntryGroup.key` tree-carrier marker (as Group does): its config is entry and patch lists, so interpolation keeps it literal and a `!!js` expression inside a nested row's config resolves lazily in that row's own fiber (Include's own `path` therefore stays literal too). Deferred failures retain the owning row diagnostic, and tree teardown does not persist failure-driven self-disposal.
16. **`cordis/package.json` publishes `src`**: `src` is in the `files` list, as it is for the other eight packages. Cordis declares `"./src/*": "./src/*"` in its exports, so a tarball without `src` publishes an export map pointing at absent files; the release change judgement also reads `files` to decide whether a diff reaches the payload, and a package whose only published paths are build output has no tracked path to match.
17. **`@freddie` scope**: every manifest `name`, every internal dependency entry among this set, and every module specifier that reaches them use the scoped names in the package table's `npm name` column. Directory names, version numbers, and dependency ranges are unchanged, and no inherited runtime identifier is renamed — `Symbol.for('schemastery')` and Schemastery's `vendor:` metadata field keep their original values, because they are wire/registry identifiers rather than package references. `pnpm run rescope-vendor --apply` is the codemod that established this; the table's two name columns are the mapping, restated for consumers in [docs/rescope.md](../docs/rescope.md).
18. **Entry `disabled` interpolation in `loader/src/config/entry.js`**: a `disabled: !!js` expression evaluates against the loader context at every mount decision; the raw node stays in the options, so write-back keeps the `!!js` form. `disabled` is the only interpolated metadata field.
19. **Plain JavaScript throughout**: every package's source is `src/*.js`. No compile step, no `lib/` output, no per-package `tsconfig.json` or `tsdown.config.ts`. `package.json` `main`/`exports` point directly at `src/index.js` (for `schemastery`, a single ESM entry replacing a prior dual `.mjs`/`.cjs` build; for `logger-console`, the `node`/`default` conditional export points at `src/index.js`/`src/browser.js`). Interfaces, type aliases, `declare module`/`declare global` blocks, and inline type annotations are gone; `const enum`s are plain frozen-shape objects (`FiberState`, `LoggerLevel` in `cordis`, `ModulePhase` in `loader`, an unexported `State` in `cosmokit/string.js`); constructor parameter properties are explicit field declarations plus constructor-body assignment; declaration merging (a namespace merging with a same-named class/function) is either a hoisted-function-then-attach pattern (`Inject`/`Inject.resolve` in `cordis/registry.js`) or a `static` class field (`CordisError.Code` in `cordis/fiber.js`, `Hmr.Config` in `hmr/index.js`); a namespace merging only with a type alias converted to a standalone object (`ModuleLoader` in `loader/internal.js`); type-only namespaces (`Include.Config`, `ConsoleExporter`, `Plugin`, `Property`, `LoggerService.Intercept`) are deleted; abstract classes (`Realm`, `EntryTree`) keep their abstract methods as real methods that throw `not implemented`, overridden by every concrete subclass. `schemastery/src/index.js` also dropped a 192-line `declare global { namespace Schemastery { ... } }` block that carried no runtime code despite containing `let`/interface-like syntax — `declare` makes a block's contents non-emitting regardless of the keywords inside it. This entry is what retires entries 3, 4, 5, 10, and 13 above.

20. **`webjsx/src/{createElement,applyDiff,attributes,createDOMElement}.js` function-component and DOM-node support**: upstream webjsx's `createElement`/`createElementJSX` treat a function `type` as a Fragment-like pass-through, discarding the function and its props; this project's client UI is built entirely from function components (`Button`, `Modal`, `Tooltip`, and the rest of `dsh-client-ui-primitives`), so both now invoke `type(props)` when `type` is neither a string nor `Fragment`. `applyDiff`'s keyed-diff and `canUpdateVNodes`/`applyChanges` paths treat a real DOM `Node` appearing where a vnode is expected (returned by a one-shot imperative create/update helper, e.g. a self-managed `DshSlotOutlet`/`DshRootOutlet` subtree) as an update-in-place replacement rather than un-updatable, and `createDOMElement` passes an already-real child `Node` through unchanged instead of re-wrapping it. `updateAttributesCore` removes an SVG element's attribute via `removeAttribute` instead of assigning `undefined` through the property accessor, which SVG's read-only DOM properties throw on. `createElement`/`createElementJSX` also distinguish an explicitly empty children list from no children argument at all (self-closing JSX), so a self-managed subtree's ancestor re-render does not clobber it on every pass. None of this is documented upstream behavior; `webjsx.org` and the GitHub README cover only string-tag/Web-Component elements and Fragments.
21. **`hmr/src/index.js` never calls `loader.exit()`**: a change in the CLI entry's dependency tree (`externals`) used to request a full process restart. The web GUI's contract is that a source edit must not kill the listening pid. Those files now stash and take the same cache-bust + plugin-reload path as application modules. `snapshot()` exposes a bounded leaf-only journal (`deferred`, `stashed`, recent events) so an agent can inspect HMR without walking live fibers. Profile boot also watches `framework/*/src` alongside `packages/` and `apps/`.
22. **`webjsx/src/attributes.js` serializes unknown HTML values as attributes**: a key that is not a real DOM property writes `String(value)` through `setAttribute`, while `false`, `null`, and `undefined` remove that attribute. Data selectors and ARIA metadata commonly carry boolean or numeric values; assigning them as JavaScript expandos left CSS, DOM lookup, and assistive technology unable to observe rendered state. DOM properties continue through property assignment, and SVG remains attribute-only.

## Working in this directory

Edit these packages directly, the same as any package under `packages/`. There is no sync step to preserve and no upstream to re-apply changes onto — a fix belongs here, in a normal commit, with the reasoning in the divergence log if the code's shape would otherwise be surprising.

After changing anything here, boot a real composition to exercise the Loader/Include chain end to end (`--dump-config` on a profile, or an `examples/*` composition) rather than reasoning about the lifecycle from the source alone; the reentrancy and ordering behavior documented above is not visible in a static read.

If you are pulling a genuinely useful upstream change into one of these packages, treat it as writing that change here by hand: read the upstream diff for its idea, then implement it against this code, which has a different type discipline, different lifecycle guarantees, and different file extensions. A file-level copy will not apply.
